01

这个方向，一天到底在干嘛

不用行话讲。下面是深圳一家做智能客服的公司里，一位 AI 应用开发实习生的普通一天。

一句话：你不训练模型，你负责模型外面那一整圈东西，喂给它什么上下文、允许它调哪些工具、它答错了怎么兜住、回答一次花多少钱、怎么证明它真的变好了。 模型 API 代码里通常只占一行，剩下的全是让它稳定、便宜、可衡量地跑起来的部分。

09:30
先看昨天的 badcase 列表

运营标了 12 条「答非所问」。你逐条翻 trace：5 条是检索压根没召回对的段落，3 条是提示词里没写清楚「不知道就说不知道」，模型自己编了。

10:10
改提示词，然后跑评测集

把「你必须基于检索内容回答」改成「只允许使用 <context> 里的信息，没有就说没有」，顺手补两个反例。跑一遍 30 条评测集，通过率 71% → 84%。这一步没有玄学，就是改一版、测一版。

11:30
给检索库调参数

chunk 从 800 字切成 500 字带 80 字重叠，重排模型从小换到大，命中率又涨 6 个点。参数不是拍脑袋定的，是做了三组对照实验选出来的，这三组数据最后写进了验收报告。

14:00
写一个工具函数，让模型能用

产品说「用户问天气，应该直接去查」。你定义一个查天气的工具，把超时、返回空、城市名识别不出来这三种情况都处理掉，工具出错时模型该怎么说话，也是你设计的。

16:00
看成本和延迟

昨天调用 4.2 万次，花了 ¥380，P95 延迟 3.4 秒。缓存命中率只有 12%，你把高频问题的答案缓存起来，第二天成本掉到 ¥240。省钱这件事，在这行是能被量化的功劳。

17:30
把今天的坑写成测试用例

今天踩的 8 个新问题补进评测集，进 CI。以后每次改提示词自动跑一遍，防止「修好了 A，弄坏了 B」。这是应用开发和「调 API 做套壳」最本质的分界线。

19:00
写一句结论进周报

「检索质量是当前瓶颈，下版本引入混合检索。」，不写「完成了优化工作」这种话，写清楚判断和下一步。

一句话定位：这个岗位 = 大模型能力 × 工程落地力。它的日常是「改一版 → 测一版 → 看数据 → 再改一版」， 更接近做产品，而不是做研究。如果你喜欢的是「东西真的被用起来」，而不是「指标又涨了 0.3 个点」，那你会喜欢这里。

03

真实的门槛，和信息差

这一节是本页最重要的部分。下面每一条，都是问过 4 位在岗学长之后确认过的。
大家以为做 AI 必须会训练模型，不然就是「调 API 的搬运工」。
→
实际上80% 的岗位只要求你会调用和调优。真正训模型的岗位集中在少数大厂和模型公司，剩下的全在做应用，把模型接进真实的业务里。这部分不需要 GPU，也不需要推导公式，需要的是工程判断力。
大家以为数学不好做不了 AI，得先补线代概率。
→
实际上应用层用到的数学，大二高数水平就够。你真正要能看懂的是评测指标（命中率、准确率、P95 延迟）和「余弦相似度」这个概念。反向传播怎么推导，面试官不会问应用岗。
大家以为这行已经饱和了，都在卷。
→
实际上会做 RAG 和 Agent 落地的人严重不足。招聘 JD 已经从「了解大模型」升级成「有 RAG/Agent 落地经验」，而大部分同学的项目还停在调 API 做套壳。做过两个能跑通的真实项目，你就已经站在前面了。
大家以为要读很多论文，英文不好直接劝退。
→
实际上能读懂官方文档 + 会搜，就够用了。90% 的日常工作靠文档、GitHub issue 和跑实验解决。真要读论文的场景是「线上效果卡住了」，那时你是带着问题去读的，和硬啃完全是两件事。
大家以为不会 Python 就进不来，得先把 Python 学扎实。
→
实际上语法一周能上手，卡人的是工程习惯。有任意一门语言底子的人，语法一天看完；真正要花时间的是虚拟环境、类型注解、以及「同一个问题有八个库」时的选型判断。路线第一阶段就专门补这个。

05

一条典型路线长什么样

这是这个方向上一条被走通过的路，4 位已上岸的学长走过、验证过 3 轮。你自己那条会按你的情况重排，起点、节奏、主项目都不一样。
1
STAGE 011–2 周

能用 Python 工程化的方式写程序

产出把你以前写过的某个课设脚本用 Python 重写一遍：能跑、有类型注解、别人 clone 下来一句命令就能运行。
2
STAGE 022 周

能可靠地让模型输出你要的结构化结果

产出「周报生成器」：一堆打卡记录进去，结构稳定的周报出来。模型输出必须是 JSON，字段错了自动重试，这是所有下游功能的地基。
3
STAGE 033 周

能独立完成一个 RAG 应用的搭建、调优与评测

产出深大校园问答机器人：混合检索 + 重排 + 引用溯源，配 30 条自己标的评测集，命中率做到 85% 以上。这个项目是简历上最能被追问的一个。
4
STAGE 043 周

能设计有工具、有记忆、会自我纠错的 Agent

产出多工具任务 Agent（例：自动排查 CI 失败并给出修复建议）。工具出错怎么办、上下文太长怎么办、循环停不下来怎么办，这三个问题答不上来就不算做完。
5
STAGE 052 周

能把 Demo 变成敢上线的服务

产出把上面的项目改造一遍：轨迹可查、成本有看板、高频问题有缓存、越界提问有护栏。这是后端底子的人反超的赛段。
6
STAGE 063 周

能把两个项目讲成 20 分钟的面试故事

产出两个项目的简历语言、被追问 5 层也不崩的叙事、3 场模拟面试（组内互面 + 学长终面）。
六个阶段总共约 14 周（每天 2.5 小时）。想快可以快：如果你已经会 Python、写过后端，前两个阶段可以申请免修直接跳。 每周能投入多少、哪个阶段该展开，问卷里说清楚，路线会按你的真实情况排，宁可诚实报 1 小时，不要冲动报 4 小时。
