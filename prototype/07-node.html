动手：四步，按顺序做

勾完 4 条解锁产出
看懂和敲过是两回事。每一步都真的在终端里做一遍——卡住了就回第一拍翻那一段，别硬扛。
🎉 练完了，可以去创造环节了 去做产出 →
01 在自己电脑上建一个仓库，把第一份文件提交上去 → 你会得到：一个真实存在的仓库，里面躺着你的第一条提交记录（带时间和一句你写的说明） 约 15 分钟
02 故意把一个文件改崩，再用 Git 把它变回来 → 你会得到：一次真的「后悔药」体验。删掉一整个文件、敲一条命令、文件回来了——这条命令救过所有人的命 约 20 分钟
03 开一个分支，在上面加一行字，再合并回主干 → 你会得到：一张能画出来的分叉图（git log --graph），你会第一次看见「分支」长什么样 约 20 分钟
04 把仓库推到 GitHub，在网页上改一次，再拉回本地 → 你会得到：一个能直接发给同学的公开链接，以及一次完整的「本地 ↔ 远端」往返 约 15 分钟

做出东西：你的第一个仓库

这一关的产出物
这是你这一关要交出来的东西。标准是公开的，做不到就改到做到——没有「差不多就行」。
DELIVERABLE · 本关产出

一个公开的 GitHub 仓库，README 5 行说清它是什么

不用是什么了不起的项目——一个记录你学习笔记的仓库就够。重要的是它结构完整： README 说清这是什么、怎么跑、你学到的最意外的一点；提交记录能看出你一步步做了什么。

验收标准（3 条 · 学长按这三条看）
✓仓库公开可访问，README 里有「这是什么 / 怎么跑 / 学到什么」三行
✓提交记录 ≥ 3 条，每条说明都在讲「我做了什么」，而不是清一色 update
✓有一次真实的分支合并：git log --graph 能画出分叉和合流
做完之后你会得到：你简历上第一个能放链接的东西，也是你以后所有项目的家。 往后每一关的产出都会提交到这个账号下——大二找实习的时候，你的 GitHub 首页会替你说话。
