# 分支路线规格总纲

所有分支路线（Java 后端 / 前端 / 产品 / …）都必须长成这个样子。写在各自路线之前，先读这份。

原型设计阶段：本文件是**设计规格**，不是代码。字段用 JSON 示意描述，不落库。

---

## 一、一条路线 = 三层

| 层 | 是什么 | 免费可见 | 样板页 |
|---|---|---|---|
| **L0 方向页** | 科普：这个方向是什么、前景、典型一天、信息差、适合谁 | ✅ 全公开 | `03-direction.html` |
| **L1 阶段** | 6 个阶段，每阶段一个项目产出 + 一道验收关 | ✅ 全公开 | `06-roadmap.html` |
| **L2 关卡** | 每阶段 4–6 关，每关四拍 + 产出物 + 卡点 | ✅ 全公开 | `07-node.html` |

外加两类挂件：

- **AI 通识层**（2.5 段，6 关）—— 见 `_ai-layer.md`，所有路线共用
- **VIP 加练关**（每路线 3 道）—— 38 / 68 档可进，红线见 §五

## 二、L0 方向页字段

| 字段 | 要求 |
|---|---|
| 一句话 | 说清这个方向每天在干什么，不写"负责…相关工作"这种空话 |
| 典型一天 | 6 个时间点，每个一段。要让人看见真实节奏（含开会、改 bug、等评审） |
| 真实工作内容 | 3 条，每条带一个具体场景 |
| 前景 | 招人真实情况 / 薪资区间 / 3 年后在做什么。**数据必须标年份与来源** |
| **AI 时代怎么变** | **必填**。四段式，写法见下面专节 |
| 信息差 | 误解 vs 真相，4–6 组。误解要写成"外行真的会这么想"的话 |
| 适合谁 | 4 条，**写人不写形容词**（不写"有耐心的人"，写"能接受一个 bug 查三天的人"） |
| 不适合谁 | 4 条，同上。这一节不许客气 |
| 能力清单 | 硬技能 / 软技能两组 |
| 入门前置 | 走这条线之前要会什么（指向探索路线对应站） |
| 从哪开始 | 一个按钮，跳 L1 |

**数据红线**：薪资、岗位数、录取率这类数字，**不许凭印象写**。每个数字要标来源（招聘平台抽样 / 学长 offer / 公开报告）和年份，并在页面注明"数据来自 X，仅供参考，不做就业承诺"。没有可靠来源就写区间 + 说明，不写精确值。

## 「AI 时代怎么变」怎么写（每条技术路线必填）

用户要求（2026-09-21）：**要告诉他们企业内也在大量用 AI，但要讲清楚充分学懂一套后端 / 前端逻辑的重要性。**

四段式，顺序不能变：

**一、企业里已经在用它干什么（说现在时，不说未来时）**
列 3–4 件具体的事，是这个行业里真实发生的。不许写"取代程序员"这种吓唬人的话，也不许写"它只是个工具"这种轻描淡写的话。

**二、被压缩的是什么（诚实，这一节不许回避）**
明确写出哪些活的含金量在下降、什么样的简历竞争力在掉。**回避了，他们会从别处看到更夸张的版本，反而更慌。**

**三、为什么仍要学透这套逻辑（重点，4 条）**

1. **它写的东西要有人判断对不对。** 判断力只来自你真的懂。不懂的人拿到一份能跑的代码，看不出它在什么情况下会错。
2. **出事的时候它不在。** 线上问题需要对你自己系统的整体理解——它看不见你的系统，只能猜。
3. **它给的是"平均解"，不是"你的解"。** 取舍来自你对业务和系统的理解，它不知道你的上下文。
4. **它是杠杆，杠杆放大的是你本来的水平。** 你懂 60 分它把你抬到 80；你懂 20 分它把你抬到 40，而岗位线是 60。**先有可被放大的东西，杠杆才有意义。**

第 1、2 条必须写成**这个方向的具体场景**（后端的慢查询和并发，前端的边界情况和真机体验），不许写通用道理。

**四、这条路线怎么安排（落到行动）**
点名哪些阶段是"它帮不了你的部分"，并说明助学层只教用它学懂、不教用它代写。

**禁止**：神化（"不会用就被淘汰"）、恐吓（"这个岗位要消失了"）、空话（"要培养不可替代的能力"）。每一条都要有具体场景撑着。

## 三、L1 阶段字段

```
stageId  枚举，如 java-s1
no       1..6（2.5 为 AI 通识层）
name     阶段名，动词开头，如「让数据真的存下来」
weeks    按每周 6 小时估算
goal     一句目标
output   本阶段结束手上有什么（具体：一个地址 / 一份文档 / 一个仓库）
caps[]   本阶段覆盖的能力点 id
gate     本阶段验收关
```

阶段命名规则：**动词开头，说清状态变化**。「把环境装好」「让数据真的存下来」「让它扛得住」——不写「Java 基础」「数据库进阶」这种课表名。

---

## 四、L2 关卡字段

```
nodeId    如 java-s2-3
no        阶段内序号
name      关卡名，动词开头，如「增删改查做全」
hours     3–6
learn     学：看懂什么（1–2 句）
drill     练：动手做什么（具体到命令/动作）
create    创：做出什么（**必须是一个可交付的东西**）
verify    验：怎么确认自己会了
stuck[]   3 条卡点，格式：现象 → 原因 → 怎么办
docs[]    挂哪些资料（resourceId，走白名单）
caps[]    覆盖的能力点 id
```

### 四拍的定义（不许省任何一拍）

| 拍 | 干什么 | 判定标准 |
|---|---|---|
| **学** | 看懂这个东西是什么、为什么要有它 | 能用一句话向别人解释 |
| **练** | 跟着动手做一遍 | 手上有真实输出 |
| **创** | **自己做出一个东西** | 具体到文件名 / URL / 一份清单 |
| **验** | 确认自己真的会了 | 一个可自测的动作，不是"感觉懂了" |

「创」是结果型社区的落点，任何一关没有产出物就不许上线。

### 卡点三条规定

1. **必须写成"现象 → 原因 → 怎么办"三段**，不许只写"注意 XX 问题"。
2. 卡点要来自真实新手会撞的墙，不是知识点的补充说明。判断标准：**这条卡点说出来，走过这关的人会点头。**
3. 三条里至少一条是**环境问题**（装不上、跑不起来、报错看不懂）——新手卡在这里的比例最高。

## 五、VIP 加练关

```
gateId      如 java-v1
afterStage  挂靠阶段
name        如「线上事故复盘室」
nature      固定值：体验型
caps[]      覆盖能力点 —— **必须与某公开关完全一致**
hours       1–2
```

**红线（上线前逐条自检）**：

1. 这道题考的能力点，免费路径哪一关覆盖？**答不出就不许上。**
2. 它是否引入了免费路径没有的知识点？**有就删掉。**
3. 它给的三种东西至少占一样：更真实的场景 / 有对手 / 更细的复盘。

**每路线 3 道**，分别挂在阶段 3、阶段 4、阶段 6 之后（AI 通识层不算阶段）。

## 六、验收关与印记

- 每阶段末尾一道，**独立关卡，不在学习路径上**（沿用已定稿设计）。
- 系统验收：交链接 / 仓库 / 录屏三选一，无头浏览器真打开点一遍，回逐条 ✓/✗ + 截图证据 + 卡在哪。
- **通过后签发编号印记**（2026-09-21 变更：取消学长署名，改为系统签发 + 证据链）。
- 印记页可查：交了什么、逐条 ✓/✗、关键步骤截图、通过时间、编号。**任何人可查可复核。**
- 不通过：**免费重提，不限次数**（这条不变）。
- 配额：免费每周 3 次 / 38 每周 10 次 / 68 不限次。

## 七、Patch 枚举（小搭唯一能输出的操作）

```
skipStage(stageId, reason)          跳过某阶段
compressStage(stageId, ratio)       压缩某阶段时长
insertStage(afterStageId, ...)      插入强化阶段
insertModule(stageId, ...)          插入单个关卡
swapProject(stageId, projectId)     换主项目
reorderStage(a, b)                  交换阶段顺序
swapResource(nodeId, resourceId)    换本关挂的资料（必须在白名单内）
setPace(hoursPerWeek)               调整节奏
markMastered(capId)                 标记已掌握（影响后续讲解与推荐）
```

一次最多 6 条。模型输出不了别的东西 —— Zod 校验兜底。

## 八、资料挂载规则

每关挂三类，缺哪类补哪类：

1. **引路版**（现有探索版 41 份）作前置铺垫
2. **精通版**（现有 15 份）
3. **路线专版**（新增）—— 本方向深挖

**策略：先画骨架，再按关卡补资料，缺哪份写哪份。** 不让资料没有需求方。

写作红线全部沿用 `materials/README.md`：不许元叙述、不许跳跃、不许预设前置知识、默认 Windows、代码必须跑过、正文零链接、文末最多三条。
