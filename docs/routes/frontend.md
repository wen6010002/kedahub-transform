按 `docs/routes/_spec.md` 的规格写。**24 关 / 约 100 小时**（主线）+ AI 助学层 5 关 / 5 小时 = **29 关 / 105 小时**。

## L0 方向页

### 一句话

前端做的事，是**让用户看到的每一屏都能看、能用、不出错**——包括设计稿没画出来的那些状态。

### 典型一天

| 时间 | 在干什么 |
|---|---|
| 09:30 | 看昨天的线上报错和用户反馈，回设计群的消息 |
| 10:00 | 站会：昨天做了什么、今天做什么、卡在哪 |
| 10:30 | 对着设计稿写组件 |
| 12:00 | 午饭 |
| 14:00 | 跟设计对齐一个交互细节，发现设计稿没画加载态和失败态 |
| 15:30 | 联调接口，发现后端返回的字段名和说好的不一样 |
| 17:00 | code review：被指出没处理错误态、没加埋点 |
| 19:00 | 测试同学在安卓机上发现布局炸了，改 |
| 21:00 | 补文档，写今天的复盘 |

真实节奏是：**写界面只占一天的一半，剩下是对齐、联调、修真机上的问题。**

### 真实工作内容（3 条）

1. 把设计稿变成能用的界面——包括它没画出来的加载、失败、空数据状态。
2. 保证在不同的手机、不同的网络下都能用。
3. 跟设计和后端对齐，把没说清楚的地方问清楚。

### 前景

- **招人真实情况**：前端岗位数量少于后端，竞争不小。校招看的是**你做的东西能不能真的用**（真机上试过没有、边界情况处理了没有），以及基础（HTML/CSS/JS、框架、浏览器、网络、性能）。
- **薪资区间**：**待补真实数据**。要求：来源必须是主流招聘平台抽样或学长真实 offer，标注年份，页面注明「数据来自 X，仅供参考，不做就业承诺」。
- **三年后**：三条路——继续写业务界面并带小团队 / 专精某一块（性能、可视化、跨端、工程化）/ 转向全栈或产品。写清楚，不画饼。

### AI 时代，前端这一行在怎么变

**一、企业里已经在用它干什么（这是现在时，不是未来时）**

- 还原设计稿：截图进去，组件代码出来。**前端是被影响最早的方向之一**，因为"视觉 → 代码"这一步它做得特别好
- 写样式和布局、补响应式、批量改格式
- 解释报错、生成动画片段、把一种框架的组件转成另一种
- 不少团队已经把"设计稿 → 初版组件"这一步交给它了

**二、被压缩的是什么（这一节不回避）**

- 「能把设计稿切成页面」这件事，含金量确实在快速下降
- 只有静态页面、仿站的作品集，竞争力明显下降
- 简单的表单、列表、后台管理页，产出效率提升很多

**三、那为什么还要学透这套前端逻辑**

1. **它写不出"不出错"的界面。** 空数据、超长文本、网络失败、快速连点、断网重连——真实用户的报错八成来自这些边界情况，而它通常想不到。**它给你的是"正常情况下能用"的版本，不是"出错时也体面"的版本。**
2. **它不知道你的用户是谁。** 键盘能不能用、读屏能不能读、低端安卓上卡不卡、弱网下什么表现——这些要靠你真的去设备上点一遍。它没法替你体验。
3. **它给的是"能看"，不是"好用"。** 加载态、失败重试、乐观更新、埋点——这些决定体验的东西它不会主动加，因为没人告诉它要加。
4. **它是杠杆，杠杆放大的是你本来的水平。** 你懂 60 分，它能把你抬到 80 分；你懂 20 分，它把你抬到 40 分，而岗位线是 60 分。**先有可被放大的东西，杠杆才有意义。**

**四、这条路线怎么安排**

- **阶段 4（尤其是「四种状态」那一关）和阶段 5（真实项目质感）是它帮不了你的部分**——边界情况、真机体验、可访问性、性能，全是"要真的去用一遍才知道"的东西
- 助学层（2.5 段）只教你怎么用它把东西学懂，**不教用它替你写代码**
- 每阶段的助学卡写清了：可以问它什么、问的时候给什么上下文、它答完你检查什么

### 信息差（误解 vs 真相）

| 误解 | 真相 |
|---|---|
| 前端就是写页面，比后端简单 | 难点不在写页面，在**让它在任何情况下都不出错**——这才是花时间的地方 |
| 框架学一个就够了 | 框架会换，底层（DOM、事件、浏览器、网络）不会换。底层不牢，换个框架就从头来 |
| 设计稿给什么做什么 | 设计稿通常只画了最好的那种情况。加载、失败、空数据要你自己补，这部分占实际工作量不小 |
| 在自己电脑上能跑就行 | 用户的手机、系统、网络都不一样。只测过自己电脑的页面，上线必出问题 |
| 前端不用懂后端 | 你要天天跟接口打交道。联调时说不清是前端还是后端的问题，会很被动 |

### 适合谁（写人，不写形容词）

- 改完立刻想看到效果的人（前端的反馈最快）
- 对"用户会怎么用、会不会点错"这类问题真的上心的人
- 愿意在不同手机上一遍遍试的人
- 能在"好看"和"能用"起冲突时做出取舍的人

### 不适合谁

- 受不了反复改视觉细节的人（一个间距可能改八遍）
- 只关心逻辑不关心呈现的人（后端或算法更适合）
- 不愿意处理边界情况的人（前端大部分时间在防出错）
- 希望学完就能做出完整产品的人（这条路要走 100 小时以上）

### 能力清单

- **硬技能**：HTML 语义化、CSS 布局（flex / grid）、响应式、JavaScript、DOM 与事件、调试工具、一门框架、构建工具、Git、HTTP 基础、性能与可访问性基础
- **软技能**：把设计稿没画的状态问清楚、跟后端对齐字段、在真机上验证、说清"为什么这么做"

### 入门前置

探索路线的「计算机初识」9 站 + 「前后端初识」至少前 5 站。

## 阶段 1 · 让页面立起来（14h）

**1.1 HTML：把内容放进正确的标签里** · 3h

- 学：标签不是样式，是**意思**。语义化是让机器和人都读得懂结构
- 练：只写 HTML，做一个自我介绍页
- 创：一个语义化的个人介绍页（能被读屏软件读出来）
- 验：关掉所有样式，页面结构依然清楚
- 卡点：
  1. 通篇都是 div → 不知道还有别的标签 → 先想"这段内容是什么"，再选标签
  2. 手机上字特别小 → 没设 viewport → 加上 viewport 那行 meta
  3. 中文变乱码 → 没声明编码 → 文件保存为 UTF-8 并声明 charset
- 能力点：`fe-s1-html`、`fe-s1-semantic`

**1.2 CSS：让它长成你想要的样子** · 4h

- 学：选择器怎么匹配、优先级、盒模型
- 练：给上面那个页面加样式
- 创：一个好看的个人介绍页
- 验：不查资料，说得出三处样式为什么生效的是这一条
- 卡点：
  1. 样式没生效 → 选择器没匹配上或被优先级盖了 → 用开发者工具看哪条被划掉
  2. 两个元素之间的间距对不上 → 外边距合并或盒模型没算清 → 画出来看
  3. 宽度总差一点 → padding 和 border 也算宽度 → 全局设 box-sizing
- 能力点：`fe-s1-css`

**1.3 布局：让它排得开** · 4h

- 学：flex 管一维排列，grid 管二维网格，各自什么时候用
- 练：用 flex 做一个导航栏，用 grid 做一个卡片列表
- 创：一个两栏布局 + 卡片列表的页面
- 验：往里加第 7 张卡片，布局不炸
- 卡点：
  1. flex 子元素不换行，挤成一条 → 没设 wrap → 加 flex-wrap
  2. grid 列宽不听话 → 用了固定宽度 → 用 fr 或 minmax
  3. 垂直居中搞半天 → 方法太多 → 记住两种就够：flex 居中、grid place-items
- 能力点：`fe-s1-layout`

**1.4 让它在不同屏幕上都能看** · 3h

- 学：响应式、断点、移动端优先
- 练：把页面改成手机上也能看
- 创：一个手机和电脑都正常显示的页面
- 验：在真实手机上打开，不用缩放能正常读
- 卡点：
  1. 手机上字太小 → 没设 viewport 或用了固定 px → 相对单位和 viewport
  2. 图片把页面撑爆 → 没限制宽度 → img 设 max-width 100%
  3. 只在浏览器里拉窗口看 → 和真机不一样 → 用真机或设备模拟器验证
- 能力点：`fe-s1-responsive`

**验收关**：交一个手机和电脑都正常显示的页面（部署地址或仓库）。验：真机能打开、缩小窗口不炸、关掉样式结构仍清楚。

## 阶段 2 · 让它动起来（16h）

**2.1 JS 第一件事：拿到元素并改它** · 4h

- 学：DOM 是什么、怎么选中元素、怎么改内容和样式
- 练：点一下按钮，页面上换一句话
- 创：一个会响应点击的页面
- 验：不看教程，加一个新按钮并让它生效
- 卡点：
  1. 拿到 null → 脚本在元素前面就执行了 → 脚本放最后，或用 defer
  2. 改了但页面没变化 → 选中的元素不对 → 先打印出来看看是不是它
  3. 只在脑子里找错 → 太慢 → **先学会看控制台**
- 能力点：`fe-s2-dom`

**2.2 事件与状态：记住用户做过什么** · 4h

- 学：事件是什么、事件冒泡、状态该放在哪
- 练：做一个待办清单，能加、能删、能标记完成
- 创：一个能增删改的待办清单（刷新就没了，下一关解决）
- 验：连续做五个操作，状态都是对的
- 卡点：
  1. 事件绑了不触发 → 元素还没渲染出来 → 渲染之后再绑，或用事件委托
  2. 循环里绑事件，拿到的一直是最后一个 → 闭包问题 → 用 let 或传参
  3. 状态散在各个地方，改一处忘一处 → 没有单一数据源 → 统一放一个变量里
- 能力点：`fe-s2-event`、`fe-s2-state`

**2.3 调试：出问题怎么找** · 4h

- 学：开发者工具四个必会的用法、断点、网络面板
- 练：故意写五个 bug，只靠工具把它们找出来
- 创：一份"前端出问题先看哪"的清单
- 验：别人在你代码里藏一个 bug，你三分钟内找到
- 卡点：
  1. 只会用 alert 打值 → 太慢且会打断流程 → 用断点
  2. 接口问题找不到 → 不看网络面板 → 网络面板看请求和响应
  3. 改一下刷一下 → 效率低 → 开热更新
- 能力点：`fe-s2-debug`

**2.4 让它记住数据** · 4h

- 学：本地存储能存什么、不能存什么
- 练：让待办清单刷新后还在
- 创：一个刷新不丢数据的待办清单
- 验：关掉浏览器再打开，数据还在
- 卡点：
  1. 存了对象取出来变成字符串 → 没序列化 → 存之前转字符串，取之后转回来
  2. 把密码或 token 存进去 → 不安全 → **本地存储不存任何敏感信息**
  3. 换台电脑数据没了 → 它只存在这台机器上 → 需要跨设备就得存服务端
- 能力点：`fe-s2-storage`

**验收关**：交一个刷新不丢数据的待办清单。验：增删改都对、刷新不丢、清空缓存后会重建。

## 阶段 3 · 组件化与工程化（18h）

**3.1 为什么要有框架** · 4h

- 学：直接操作 DOM 会遇到什么问题、框架替你解决了什么
- 练：用框架把待办清单重写一遍
- 创：框架版的待办清单
- 验：说得出"不用框架做这个，麻烦在哪"
- 卡点：
  1. 用着框架却还在手动改 DOM → 思维方式没换 → 改数据，让框架去更新界面
  2. 改了数据界面不变 → 改数据的方式不对 → 用框架规定的方式更新
  3. 一上来就装一堆库 → 不知道每个解决什么问题 → 先只用核心，缺了再加
- 能力点：`fe-s3-framework`

**3.2 组件：把页面拆开** · 5h

- 学：组件是什么、props 和自己的状态、什么时候该拆
- 练：把页面拆成五个组件
- 创：一个组件化的小应用
- 验：其中两个组件能在别的地方直接用
- 卡点：
  1. 拆得太碎或太粗 → 没标准 → 按"会不会一起变 / 能不能复用"判断
  2. 状态放错层级 → 谁用就放谁最近的公共父级 → 先放低，不够再往上提
  3. 子组件直接改父组件的状态 → 数据流乱了 → 子组件通知，父组件改
- 能力点：`fe-s3-component`（**VIP 关 V2 覆盖此能力点**）

**3.3 构建工具与包管理** · 4h

- 学：为什么要构建、依赖怎么管、版本锁是什么
- 练：从零配一个项目，装依赖、起开发服务器、打包
- 创：一个能打包出静态文件的项目
- 验：删掉依赖重新安装，还能跑起来
- 卡点：
  1. 依赖装不上或很慢 → 源的问题 → 换国内源，必要时清缓存
  2. 别人能跑你跑不了 → 版本不一致 → 用锁文件固定版本
  3. 本地能跑、打包失败 → 路径或环境变量问题 → 看构建日志的第一条错误
- 能力点：`fe-s3-build`

**3.4 Git 协作** · 5h

- 学：分支、提交、合并、冲突
- 练：开三个分支，故意制造一次冲突并解决
- 创：一个提交记录干净的仓库
- 验：看提交记录能说清这个项目是怎么一步步做出来的
- 卡点：
  1. 所有改动都堆在主分支 → 出问题没法回退 → 一个改动一个分支
  2. 提交信息写"修改" → 等于没写 → 写清改了什么、为什么
  3. 遇到冲突直接删对方的 → 会丢代码 → 逐段看，不确定的问
- 能力点：`fe-s3-git`

**验收关**：交一个组件化的应用 + 仓库。验：能打包、提交记录干净、组件能复用。

## 阶段 4 · 状态与数据（18h）

> **这一阶段是它帮不了你的部分。**
> 一个请求有四种状态——加载、成功、失败、空——它通常只给你成功那一种。
> 而真实用户遇到的大多数问题，恰恰发生在另外三种里。
> 可以问它"这个状态该怎么处理"，但**你的页面必须真的被断网、被清空数据、被快速连点过一遍**。

**4.1 接真实接口** · 4h

- 学：请求怎么发、异步是什么、跨域为什么会发生
- 练：调一个公开接口，把数据渲染到页面上
- 创：一个展示真实数据的页面
- 验：断网一次，看页面变成什么样（不是白屏就行）
- 卡点：
  1. 报跨域错误 → 服务端没放开或没走代理 → 开发时配代理
  2. 数据拿到了页面还是空 → 异步时机问题 → 数据到了再渲染
  3. 不知道请求发出去没有 → 没看网络面板 → 网络面板看请求和响应
- 能力点：`fe-s4-fetch`

**4.2 四种状态：加载、成功、失败、空** · 5h

- 学：**一个请求有四种状态，不是两种。** 空数据和加载中是两回事，失败和空也是两回事
- 练：把上面那个页面补全四种状态，每种都有对应的界面
- 创：一个四种状态都处理好的页面
- 验：人为制造这四种状态（断网、接口报错、返回空数组、慢速网络），每种界面都是对的
- 卡点：
  1. 只处理了成功 → 网络一慢就白屏 → 四种状态一个都不能少
  2. 失败了只在控制台打日志 → 用户不知道发生了什么 → 界面上要有提示和重试
  3. 空数据的页面长得像"一直在加载" → 两种状态没分开 → 分别设计
- 能力点：`fe-s4-state4`（**VIP 关 V3 覆盖此能力点**）

**4.3 状态管理** · 4h

- 学：什么时候才需要状态管理、常见方案解决什么
- 练：把跨组件共享的状态抽出来
- 创：一个多处共享状态的应用
- 验：说得出哪些状态该共享、哪些不该
- 卡点：
  1. 什么状态都往全局塞 → 改一处影响一片 → 只用的人在用的才提升
  2. 改状态的方式不统一 → 出 bug 找不到源头 → 统一入口
  3. 为了用它而用它 → 三个人写的项目上了重型方案 → 够用就行
- 能力点：`fe-s4-statemgmt`

**4.4 路由** · 5h

- 学：前端路由是什么、为什么刷新会 404
- 练：做三个页面，能跳转、能刷新、能直接输地址打开
- 创：一个多页面的应用
- 验：把任意一个页面地址发给别人，他能直接打开
- 卡点：
  1. 刷新就 404 → 服务端没配回退 → 所有路径回退到首页
  2. 刷新后路由参数丢了 → 参数只存在内存 → 放进地址里
  3. 返回上一页，之前的状态没了 → 状态没保存 → 关键状态放进地址或存储
- 能力点：`fe-s4-router`

**验收关**：交一个接真实接口、四种状态都处理好的应用。验：断网 / 接口报错 / 返回空 / 慢速网络，四种界面都对。

## 阶段 5 · 真实项目质感（20h）

> **这一阶段同样是它帮不了你的部分。**
> 可访问性、真机体验、性能——这些只能靠你真的去设备上点一遍、量一遍。
> 它没法替你体验。

**5.1 动效与反馈** · 5h

- 学：什么时候该有动效、什么算对的反馈、要考虑减动效偏好
- 练：给关键操作加反馈动效（点击、完成、失败）
- 创：一个点哪儿都有反馈的页面
- 验：闭着眼点，也知道操作有没有生效
- 卡点：
  1. 到处都加动效 → 页面很闹 → **只在状态变化的地方加**
  2. 动画卡顿 → 动的属性触发了重排 → 只动 transform 和 opacity
  3. 没考虑有人不喜欢动效 → 会让人不适 → 尊重系统的减动效设置
- 能力点：`fe-s5-motion`

**5.2 可访问性** · 5h

- 学：键盘能不能用、读屏能不能读、对比度够不够
- 练：**全程只用键盘**走完你的页面；再用读屏软件听一遍
- 创：一个键盘可达、读屏能读的页面
- 验：不用鼠标，能完成页面上的所有操作
- 卡点：
  1. 用 div 当按钮 → 键盘根本到不了 → 用真正的按钮元素
  2. 只用颜色区分状态 → 色觉障碍的人看不见 → 加文字或形状
  3. 弹窗打开后焦点跑了 → 焦点没管理 → 打开时移进去，关闭时还回去
- 能力点：`fe-s5-a11y`

**5.3 性能：先量再改** · 5h

- 学：加载慢在哪、怎么量、常见优化手段
- 练：用工具量一次，找出最大的那个问题并改掉
- 创：优化前后的对比数据（不是感觉，是数字）
- 验：说得出你的页面慢在哪，以及改完快了多少
- 卡点：
  1. 凭感觉优化 → 改的不是瓶颈 → **先量，再改，再量**
  2. 图片没压缩 → 往往就是最大的那一项 → 压缩并按需加载
  3. 一次加载了所有页面的代码 → 首屏很慢 → 按页面拆开加载
- 能力点：`fe-s5-perf`（**VIP 关 V1 覆盖此能力点**）

**5.4 埋点与真实反馈** · 5h

- 学：埋点是什么、该记什么、怎么用它判断一个功能好不好
- 练：给三个关键操作加埋点，看一周数据
- 创：一份埋点方案 + 一份"从数据里看出了什么"的小结
- 验：说得出一个"因为数据所以改了设计"的决定
- 卡点：
  1. 什么都埋 → 数据一堆没人看 → 只埋你要回答的那个问题
  2. 埋了不看 → 等于没埋 → 定一个看数据的固定时间
  3. 把用户的个人信息埋进去 → 合规风险 → 涉及隐私的一律不埋
- 能力点：`fe-s5-analytics`

**验收关**：交一个真机上好用、键盘可达的页面 + 性能对比数据。验：真机能用、键盘能走完、有优化前后的数字。

## 阶段 6 · 上线与作品集（14h）

**6.1 部署** · 3h

- 学：静态托管、域名、HTTPS、缓存
- 练：部署上线，配好域名和证书
- 创：**一个公网可访问的地址**（本阶段硬产出）
- 验：换一台没配过的设备打开，能用
- 卡点：
  1. 刷新子页面 404 → 没配路由回退 → 所有路径回退到首页
  2. 改了线上没变 → 被缓存了 → 配好缓存策略
  3. 线上报本地没有的错 → 环境变量不一致 → 检查构建时的环境变量
- 能力点：`fe-s6-deploy`

**6.2 README 与作品集页** · 4h

- 学：项目怎么展示、该写什么
- 练：写一份 README + 一个作品集页面
- 创：一份 README + 一个作品集页
- 验：别人看完知道你做了什么、难在哪、怎么跑起来
- 卡点：
  1. 只放一个链接 → 没人会点 → 先写清楚再看要不要点
  2. 说不出难点 → 没复盘 → 回想你卡得最久的那次
  3. 作品集堆了二十个项目 → 显得每个都不深 → 放三个，每个讲透
- 能力点：`fe-s6-portfolio`

**6.3 讲清你的项目** · 4h

- 学：讲项目讲什么、面试官在听什么
- 练：完整讲一遍并录下来，听一遍
- 创：一段讲解录音 + 一份改进清单
- 验：连着答三个"为什么这么做"不卡壳
- 卡点：
  1. 讲成功能列表 → 听不出你做了什么 → 每个功能后面加一句"难在哪"
  2. 说不出为什么用这个方案 → 当初没比较 → 补一句"当时还考虑过什么"
  3. 只讲技术不讲用户 → 显得没产品感 → 加一句"用户因此少点了几下"
- 能力点：`fe-s6-present`

**6.4 前端面试准备** · 3h

- 学：常问的五块——HTML/CSS 基础、JavaScript、框架、浏览器与网络、性能
- 练：自测 + 计时回答
- 创：一份自己的错题本
- 验：同一道题隔一周还能答出来
- 卡点：
  1. 只背概念不写 → 手写就废 → 边背边写一遍关键代码
  2. 追问就露馅 → 只准备了一层 → 每个知识点往下挖三层
  3. 作品和简历对不上 → 会被问穿帮 → 两边对齐
- 能力点：`fe-s6-interview`

**验收关**：交公网地址 + 作品集页 + 讲解录音。验：能打开、项目讲得清、简历与作品一致。

## VIP 加练关（38 / 68 档）

三道关全部指向**边界情况**——正是助学层反复强调"它最容易漏掉"的那部分。

**V1 真机急诊室**（挂阶段 5 后，2h）
给你一个"在我电脑上好好的"页面，在一台低端安卓机上会崩或卡死。限时找出问题并修好。
覆盖能力点：`fe-s5-perf`（= 免费关 5.3）。给的是**真实设备场景 + 限时压力 + 事后诊断**。

**V2 甲方改稿**（挂阶段 3 后，1.5h）
小搭扮演甲方，连改三版需求，你要保住组件的一致性和可用性，并说出每版改动的影响。
覆盖能力点：`fe-s3-component`（= 免费关 3.2）。给的是**有对手 + 针对你的设计**。

**V3 用户来了**（挂阶段 4 后，1.5h）
小搭扮演真实用户，用各种奇怪操作折磨你的页面：快速连点、中途断网、输入超长文本、连续返回。你要保证它不崩。
覆盖能力点：`fe-s4-state4`（= 免费关 4.2）。给的是**有对手 + 真实场景 + 复盘更细**。

自检三条：能力点免费路径都有覆盖 ✓ / 没引入新知识 ✓ / 更真实 + 有对手 + 复盘更细 ✓
