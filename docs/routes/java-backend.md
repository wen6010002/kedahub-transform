## L0 方向页

### 一句话

后端工程师做的事，是**让数据被安全地存下来、准确地取出来、并且扛得住很多人同时来取**。

### 典型一天

| 时间 | 在干什么 |
|---|---|
| 09:30 | 到工位，先看昨晚的告警和监控，回群里几条消息 |
| 10:00 | 站会：昨天做了什么、今天要做什么、卡在哪 |
| 10:30 | 开始写代码。一个接口的需求，先跟产品对清楚字段和边界情况 |
| 12:00 | 午饭 |
| 14:00 | 联调。前端说接口返回不对，一起对字段，发现是空值没处理 |
| 15:30 | code review。同事挑出三个问题：事务没加、日志没打、异常吞了 |
| 17:00 | 改完提交，等 CI 跑完 |
| 19:00 | 线上慢查询告警，拉日志、看 explain、加索引 |
| 21:00 | 补文档，写今天的复盘 |

真实节奏是：**写代码只占一天的三分之一，剩下三分之二在对需求、改问题、查线上。**

### 真实工作内容（3 条）

1. 把一句话需求变成一个能跑、不会挂、别人能调用的接口——包括它出错时返回什么。
2. 跟前端和产品对齐字段与边界。需求改三版是常态，你要能说清"这样改会影响什么"。
3. 线上出问题时靠日志和监控定位，不靠猜。

### 前景

- **招人真实情况**：后端是招人最多的技术岗之一，竞争也最大。校招主要看两件事——项目是不是你自己做的、基础扎不扎实（集合、并发、JVM、MySQL、Spring、Redis）。
- **薪资区间**：**待补真实数据**。要求：来源必须是主流招聘平台抽样或学长真实 offer，标注年份，页面注明「数据来自 X，仅供参考，不做就业承诺」。没有可靠来源就只写区间与趋势，不写精确值。
- **三年后**：三条路——继续写业务接口并带小团队 / 专精某一块（性能、数据、中间件）/ 转向架构或基础设施。写清楚，不画饼。

### AI 时代，后端这一行在怎么变

**一、企业里已经在用它干什么（这是现在时，不是未来时）**

- 写样板代码和 CRUD 接口：一个标准的增删改查接口，几秒钟出初稿
- 解释报错、讲清别人的代码：新人上手的时间明显缩短
- 写文档初稿、测试用例骨架、SQL 改写建议
- 不少团队已经把它接进了日常流程。这不是趋势判断，是已经发生的事

**二、被压缩的是什么（这一节不回避）**

- 「会写 CRUD 接口」这件事，含金量确实在下降
- 只有培训班式项目（增删改查 + 一个管理后台）的简历，竞争力在快速下降
- 简单的数据搬运、格式转换类需求，一个人能干的活变多了，需要的人变少了

**三、那为什么还要学透这套后端逻辑**

1. **它写的东西得有人判断对不对。** 它能给你一个看起来能跑的分页查询，但看不出这条 SQL 在 100 万行数据下会不会全表扫描；它能写一个扣库存的接口，但看不出并发下会不会变负。**判断力只来自你真的懂。**
2. **出事的时候它不在。** 线上慢查询、库存变负、内存溢出——这些需要对你自己系统的整体理解。它看不见你的系统、你的数据量、你的调用方，只能靠猜。而线上问题从来不等人。
3. **它给的是"平均解"，不是"你的解"。** 这里要不要加缓存、事务边界划在哪、这个字段要不要冗余、这个接口要不要拆——这些取舍来自你对业务和系统的理解，它不知道你的上下文。
4. **它是杠杆，杠杆放大的是你本来的水平。** 你懂 60 分，它能把你抬到 80 分；你懂 20 分，它把你抬到 40 分，而岗位线是 60 分。**先有可被放大的东西，杠杆才有意义。**

**四、这条路线怎么安排**

- **阶段 4（让它扛得住）和阶段 5（让它像个真项目）是它帮不了你的部分**——性能、并发、事务、部署、线上排查，全是系统性问题，必须自己走一遍
- 助学层（2.5 段）只教你怎么用它把东西学懂，**不教用它替你写代码**
- 每阶段的助学卡写清了：可以问它什么、问的时候给什么上下文、它答完你检查什么

### 信息差（误解 vs 真相）

| 误解 | 真相 |
|---|---|
| Java 太老了，快被淘汰 | 企业里存量系统最多、招聘量最大的仍是 Java。"老"意味着稳定和岗位多 |
| 学会 Spring Boot 就能找工作 | Spring Boot 只是工具。面试问的是你用它解决了什么问题、为什么这么设计 |
| 后端不用管界面 | 你天天跟前端对齐字段。界面显示错了，第一个被叫的是你 |
| 写完代码就完了 | 上线才是开始——监控、日志、慢查询、回滚，占掉一半时间 |
| 八股背熟就行 | 背熟只能过第一轮。追问项目细节时，背的东西救不了你 |

### 适合谁（写人，不写形容词）

- 能接受一个 bug 查三天，最后发现是一行配置的人
- 对"数据怎么存、怎么传、怎么不出错"这类问题真的感兴趣的人
- 愿意把事情做完整的人：写完还要测、要上、要能回滚
- 读得下别人的代码，也接受别人挑你代码的人

### 不适合谁

- 想立刻在屏幕上看到效果的人（前端更适合）
- 讨厌处理边界情况的人（后端大部分时间在防出错）
- 不想写文档和测试的人
- 希望学完一个月就能独立做项目的人（这条路要走 100 小时以上）

### 能力清单

- **硬技能**：Java 基础与集合、并发、JVM 基础、MySQL 与 SQL 优化、Spring Boot、MyBatis、Redis、HTTP/REST、Git、Docker 基础、Linux 常用命令、单元测试
- **软技能**：把模糊需求问清楚、读日志定位问题、写清楚的技术文档、在 review 里接受意见

## 阶段 1 · 把环境装好，跑通第一个接口（12h）

**1.1 装好 JDK 和 IDE，跑出第一行 Java** · 4h

- 学：JDK / JRE / JVM 各是什么、IDE 替你干了什么、环境变量是什么东西
- 练：装 JDK 17 + IDEA，写 HelloWorld，**命令行和 IDE 各跑一次**
- 创：一个控制台小工具（比如批量给文件改名）
- 验：不看教程，从零新建一个项目并跑通
- 卡点：
  1. 提示 `javac 不是内部或外部命令` → PATH 没配上 → 回到安装目录确认 bin 路径加进了 PATH
  2. IDEA 里找不到 JDK → 项目 SDK 没设 → File → Project Structure 里指定
  3. 输出中文乱码 → 文件编码不是 UTF-8 → 全局编码改成 UTF-8 并重新保存
- 能力点：`java-s1-env`、`java-s1-cli`

**1.2 用 Maven 管依赖，跑通一个 Web 接口** · 4h

- 学：为什么需要构建工具、pom.xml 里有什么、依赖从哪来、Spring Boot 替你干了什么
- 练：用 start.spring.io 生成项目，写一个 `/hello` 接口，浏览器打开它
- 创：一个返回当前服务器时间的接口，用 curl 能调通
- 验：删掉项目重新生成一次，不看教程跑通
- 卡点：
  1. 依赖下载卡住不动 → 走的是国外源 → 改 settings.xml 的镜像地址
  2. 启动报 8080 端口被占用 → 别的程序占着 → 换 `server.port` 或关掉占用程序
  3. 一屏报错看不懂 → 不知道从哪读起 → **从最后一行 `Caused by` 往上读**
- 能力点：`java-s1-build`、`java-s1-http`

**1.3 让接口接收参数并返回 JSON** · 4h

- 学：GET 和 POST 的区别、参数怎么传、JSON 是什么、 Controller 该干什么不该干什么
- 练：写 `/course?name=xxx` 返回 JSON，用浏览器和测试工具各调一次
- 创：一个"输入课程名返回课程信息"的接口
- 验：说得出 GET 和 POST 什么时候用哪个
- 卡点：
  1. 中文参数乱码 → URL 编码问题 → 用 POST + JSON body 传中文
  2. 400 Bad Request → 参数类型没对上或必填没传 → 看响应体里的具体提示
  3. 返回的是字符串不是 JSON → 没加返回对象或没配序列化 → 返回一个对象而不是拼字符串
- 能力点：`java-s1-http`、`java-s1-json`

**验收关**：交一个能跑通的接口（仓库地址或部署地址）。验：能启动、返回预期 JSON、README 写清怎么跑。

## 阶段 2 · 让数据真的存下来（16h）

**2.1 装 MySQL，建第一张表** · 4h

- 学：数据库是什么、表 / 行 / 列、主键有什么用、SQL 四句话
- 练：装 MySQL（或 Docker 起一个），建 course 表，插 10 条数据，查出来
- 创：一份建表 SQL + 10 条测试数据
- 验：不看教程，新建一张表并查出数据
- 卡点：
  1. 服务起不来 → 3306 被占或密码策略太严 → 换端口 / 改密码强度要求
  2. 语句执行报语法错 → 忘了分号或引号没配对 → 一次只执行一句
  3. 中文变成问号 → 字符集不对 → 库表统一 utf8mb4
- 能力点：`java-s2-sql`、`java-s2-model`

**2.2 用 MyBatis 把数据接到接口上** · 4h

- 学：ORM 是什么、Mapper 怎么写、连接池是什么、配置放哪
- 练：写一个查询接口，从数据库取数据返回
- 创：课程列表接口（带分页）
- 验：改一条数据库记录，接口返回立刻变
- 卡点：
  1. 报时区错误 → JDBC URL 没指定时区 → 加上 `serverTimezone`
  2. 字段名和属性名对不上 → 下划线转驼峰没开 → 开 map-underscore 或写别名
  3. 跑一会儿就连不上 → 连接没归还 → 别手动拿连接，交给框架
- 能力点：`java-s2-orm`

**2.3 增删改查做全** · 4h

- 学：REST 风格怎么对应四个操作、状态码该返回什么、参数校验放哪
- 练：实现新增 / 修改 / 删除 / 查询四个接口，用测试工具全部调一遍
- 创：一个完整的课程管理小后端（不用做页面）
- 验：四个接口都能通，并且错误输入不会让服务崩
- 卡点：
  1. 不知道用 PUT 还是 POST → 分不清语义 → 修改用 PUT，新增用 POST，记死这一种
  2. 删除到底真删还是标记 → 想不清楚 → 业务数据一律标记删除
  3. 更新时把其他字段覆盖成空 → 只传了部分字段 → 明确只更新传入的非空字段
- 能力点：`java-s2-crud`、`java-s2-rest`

**2.4 让数据不出错：事务与唯一约束** · 4h

- 学：事务是什么、唯一索引挡住什么、外键为什么很多公司不让用
- 练：故意重复插入一次，加唯一索引挡住；写一个事务回滚的例子
- 创：一份"这个库必须加哪些约束"的清单 + 已加约束的表结构
- 验：制造一个并发插入，验证约束真的挡住了
- 卡点：
  1. 事务不生效 → 方法不是 public 或同类内部调用 → 移到另一个类里调用
  2. 唯一冲突报错很难看 → 没捕获 → 转成一句人话的错误提示
  3. 死锁 → 加锁顺序不一致 → 所有地方按同一顺序操作
- 能力点：`java-s2-tx`

**验收关**：交一个带增删改查的小后端。验：四个接口通、数据真落库、约束加对了。

## 阶段 3 · 让别人安全地用你的接口（16h）

**3.1 登录：密码怎么存** · 4h

- 学：为什么不能明文存密码、哈希和加盐、Session 和 Token（JWT）的区别
- 练：实现注册 + 登录，登录后返回 token
- 创：一个带登录的小后端
- 验：打开数据库，确认里面没有明文密码
- 卡点：
  1. BCrypt 每次结果不一样，以为是 bug → 加盐本来就每次不同 → 用 matches 校验而不是比对字符串
  2. token 放哪不知道 → 混淆了存储位置和传递方式 → 放请求头，别放 URL
  3. 退出登录怎么做得想清楚 → token 本身无状态 → 短期有效 + 刷新机制
- 能力点：`java-s3-auth`

**3.2 鉴权：谁能看什么** · 4h

- 学：拦截器 / 过滤器、角色、水平越权和垂直越权
- 练：写拦截器挡掉没 token 的请求；普通用户访问不了管理员接口
- 创：一份鉴权规则表（谁可以访问哪个接口）+ 实现
- 验：换一个用户的 token，确认访问不到别人的数据
- 卡点：
  1. 拦截器没生效 → 没注册或顺序不对 → 确认注册且优先级高于其他
  2. 静态资源被拦 → 路径匹配太宽 → 把公开路径加进白名单
  3. 只在前端隐藏按钮 → 假的鉴权 → **后端必须再判一次**
- 能力点：`java-s3-authz`

**3.3 统一异常与返回格式** · 4h

- 学：为什么不能把异常堆栈直接返回、统一响应体长什么样、错误码怎么定
- 练：写全局异常处理，所有接口返回同一种结构
- 创：一份错误码表 + 全局异常处理实现
- 验：故意触发三种错误，返回的都是同一种结构
- 卡点：
  1. 异常被吃掉 → catch 了不打日志 → 至少打一行日志再返回
  2. 404 没被接管 → 框架默认处理没关 → 接管 NoHandlerFound
  3. 参数校验提示看不懂 → 用的是默认文案 → 每条校验写人话
- 能力点：`java-s3-error`（**VIP 关 V3 覆盖此能力点**）

**3.4 日志与排错** · 4h

- 学：日志级别、该记什么不该记什么、怎么只靠日志定位问题
- 练：给关键路径加日志，故意制造一个错误，只靠日志把它找出来
- 创：一份"出问题先看哪"的排错手册
- 验：让别人制造一个错误，你只靠日志定位
- 卡点：
  1. 日志打了但没打关键参数 → 不知道该记什么 → 出错时你需要什么就记什么
  2. 生产打 DEBUG 拖慢服务 → 级别没分开配 → 生产默认 INFO
  3. 敏感信息进日志 → 直接打了整个对象 → 脱敏后再打
- 能力点：`java-s3-log`

**验收关**：交带登录鉴权的系统。验：没 token 被挡、密码没明文、错误返回统一。

## 阶段 4 · 让它扛得住（22h）

> **这一阶段是它帮不了你的部分。**
> 性能、并发、事务、线上排查，都需要对你自己系统的整体理解——它看不见你的系统，只能猜。
> 这部分学得扎不扎实，决定了你是「会用工具的人」还是「能被工具替代的人」。
> 可以问它"这个指标什么意思""可能的原因有哪几个"，但**它给的猜测必须有数据支撑才作数**。

**4.1 先用数据说话：压测与指标** · 4h

- 学：QPS、响应时间、P99、怎么压测
- 练：用压测工具打你的接口，记录基线数据
- 创：一份压测报告（优化前）
- 验：说得出平均响应时间之外，还要看 P99
- 卡点：
  1. 本机压测数据不准 → 客户端和服务端抢资源 → 分开两台机器，或只做相对对比
  2. 只看平均值 → 平均值会骗人 → 一定看 P99 和错误率
  3. 第一次数据特别差 → JVM 没预热 → 先跑一轮预热再记数据
- 能力点：`java-s4-bench`

**4.2 加缓存：Redis 入门** · 5h

- 学：缓存解决什么、什么时候不该加、穿透 / 击穿 / 雪崩
- 练：给热点查询加 Redis，对比前后 QPS
- 创：一份缓存方案 + 压测对比报告
- 验：把 Redis 停掉，服务还能正常返回（只是变慢）
- 卡点：
  1. 缓存和数据库不一致 → 更新时没处理缓存 → 先更新库再删缓存
  2. 对象存进去取出来报错 → 序列化方式不统一 → 统一用一种序列化
  3. 缓存没设过期时间 → 数据永远不更新 → **所有缓存都要有过期时间**
- 能力点：`java-s4-cache`

**4.3 并发：为什么数据会错** · 4h

- 学：线程安全是什么、锁的粒度、乐观锁和悲观锁
- 练：制造一个超卖（库存变负），再用锁 / 乐观锁修掉
- 创：一个并发安全的扣减库存接口
- 验：并发 100 次扣减，库存不会变负
- 卡点：
  1. 加了锁还是错 → 锁的不是同一把 → 确认锁的是同一个对象
  2. 事务里加锁顺序不对 → 锁先释放事务后提交 → 调整顺序，先提交再释放
  3. 乐观锁一直重试失败 → 冲突太激烈 → 加次数上限并转成明确错误
- 能力点：`java-s4-concurrency`

**4.4 慢查询优化** · 5h

- 学：索引是什么、explain 看什么、最左前缀、什么时候索引会失效
- 练：造 10 万条数据，找一个 2 秒的查询，用 explain 定位，加索引优化到 50ms 内
- 创：优化前后对比（explain 结果 + 耗时）
- 验：不看教程，对一条新慢 SQL 走完定位到优化的全过程
- 卡点：
  1. 加了索引没生效 → 隐式类型转换或用了函数 → 保证字段类型一致、别在字段上套函数
  2. 以为索引越多越好 → 索引会拖慢写入 → 只给真正常查的字段建
  3. 只优化查询不管写入 → 写变慢了没发现 → 优化后重测一遍写入
- 能力点：`java-s4-sqltune`（**VIP 关 V1 覆盖此能力点**）

**4.5 JVM 入门：内存与 GC** · 4h

- 学：JVM 内存分哪几块、垃圾回收在干什么、常见 OOM 长什么样
- 练：制造一个 OOM，看堆栈；用工具看内存占用
- 创：一份"线上 OOM 怎么查"的手册
- 验：看到一段 GC 日志，说得出是不是有问题
- 卡点：
  1. 本地复现不了生产问题 → 参数和数据量不一样 → 复现不了就先做堆转储分析
  2. 只会重启 → 不知道还能查 → 重启前先保存堆快照
  3. 参数乱调 → 照抄别人的 JVM 参数 → 先量后调，改一个看一个
- 能力点：`java-s4-jvm`（**VIP 关 V1 覆盖此能力点**）

**验收关**：交压测报告 + 优化前后对比。验：有基线数据、有优化后数据、说清改了什么。

## 阶段 5 · 让它像个真项目（22h）

**5.1 分层与代码组织** · 4h

- 学：Controller / Service / DAO 各管什么、DTO 和 VO 为什么要分开
- 练：把之前的项目重构成清晰分层
- 创：重构后的项目 + 一份目录说明
- 验：新人看目录说明能找到任意一个功能在哪
- 卡点：
  1. Service 里直接写 SQL → 分层形同虚设 → SQL 只出现在 Mapper
  2. Controller 里写业务逻辑 → 没法复用和测试 → 业务逻辑下沉到 Service
  3. 循环依赖 → 两个 Service 互相引用 → 抽第三个类，或改调用方向
- 能力点：`java-s5-struct`

**5.2 单元测试** · 4h

- 学：测试金字塔、JUnit、Mock 什么时候用、什么样的代码好测
- 练：给 Service 层写测试，覆盖率到 60%
- 创：一份测试套件，在 CI 里能跑
- 验：故意改坏一处代码，测试立刻变红
- 卡点：
  1. 测试依赖数据库跑不了 → 没用 Mock → 外部依赖一律 Mock
  2. 测了 setter/getter → 没意义的覆盖 → 只测有逻辑的方法
  3. 测试太重维护不动 → 测了实现细节 → 测输入输出，不测内部怎么走
- 能力点：`java-s5-test`

**5.3 配置与多环境** · 4h

- 学：dev / test / prod、配置外置、密钥为什么不能进代码库
- 练：三种环境配置分离，密钥走环境变量
- 创：一份配置清单 + `.env.example`
- 验：换一台机器，照着清单能把项目跑起来
- 卡点：
  1. 密钥提交到 Git → 图省事写死在配置里 → 立刻改密并从历史里清理
  2. 本地能跑线上跑不了 → 环境差异没消除 → 差异全部外置成配置
  3. 改了配置没生效 → 没重启或没走对配置文件 → 确认加载的是哪一份
- 能力点：`java-s5-config`

**5.4 容器化** · 5h

- 学：镜像和容器的区别、Dockerfile 在干什么、数据为什么要挂载
- 练：把项目打成镜像，本地跑起来
- 创：一个 Dockerfile + docker-compose（含 MySQL 和 Redis）
- 验：删掉容器重新起一个，数据还在
- 卡点：
  1. 镜像特别大 → 基础镜像选胖了 → 换精简基础镜像，只拷需要的文件
  2. 容器里时区不对 → 镜像默认 UTC → 显式设置时区
  3. 重启后数据没了 → 没挂卷 → 数据目录挂到宿主机
- 能力点：`java-s5-docker`

**5.5 上线：让别人能访问** · 5h

- 学：服务器、域名、反向代理、HTTPS、CI/CD 是什么
- 练：部署到一台服务器，配域名和证书，配好自动部署
- 创：**一个公网可访问的地址**（本阶段硬产出）
- 验：换一台没配过的电脑，打开地址能用
- 卡点：
  1. 端口访问不了 → 安全组没开 → 确认云厂商安全组和服务器防火墙
  2. 关掉终端服务就停 → 进程没托管 → 用守护进程或容器托管
  3. 证书过期 → 没配自动续期 → 配自动续期并加监控
- 能力点：`java-s5-deploy`

**验收关**：交公网地址。验：能打开、CI 能跑、测试通过、密钥没进代码库。

## 阶段 6 · 走向实习（18h）

**6.1 把项目写成能讲的样子** · 4h

- 学：项目经历怎么写、STAR、技术选型要说出理由
- 练：写一份 README（背景、架构图、难点、怎么跑起来）
- 创：一份 README + 一张架构图
- 验：让别人照着 README 把项目跑起来
- 卡点：
  1. 只写功能列表 → 看不出你做了什么 → 每个功能后面加一句"难在哪"
  2. 说不出难点 → 没复盘 → 回想你卡得最久的那次
  3. 写"使用了 Spring Boot" → 等于没写 → 写你用它解决了什么
- 能力点：`java-s6-express`

**6.2 简历与投递** · 4h

- 学：简历筛选在看什么、Java 实习生岗位要求长什么样、投递节奏
- 练：写一份针对 Java 后端的简历
- 创：一份可投的简历 + 一张投递记录表
- 验：简历上的每一条，你都能讲 5 分钟
- 卡点：
  1. 一份简历投所有岗位 → 命中率低 → 按岗位要求调整重点
  2. 项目描述和 README 不一致 → 会被追问穿帮 → 两边对齐
  3. 不知道投什么公司 → 没做功课 → 先列 30 家，分三档投
- 能力点：`java-s6-resume`

**6.3 八股与真实问答** · 5h

- 学：常问的六块——集合、并发、JVM、MySQL、Spring、Redis
- 练：自测 + 计时回答，录下来听一遍
- 创：一份自己的错题本
- 验：同一道题隔一周还能答出来
- 卡点：
  1. 背了不会说 → 只记了结论 → 每道题补一句"为什么"
  2. 只背不写 → 手写就废 → 边背边写一遍关键代码
  3. 被追问就露馅 → 只准备了一层 → 每个知识点往下挖三层
- 能力点：`java-s6-knowledge`

**6.4 面试模拟** · 5h

- 学：项目怎么讲、不会的题怎么答
- 练：完整模拟一场（自我介绍 + 项目 + 追问）
- 创：一段模拟面试记录 + 一份改进清单
- 验：连着答三个追问不卡壳
- 卡点：
  1. 讲项目像背书 → 练的是稿子不是理解 → 讲的时候不许看稿
  2. 不会的题硬编 → 比说不会更糟 → 说清不会 + 你会怎么查
  3. 最后不问问题 → 浪费一次机会 → 准备两个真问题
- 能力点：`java-s6-interview`（**VIP 关 V2 覆盖此能力点**）

**验收关**：交简历 + 模拟面试记录。验：项目描述与 README 一致、能讲清难点。
