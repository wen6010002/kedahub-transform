# 课搭 2.0 产品设计报告

面向：结果型成长社区 · 2026-09-14

---

## 一、先看结论

**课搭还是课搭。** 首页还是资料馆，还是白底橙、宽幅信息流，还是"找资料，先来课搭"。标题也还是「大学生成长社区」——这个定位本来就对，只是 1.0 没做到。

**变的是资料馆里多长出来的两条腿：**

|  | 1.0 | 2.0 |
|---|---|---|
| 资料怎么组织 | 按分类堆 | 按**路线**串，按**信息差**挑 |
| 用户拿走的 | 一堆文件 | 一条**走完的路** + 一份**被认可的结果** |
| 平台提供的 | 内容 | 内容 + **过程陪伴** + **第三方认可** |

三件没变：品牌视觉、账号与信任体系、六成以上的代码地基。

## 二、产品怎么设计

### 2.1 转型的本质

不是把资料站改成课程站。是换一个问题：

1.0 回答的是「**你要什么资料**」。
2.0 回答的是「**你想成为什么样的人，我陪你走完**」。

这个区别很实际。资料站的天花板是下载量——用户拿走文件就走了，你永远不知道他有没有打开。成长社区的天花板是**用户真的变了**——他走完了、做出了东西、拿到了认可，这件事他愿意讲给别人听，也会回来。

### 2.2 首页：资料馆不变，但里面重新排了序

首页从上到下五块，顺序就是优先级：

1. **一条新生提示条** —— 把大一的人直接分流到探索路线
2. **刊头 + 分类行** —— 和现在一模一样，品牌连续性不动
3. **路线入口（两块并排）** —— 全页最显眼的位置
   - 左：「我还不知道自己喜欢什么」→ 探索路线
   - 右：「我想走前端/算法/后端」→ 定制我的路线
4. **信息差专栏** —— 4 张卡片，标题是学长口吻的真话（"大厂暑期实习其实大三上就要投了"、"这 7 类证书别报"）
5. **双区 tab** —— 「资料库」和「路线模板」，资料库仍是默认区

比 1.0 干净在哪：原来的「关注动态」「新生特辑」「最新上架」「编辑推荐」四块并排堆着，第一次来的人不知道先看哪。现在砍掉「编辑推荐」，把「新生特辑」收进资料库区内，主线上只留一条清晰的路。

**为什么把路线提到最上面**：资料是终点，路线是路径。用户来课搭的真实动机从来不是"我想下载一个 PPT"，是"我不知道该怎么走"。资料是这条路走到某一站时顺手拿的工具，不是目的。

### 2.3 大一探索路线 —— 这是最重要的一块新东西

你提的那个问题很准：**新生不该一上来就选方向。** 如果他在开发这条路上投了一年才发现不喜欢，沉没成本会让他硬撑到毕业。

所以大一进来的第一个产品不是"选方向"，是**一条 8 站的探索路线**：

| 站 | 你会做出什么 | 哇时刻 |
|---|---|---|
| ⌨️ 黑窗口 | 一条命令把 100 个乱文件按日期改好名 | 第一次 `cd`，电脑真的走"进"了那个文件夹 |
| 📜 脚本 | 一个自动整理桌面的脚本 | 你写的 3 行代码干完了 1 小时的活 |
| 🌿 Git | 你自己的第一个 GitHub 仓库 | 删掉一整个文件，一条命令变回来 |
| 🎨 前端 | 一个手机上能打开的自我介绍页 | 室友用他的手机打开了你的网址 |
| 🖥️ 服务器 | 一个真实的公网地址 | 在图书馆用流量打开了自己的网页 |
| 🗄️ 数据库 | 一个"今天吃什么"记录器 | 刷新之后数据还在 |
| 🤖 AI | 一个帮你总结课程笔记的小工具 | 它真的读懂了你的讲义 |
| 🌌 模型 | 一个能识别手写数字的小模型 | 你改了参数，它真的变准了 |

每站 1.5–2.5 小时，全部走完约 16 小时，两周晚自习。**完全免费，没有付费点。**

**关键机制：每站结束后打一次手感分。**

三个按钮：🔥 上头了 / 🙂 还行 / 🥱 没感觉。

走完 8 站，你得到一张**手感图谱**——柱状图显示你在哪类事情上眼睛会亮。系统据此推荐 2–3 个方向，并直接生成对应的专属路线。

**为什么这个设计比问卷强**：问卷问你"喜欢逻辑还是喜欢创意"，大一学生根本答不准，因为没试过。但做完一站之后问"刚才那两小时难受吗"，一定答得准。

**用行为数据代替自我描述，是这条路线唯一的方法论。**

而且它的副产品很值钱：8 个能拿给室友看的小东西。哪怕这个人最后不走计算机，这 16 小时也没白花。

### 2.4 定制路线：隐藏式 Agent 怎么工作

用户看到的只有三句话：

「正在读取你的情况…」→「正在从模板中挑选关卡…」→「路线生成完毕」

**不出现"AI""大模型""智能"任何字眼。** 原因很简单：一旦强调是 AI 生成的，用户第一反应是"它会不会瞎编"，信任成本瞬间变高。而如果用户感觉是"课搭按我的情况给我排的"，他默认这是专业的。

底层做的事在第三章展开。这里只说对用户可见的部分：

生成完成后，路线上会挂出**调整批注**——这是让个性化"看得见"的设计：

- ✂️ 已为你跳过 2 关（你写过小项目，所以跳过了变量与类型、列表与字典）
- ➕ 已为你插入 1 个强化关（你没有结构化输出经验，直接做第 3 关会卡住）
- ⏱️ 按每周 6–10 小时重排了节奏
- 🎯 把"课程问答机器人"设成你的主项目

每条批注右边有个「恢复 / 跳过也行」的链接。**用户可以否决 Agent 的判断。** 这一点很重要——它把"系统强加给你的路线"变成了"系统建议、你拍板的路线"。

### 2.5 一条路线长什么样

不是一串待办事项，是 6 个阶段、24 个关卡。以「AI 应用开发」为例：

| 阶段 | 名字 | 关数 | 产出 |
|---|---|---|---|
| 01 | 把工具装好 | 3 | 能跑通的开发环境 |
| 02 | 让程序会取数据 | 4 | 一个会调 API 的脚本 |
| 03 | 走进大模型 | 4 | 稳定输出的结构化调用 |
| 04 | RAG | 4 | 能回答课程问题的机器人 |
| 05 | Agent | 4 | 会自己查资料的周报助手 |
| 06 | 上线 | 3 | 一个别人能打开的地址 |

每个关卡内部是**四拍**：学（看懂）→ 练（动手）→ 创（做出东西）→ 验（确认学会了）。

这个节奏是刻意排的。1.0 的路线只有"勾选/不勾选"，本质是一张待办清单。四拍里的「创」是新增的关键——**每一关都必须产出一个东西**，哪怕很小。这是"结果型"三个字的落点。

阶段末尾是一道**验收门**。免费用户可以自己点亮三条验收标准（自我确认），也可以申请学长验收（付费服务，见第四章）。

**免费用户不会被卡住**——这句话我会在第四章再讲一次，因为它是整个商业模式的地基。

### 2.6 项目组：为什么"同方向进同一个组"

你的判断是对的：路线是个性化的，但老师有限。所以按方向分组建制。

具体规则：
- **一个方向一个组**，按月滚动开班
- 每期 25–30 人封顶（1 位带组学长 + 1 位助教）
- 期长一个月

组里最核心的一个界面叫**组内进度星图**：把 28 个人按"当前走到第几阶段"铺在同一条阶段轴上。你会看到——

「本期 28 人，其中 **6 人正卡在第 3 阶段，和你一样**。」

这句话解决的是一个真问题：**免费路线的完成率低，不是因为难，是因为没人知道你在走。** 项目组做的事情本质上很简单——让 27 个人知道你这周该交东西了。

组里的其他内容：四层验收漏斗、月度答辩节、项目墙、组内讨论、带组学长答疑。

### 2.7 信息架构总图

```

├── 首页（资料馆）
│   ├── 路线入口 ──┬── 探索路线（大一，免费）
│   │              └── 定制路线 ── 问卷 → 生成 → 我的路线

```

## 三、Agent 怎么设计

### 3.1 先纠正一个我自己搞错的地方

上一版我把验收服务写成了 Java（Spring AI Alibaba）。原因是我记得你要往 Java Agent 方向走，就顺手把技术选型往求职叙事上靠了。

**这个思路是错的。** 生产系统的技术选型标准只有一个：怎么高效、怎么好维护。求职叙事不该决定架构。

修正后的选型：**全部 TypeScript，一个代码库，跑在课搭原有的 Next.js + BullMQ worker 上。**

三条理由：

1. **Agent 的核心产物是结构化对象**，而结构化对象最容易在跨语言边界上出问题。用一套语言写完，从 Zod schema 到数据库字段是同一个类型定义，不用手写两头对齐的 DTO。
2. **课搭已经有生产验证过的异步骨架**：BullMQ 共享队列 + on-demand 投递 + 指数退避重试 + fail-closed 哲学，还有一个直连的 DeepSeek 客户端。Agent 生成服务只需要加一个 job case，不用新建服务、不用配新部署。
3. **性能在这里根本不是瓶颈**。生成一条路线是分钟级的低频任务，一天几百次。为这种负载引入第二个运行时，换来的是双倍的部署、监控、日志、依赖升级负担。

**那 Java 放在哪？** 如果你想要一个 Java Agent 项目写进简历，正确做法是做一个**跟课搭解耦的独立小项目**（比如用 Spring AI Alibaba Graph 搭一个多 Agent 协作的 demo），而不是把课搭的生产架构拆成两半。为了简历去增加生产系统的复杂度，方向是反的。

### 3.2 核心原则：模板保证下限，Agent 提供上限

这是整个 Agent 设计里最重要的一句话。

**绝对不让模型从零生成一条路线。** 那必然会编出不存在的资源、不合理的顺序、错误的时长。

正确做法分两层：

- **模板层**（人写）：由学长 + 教研组写出来、经过验证的路线模板，存成结构化 JSON。每个阶段、每个关卡、每个资源都有一个稳定 id。
- **Agent 层**（模型改）：模型只能对模板做**增删改排序**，输出一串 patch 操作。

打个比方：不是让实习生从零写方案，是给他一盒已经审核过的卡片，让他按客户情况挑卡、排序、微调。

### 3.3 管线：六个能力

```
用户输入                      Agent 六步                        产出
─────────────────────────────────────────────────────────────────────
问卷 6 题         ①  读你      →  用户画像
探索路线 8 次手感      (Intake)
                              ↓
方向 + 年级 + 基础  ②  选模板    →  匹配到 1 条模板      ← 规则引擎为主
                      (Match)
                              ↓
                             ③  改模板    →  5–8 条 patch 操作    ← LLM 唯一自由发挥处
                      (Patch)
                              ↓
                             ④  编排关卡  →  每关的任务卡
                      (Compose)
                              ↓
                       ┌──────┴──────┐
                       ↓             ↓
                  ⑤ 陪跑(Coach)  ⑥ 判作业(Review)
                  卡住时给提示    四层验收漏斗第一层
```

**为什么先规则后模型**：能用 if 判断的事不要让模型决定。

- 方向匹配、年级适配、基础判定、时长估算 → **规则引擎**（确定、免费、可解释）
- "这个人具体该跳过哪两关"、"这两个项目哪个更适合他" → **模型**（模糊判断）

模型只在真正模糊的地方出手。这样既便宜又稳定，出错时也容易定位是哪一层的锅。

### 3.4 消灭幻觉的机制

Agent 的自由度被压缩在两处硬约束里：

**约束一：patch 只能是从枚举里选的操作。**

```
RoutePatch =
  | skipStage(stageId, reason)          // 跳过某阶段
  | compressStage(stageId, ratio)       // 压缩某阶段时长
  | insertStage(afterStageId, ...)      // 插入强化阶段
  | insertModule(stageId, ...)          // 插入单个关卡
  | swapProject(stageId, projectId)     // 换主项目
```

一次最多 6 条。模型输出不了别的东西。

**约束二：所有资源引用走白名单。**

模型想引用一个资料、一个项目、一个任务，只能从预先定义的 enum 里挑。想引用 `resourceId: "自己编一个"`？Zod 校验直接失败，重试。

**结果：模型在机制上无法编造内容。** 它只能做"从已验证的积木里挑和排"。这不是靠 prompt 里写"请不要编造"来约束的，是类型系统兜住的。

（顺便说，这也是为什么选 TypeScript：Zod schema 同时是给模型的输出契约、给后端的校验、给前端的类型。一套定义三处用。）

### 3.5 模型选型与成本

| 用途 | 模型 | 单次成本 |
|---|---|---|
| 路线生成（主力） | DeepSeek / GLM-4.6 / qwen3-plus | 一次生成 6–8 次调用 ≈ ¥0.15–0.30 |
| 关卡任务编排 | qwen-flash | ≈ ¥0.01 |
| 验收 AI 初评 | DeepSeek | ≈ ¥0.30 |
| 全站内容审核（1.0 已有） | DeepSeek | ≈ ¥0.001 |

结构化输出统一用 **Vercel AI SDK 的 `generateObject` + Zod**。

月度成本估算：300 个活跃用户，其中约 80 人生成或重生成路线、约 150 次验收 → **≈ ¥200/月**。

这个量级下，模型成本不是需要优化的东西。不要为了省几毛钱把架构搞复杂。

### 3.6 验收的四层漏斗

| 层 | 谁来做 | 耗时 | 决定什么 |
|---|---|---|---|
| L1 | AI 初评 | 10 分钟内 | **不决定通过与否**。跑结构化 checklist：有没有提交、能不能跑、有没有 README、有没有明显抄袭特征 |
| L2 | 同伴互评 | 48 小时窗口 | 同组 3 人按 rubric 打分 + 各写一条改进建议。互评本身是学习 |
| L3 | 助教终审 | 48 小时内 | **唯一决定通过与否的一层**，真人署名。看 L1 机械检查 + L2 同伴意见 + 自己读代码 |
| L4 | 月度答辩 | 项目组内 | 8 分钟讲 + 7 分钟问答。不发证书，是"逼你把项目讲清楚"的训练 |

**L1 明确不决定通过**，这一点是刻意的。AI 打的分不该决定一个人的努力算不算数——那是信任崩塌的起点。AI 只做机械检查，把人的时间省下来做判断。

不通过 → **免费重提，不限次数**。

### 3.7 复用 1.0 的哪些地基

约 60–65% 的现有资产直接继承，一行不改或只加枚举值：

| 地基 | 复用程度 |
|---|---|
| 账号与信任层（edu 邮箱认证、JWT 踢线、RBAC、限流、封号缓存） | 直接用 |
| 异步任务与 AI 骨架（BullMQ 队列、重试退避、fail-closed、DeepSeek 客户端） | 直接用 |
| 打卡账本引擎（勾选账本、连续天数、热力图、打卡榜） | 直接用，作为路线推进的进度底座 |
| 成就引擎（授予幂等、限时卫冕、佩戴、弹层、六阶稀有度） | 引擎 90% 复用，换一套成就字典 |
| 治理三件套（敏感词 Trie + AI 复核 + 举报闭环） | 直接用 |
| 设计系统与部署基建（token 体系、移动 tabbar、通用组件、docker 三副本） | 直接用 |

需要新建的 35–40%，全部围绕三个新概念：**Agent 生成、验收门、项目组**。

## 四、付费怎么设计

### 4.1 一句话

**路线免费，走完也免费。只有一件事收费：让别人认可你走完了。**

### 4.2 三层产品

**① 单次阶段验收 · ¥39/阶段**

把"我自己觉得我做完了"变成一份有署名的证明。

包含：AI 初评（10 分钟）+ 学长复核（48 小时）+ 通过后该阶段的编号印记 + 一份能力说明（你强在哪、下一步补哪）。

不通过免费重提，不限次数。

**② 项目组 · ¥449/期（内测 ¥199，限前 3 期）**

同方向 25–30 人一期，一个月。

包含：本期全部阶段验收（通常 5–6 次，单买要 ¥195–234）+ 每周一次学长答疑 + 组内进度星图 + 同伴互评 + 月度答辩节。

7 天无理由退款。

**③ 一对一陪跑 · ¥1,299/月（每期限 10 人）**

给有明确 deadline 的人。每周一次 1v1（60 分钟）+ 简历项目面试逐条改 + 工作日随时文字答疑。

**仅对已通过 2 次阶段验收的人开放**——这个门槛不是为了摆架子，是为了保证带的人真的在走，不然陪跑会变成心理咨询。

### 4.3 为什么这么定价

**① 为什么路线不收费，验收收费**

路线是**信息**。信息在今天基本是免费的，你花点时间总能找到替代品，收费只会把人推走。

验收是**人的时间**。学长要真的打开你的代码看半小时。这件事有成本，也正因此才有价值。

**为一个有真实成本的东西收费，用户是服的。**

**② 为什么不做订阅制**

订阅制的前提是持续使用。但成长是阵发性的——你可能连走两个月，然后期末停三周。在停下来的月份继续扣钱，是最快毁掉信任的方式。

**按次、按期，用多少买多少。**

**③ 为什么免费用户不能被卡住**

如果走到第 3 关弹出"付费解锁下一关"，用户的第一反应不是掏钱，是去别的地方找免费版本，并且从此不再相信这个平台。

**付费墙拦不住人，只会把人推走。**

我们要的是：用户走完了，做出了东西，觉得"这事值得有个证明"，然后自愿掏钱。这个转化率可能只有 5–8%，但每一个都是真的。

**④ 为什么项目组比单次验收划算这么多（这是故意的）**

单次验收 ¥39 × 6 阶段 = ¥234，而项目组 ¥449 多给了答疑、互评、答辩、同伴。

这是设计好的锚点：**一次验收是交易，一期项目组才是产品。** ¥39 的存在是让你用最低成本试一次，然后自己算明白这笔账。

### 4.4 算一笔账

**单次验收的单位经济：**

| 项 | 金额 |
|---|---|
| 收入 | ¥39 |
| AI 初评 | −¥0.30 |

| 项 | 金额 |
|---|---|

| 带组学长 | −¥2,500 |

**冷启动推演**（第 3 个月）：

- 免费用户 1,200 人（主要来自信息差专栏 + 探索路线的自然传播）
- 探索路线走完率 35% → 420 人拿到方向建议
- 付费转化 8% → 约 96 人
- 其中 70 人进项目组（约 2.3 期），26 人单次验收
- 月收入 ≈ 70 × 449 + 26 × 39 ≈ **¥32,400**，毛利 ≈ ¥24,000

这个数字不需要融资，也不需要团队——一个人 + 几个兼职学长就能跑。这是这个模式最好的地方：**它的大小由你能找到多少靠谱学长决定，不由流量决定。**
