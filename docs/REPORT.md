# 课搭 2.0 产品设计报告

面向：结果型成长社区 · 2026-09-14

---

## 一、先看结论

**课搭还是课搭。** 首页还是资料馆，还是白底橙、宽幅信息流，还是"找资料，先来课搭"。标题也还是「大学生成长社区」——这个定位本来就对，只是 1.0 没做到。

**变的是资料馆里多长出来的两条腿：**

|  | 1.0 | 2.0 |
|---|---|---|
| 资料怎么组织 | 按分类堆 | 按**路线**串，按**信息差**挑 |
| 用户拿走的 | 一堆文件 | 一条**走完的路** + 一份**被认可的结果** |
| 平台提供的 | 内容 | 内容 + **过程陪伴** + **第三方认可** |

三件没变：品牌视觉、账号与信任体系、六成以上的代码地基。

## 二、产品怎么设计

### 2.1 转型的本质

不是把资料站改成课程站。是换一个问题：

1.0 回答的是「**你要什么资料**」。
2.0 回答的是「**你想成为什么样的人，我陪你走完**」。

这个区别很实际。资料站的天花板是下载量——用户拿走文件就走了，你永远不知道他有没有打开。成长社区的天花板是**用户真的变了**——他走完了、做出了东西、拿到了认可，这件事他愿意讲给别人听，也会回来。

### 2.2 首页：资料馆不变，但里面重新排了序

首页从上到下五块，顺序就是优先级：

1. **一条新生提示条** —— 把大一的人直接分流到探索路线
2. **刊头 + 分类行** —— 和现在一模一样，品牌连续性不动
3. **路线入口（两块并排）** —— 全页最显眼的位置
   - 左：「我还不知道自己喜欢什么」→ 探索路线
   - 右：「我想走前端/算法/后端」→ 定制我的路线
4. **信息差专栏** —— 4 张卡片，标题是学长口吻的真话（"大厂暑期实习其实大三上就要投了"、"这 7 类证书别报"）
5. **双区 tab** —— 「资料库」和「路线库」，资料库仍是默认区

比 1.0 干净在哪：原来的「关注动态」「新生特辑」「最新上架」「编辑推荐」四块并排堆着，第一次来的人不知道先看哪。现在砍掉「编辑推荐」，把「新生特辑」收进资料库区内，主线上只留一条清晰的路。

**为什么把路线提到最上面**：资料是终点，路线是路径。用户来课搭的真实动机从来不是"我想下载一个 PPT"，是"我不知道该怎么走"。资料是这条路走到某一站时顺手拿的工具，不是目的。

### 2.3 大一探索路线 —— 这是最重要的一块新东西

你提的那个问题很准：**新生不该一上来就选方向。** 如果他在开发这条路上投了一年才发现不喜欢，沉没成本会让他硬撑到毕业。

所以大一进来的第一个产品不是"选方向"，是**一条 8 站的探索路线**：

| 站 | 你会做出什么 | 哇时刻 |
|---|---|---|
| ⌨️ 黑窗口 | 一条命令把 100 个乱文件按日期改好名 | 第一次 `cd`，电脑真的走"进"了那个文件夹 |
| 📜 脚本 | 一个自动整理桌面的脚本 | 你写的 3 行代码干完了 1 小时的活 |
| 🌿 Git | 你自己的第一个 GitHub 仓库 | 删掉一整个文件，一条命令变回来 |
| 🎨 前端 | 一个手机上能打开的自我介绍页 | 室友用他的手机打开了你的网址 |
| 🖥️ 服务器 | 一个真实的公网地址 | 在图书馆用流量打开了自己的网页 |
| 🗄️ 数据库 | 一个"今天吃什么"记录器 | 刷新之后数据还在 |
| 🤖 AI | 一个帮你总结课程笔记的小工具 | 它真的读懂了你的讲义 |
| 🌌 模型 | 一个能识别手写数字的小模型 | 你改了参数，它真的变准了 |

每站 1.5–2.5 小时，全部走完约 16 小时，两周晚自习。**完全免费，没有付费点。**

**关键机制：每站结束后打一次手感分。**

三个按钮：🔥 上头了 / 🙂 还行 / 🥱 没感觉。

走完 8 站，你得到一张**手感图谱**——柱状图显示你在哪类事情上眼睛会亮。系统据此推荐 2–3 个方向，并直接生成对应的专属路线。

**为什么这个设计比问卷强**：问卷问你"喜欢逻辑还是喜欢创意"，大一学生根本答不准，因为没试过。但做完一站之后问"刚才那两小时难受吗"，一定答得准。

**用行为数据代替自我描述，是这条路线唯一的方法论。**

而且它的副产品很值钱：8 个能拿给室友看的小东西。哪怕这个人最后不走计算机，这 16 小时也没白花。

### 2.4 定制路线：一个人一条路线

用户看到的只有三句话：

「正在读取你的情况…」→「正在按你的情况排关卡…」→「你的路线生成完毕」

**不出现"AI""大模型""智能"任何字眼。** 原因很简单：一旦强调是 AI 生成的，用户第一反应是"它会不会瞎编"，信任成本瞬间变高。而如果用户感觉是"课搭按我的情况给我排的"，他默认这是专业的。

**生成完之后，路线上不出现任何"为你跳过了什么""为你调整了什么"。**

这一条是刻意去掉的。一旦你告诉用户"已为你跳过 2 关"，你其实同时说了两件事：有一份标准模板存在，以及你手上这条是它的改版。用户会立刻开始想"那我是不是被砍了内容""标准版是不是更好"——**私人定制感当场消失，剩下的全是猜疑。**

所以那排批注改成只讲**这条路是按什么排的**：

- 节奏按你每周能给的 6–10 小时排的
- 主项目选了「课程问答机器人」，因为你说过想做个能帮室友的东西
- 从你已经会的那部分直接起步
- 第 3 关前面垫了一步，因为那里最容易卡住

说的都是这条路**有什么、为什么这么排**，不是它**少了什么**。用户看到的是"这是给我排的"，不是"这是改过的"。

**一个人一条路线。** 你看不到别人那条，别人也看不到你的。同一批进来的人，路线长度、关卡数、主项目都可能不一样——这不是 bug，是它本来该有的样子。

### 2.5 一条路线长什么样

不是一串待办事项，是 6 个阶段、24 个关卡。以「AI 应用开发」为例：

| 阶段 | 名字 | 关数 | 产出 |
|---|---|---|---|
| 01 | 把工具装好 | 3 | 能跑通的开发环境 |
| 02 | 让程序会取数据 | 4 | 一个会调 API 的脚本 |
| 03 | 走进大模型 | 4 | 稳定输出的结构化调用 |
| 04 | RAG | 4 | 能回答课程问题的机器人 |
| 05 | Agent | 4 | 会自己查资料的周报助手 |
| 06 | 上线 | 3 | 一个别人能打开的地址 |

每个关卡内部是**四拍**：学（看懂）→ 练（动手）→ 创（做出东西）→ 验（确认学会了）。

这个节奏是刻意排的。1.0 的路线只有"勾选/不勾选"，本质是一张待办清单。四拍里的「创」是新增的关键——**每一关都必须产出一个东西**，哪怕很小。这是"结果型"三个字的落点。

阶段末尾是一道**验收关**。它是一道**独立的关卡**，不在学习路径上——你可以先走过去继续学，但那道门会一直亮着"未通过"。

**关卡里要做什么，进去之前看不到。** 你能看见有这么一道门、它考哪个方向、它通向哪枚印记；具体要交什么、按哪几条判，解锁之后才显示。

这么做有两个原因。一是**公平**：标准和任务一旦公开，它就会变成一份能被搜到答案的作业。二是**诚实**：验收本来就该考"你有没有真的做出来"，而不是"你能不能照着标准凑出来"。

走进去之后，交一个能跑起来的东西——一个能打开的链接、一个仓库地址、或一段录屏——**AI 会把它真的打开点一遍**，逐条告诉你哪条过了、哪条没过、卡在哪一步。

**进这道门要付费**。不过免费用户每周有一次免费额度，够你试一次；项目组和陪跑用户不限次数。具体价格见第四章。

### 2.6 项目组：为什么"同方向进同一个组"

你的判断是对的：路线是个性化的，但老师有限。所以按方向分组建制。

具体规则：
- **一个方向一个组**，按月滚动开班
- 每期 25–30 人封顶（1 位带组学长 + 1 位助教）
- 期长一个月

组里最核心的一个界面叫**组内进度星图**：把 28 个人按"当前走到第几阶段"铺在同一条阶段轴上。你会看到——

「本期 28 人，其中 **6 人正卡在第 3 阶段，和你一样**。」

这句话解决的是一个真问题：**免费路线的完成率低，不是因为难，是因为没人知道你在走。** 项目组做的事情本质上很简单——让 27 个人知道你这周该交东西了。

组里的其他内容：同伴互评、月度答辩节、项目墙、组内讨论、带组学长答疑。

│   ├── 路线入口 ──┬── 探索路线（大一，免费）

## 三、Agent 怎么设计

### 3.1 先纠正一个我自己搞错的地方

上一版我把验收服务写成了 Java（Spring AI Alibaba）。原因是我记得你要往 Java Agent 方向走，就顺手把技术选型往求职叙事上靠了。

**这个思路是错的。** 生产系统的技术选型标准只有一个：怎么高效、怎么好维护。求职叙事不该决定架构。

修正后的选型：**全部 TypeScript，一个代码库，跑在课搭原有的 Next.js + BullMQ worker 上。**

三条理由：

1. **Agent 的核心产物是结构化对象**，而结构化对象最容易在跨语言边界上出问题。用一套语言写完，从 Zod schema 到数据库字段是同一个类型定义，不用手写两头对齐的 DTO。
2. **课搭已经有生产验证过的异步骨架**：BullMQ 共享队列 + on-demand 投递 + 指数退避重试 + fail-closed 哲学，还有一个直连的 DeepSeek 客户端。Agent 生成服务只需要加一个 job case，不用新建服务、不用配新部署。
3. **性能在这里根本不是瓶颈**。生成一条路线是分钟级的低频任务，一天几百次。为这种负载引入第二个运行时，换来的是双倍的部署、监控、日志、依赖升级负担。

**那 Java 放在哪？** 如果你想要一个 Java Agent 项目写进简历，正确做法是做一个**跟课搭解耦的独立小项目**（比如用 Spring AI Alibaba Graph 搭一个多 Agent 协作的 demo），而不是把课搭的生产架构拆成两半。为了简历去增加生产系统的复杂度，方向是反的。

### 3.2 核心原则：模板保证下限，Agent 提供上限

这是整个 Agent 设计里最重要的一句话。

**先说清楚：这一整套机制只存在于后端。** 用户永远看不到"模板"这个词，也看不到"为你调整了什么"——他看到的只是一条为他排好的路线（原因见 2.4）。下面讲的是它内部怎么保证不出错。

**绝对不让模型从零生成一条路线。** 那必然会编出不存在的资源、不合理的顺序、错误的时长。

正确做法分两层：

- **模板层**（人写）：由学长 + 教研组写出来、经过验证的路线模板，存成结构化 JSON。每个阶段、每个关卡、每个资源都有一个稳定 id。
- **Agent 层**（模型改）：模型只能对模板做**增删改排序**，输出一串 patch 操作。

打个比方：不是让实习生从零写方案，是给他一盒已经审核过的卡片，让他按客户情况挑卡、排序、微调。

### 3.3 管线：六个能力

```
用户输入                      Agent 六步                        产出
─────────────────────────────────────────────────────────────────────
问卷 16 题        ①  读你      →  用户画像
探索路线 8 次手感      (Intake)
                              ↓
方向 + 年级 + 基础  ②  选模板    →  匹配到 1 条模板      ← 规则引擎为主
                      (Match)
                              ↓
                             ③  改模板    →  5–8 条 patch 操作    ← LLM 唯一自由发挥处
                      (Patch)
                              ↓
                             ④  编排关卡  →  每关的任务卡
                      (Compose)
                              ↓
                       ┌──────┴──────┐
                       ↓             ↓
                  ⑤ 陪跑(Coach)  ⑥ 判作业(Review)
                  卡住时给提示    系统验收（独立关卡）
```

**为什么先规则后模型**：能用 if 判断的事不要让模型决定。

- 方向匹配、年级适配、基础判定、时长估算 → **规则引擎**（确定、免费、可解释）
- "这个人具体该跳过哪两关"、"这两个项目哪个更适合他" → **模型**（模糊判断）

模型只在真正模糊的地方出手。这样既便宜又稳定，出错时也容易定位是哪一层的锅。

### 3.4 消灭幻觉的机制

Agent 的自由度被压缩在两处硬约束里：

**约束一：patch 只能是从枚举里选的操作。**

```
RoutePatch =
  | skipStage(stageId, reason)          // 跳过某阶段
  | compressStage(stageId, ratio)       // 压缩某阶段时长
  | insertStage(afterStageId, ...)      // 插入强化阶段
  | insertModule(stageId, ...)          // 插入单个关卡
  | swapProject(stageId, projectId)     // 换主项目
```

一次最多 6 条。模型输出不了别的东西。

**约束二：所有资源引用走白名单。**

模型想引用一个资料、一个项目、一个任务，只能从预先定义的 enum 里挑。想引用 `resourceId: "自己编一个"`？Zod 校验直接失败，重试。

**结果：模型在机制上无法编造内容。** 它只能做"从已验证的积木里挑和排"。这不是靠 prompt 里写"请不要编造"来约束的，是类型系统兜住的。

（顺便说，这也是为什么选 TypeScript：Zod schema 同时是给模型的输出契约、给后端的校验、给前端的类型。一套定义三处用。）

### 3.5 模型选型与成本

| 用途 | 模型 | 单次成本 |
|---|---|---|
| 路线生成（主力） | DeepSeek / GLM-4.6 / qwen3-plus | 一次生成 6–8 次调用 ≈ ¥0.15–0.30 |
| 关卡任务编排 | qwen-flash | ≈ ¥0.01 |
| 验收 AI 初评（无头浏览器 + 视觉模型，跑一遍 demo） | DeepSeek + 视觉模型 | ≈ ¥0.40 |
| 全站内容审核（1.0 已有） | DeepSeek | ≈ ¥0.001 |

结构化输出统一用 **Vercel AI SDK 的 `generateObject` + Zod**。

月度成本估算：1,200 免费用户里约 400 人当月有推进，人均过 2 道验收关、平均重提 1.5 次 → 约 1,200 次 系统验收；加 80 次路线生成。**总计 ≈ ¥500/月**。

比旧方案高了一倍多，因为 系统验收从"读一遍代码"变成了"开一个浏览器把 demo 点一遍"——多了容器和截图。但这 ¥500 换来的是**免费层能给出一个真结论**，是整个免费体验里最值钱的部分。这个量级下，模型成本仍然不是需要优化的东西。

### 3.6 验收关：AI 把你的 demo 跑一遍

每个阶段末尾是一道验收关。走进去，你要交的**不是代码，是一个能跑起来的东西**。三种形态任选：

| 你交什么 | AI 怎么验 |
|---|---|
| 一个能打开的链接 | 无头浏览器打开它，照验收标准点一遍：该有的按钮在不在、点了有没有反应、中途会不会报错。每一步截图 |
| 一个仓库地址 | 拉下来，读 README，看目录结构，能跑就把测试跑一遍 |
| 一段录屏 | 视觉模型看一遍，逐条对照标准 |

AI 交回来三样东西：**逐条的 ✓/✗**、**截图证据**、**卡在哪一步**。

这一步比"读一遍代码"强得多，因为代码漂亮但打开是白屏，就是没做完；代码乱但能跑通，对大一学生就是完成了。

**验收关验的是结果，不是过程。** 这跟"结果型社区"是同一件事。

**系统判什么、不判什么，这条线要划死：**

| 系统判（事实） | AI 不判（判断） |
|---|---|
| 做出来了没有 | 做得好不好 |
| 跑不跑得起来 | 代码写得漂不漂亮 |
| 说好的功能在不在 | 有没有更好的实现 |
| 有没有明显的抄袭特征 | 这个人学到了多少 |

左边是事实，机器判得又快又准、又便宜。右边是判断，机器判不了，**也不该由它判**——AI 说"你通过了"和学长说"你通过了"，分量完全不同，前者说多了会把这个凭证本身说废。

所以验收关上有两档：

| | 系统验收 | 学长验收 |
|---|---|---|
| 给你什么 | "做对了没有"这个事实 | "做得怎么样"这个判断 |
| 谁判 | 无头浏览器 + 视觉模型 | 真人助教，署名 |
| 多久 | 3 分钟 | 48 小时内 |
| 价格 | **¥9 / 关**（免费用户每周 1 次） | **¥39 / 阶段** |
| 结论能对外吗 | 不能 | 能——编号印记，可查 |

**验收关是整个产品里唯一的收费点。** 它不拦你走路——学习路径在门外，你照走——但它是唯一能"通过一个阶段"的方式。

### 3.7 完整链路：两档验收 + 组内两层

把上面两扇门展开，就是完整的一条链：

| 层 | 谁来做 | 耗时 | 给什么 | 价格 |
|---|---|---|---|---|
| **系统验收** | 无头浏览器 + 视觉模型 | 3 分钟内 | 逐条 ✓/✗ + 截图证据 + 缺口定位 | **¥9/关** · 免费用户每周 1 次 · 组内不限 |

不通过 → **免费重提，不限次数**。重提不再收费这一条，两层都适用。

（系统验收 ¥9 这个价是有意的：它便宜到可以随手买，但又不像免费那样可以随便糟蹋。免费送的东西没人珍惜，交过 9 块钱的人会认真读完那份清单。）

约 60–65% 的现有资产直接继承，一行不改或只加枚举值：

## 四、付费怎么设计

### 4.1 一句话

**学习和探索全免费。收费只在验收关这一处。**

验收关卖两样东西：**"我做对了没有"（¥9）** 和 **"有人认我了"（¥39）**。

### 4.2 五层产品

**① 免费 · ¥0**

- 全部资料库（136 份）
- 计算机探索路线全 8 站 + 手感图谱
- 一条专属定制路线，6 阶段 24 关卡，**学习内容全程可走**
- **每周 1 次免费的 系统验收额度**
- 打卡、进度、周窗口、休整券、路线推进榜

免费用户看得见每一道验收关——知道它在哪、考哪个方向、通向哪枚印记。**但关卡里要做什么、按哪几条判，解锁之后才显示。**

**② 系统验收 · ¥9/关**

一道验收关的入场券，也是最快的一次"我到底做对没有"。

- 把你交的东西（链接 / 仓库 / 录屏）**真的打开点一遍**
- 逐条 ✓/✗ + 每一步的截图 + 卡在哪一步
- 3 分钟内出结论；**这道关解锁之后，改完免费重跑，不限次数**
- 免费用户每周 1 次，项目组与陪跑用户不限次数

**③ 学长验收 · ¥39/阶段**

把"系统说我的 demo 跑通了"变成"一个真人看过，署名认可"。

- 已有的 系统验收结论 + 截图证据
- **真人助教 48 小时内给评语**，逐条说好在哪、差在哪
- 通过 → 该阶段的**编号印记** + 一份能力说明
- 不通过 → **免费重提，不限次数**

（学长验收本身包含一次 系统验收，不用重复买。）

**④ 项目组 · ¥449/期（内测 ¥199，限前 3 期）· 首次 14 天免费**

同方向 25–30 人一期，一个月。

- **系统验收不限次数**（单买 ¥9/关）
- 本期全部学长验收（通常 5–6 次，单买要 ¥195–234）
- 每周一次学长答疑 + 组内进度星图
- 同伴互评 + 月度答辩节
- **新用户首次 14 天免费**：不绑卡、不自动续费、到期不扣款

**⑤ 一对一陪跑 · ¥1,299/月（每期限 10 人）**

给有明确 deadline 的人。每周一次 1v1（60 分钟）+ 简历项目面试逐条改 + 工作日随时文字答疑。

**仅对已通过 2 次学长验收的人开放**——这个门槛不是摆架子，是为了保证带的人真的在走，不然陪跑会变成心理咨询。

**不参与免费试用**，理由见 4.5。

### 4.3 为什么收费点落在验收关

这是整个付费设计里最要紧的一个位置选择。

**关键在于：这道墙立在"你已经学完一段"之后，不是立在"你还什么都没得到"的时候。**

路线中段收费是灾难。走到第 3 关弹一个付费框，用户的第一反应不是掏钱，是去别的地方找免费版本，并且从此不再相信你——那时候他还没拿到任何东西，你却在要他付钱。

验收关不一样。走到这里，他已经花了两个晚上，**产出就在手上**。这时候他要解决的问题不再是"值不值得开始"，而是"这东西到底行不行、能不能拿给别人看"。

而且这道门有两点让它不烦人：

**第一，它不在学习路径上。** 你不付钱，学习照常往下走，只是那扇门一直亮着"未通过"。没有人被半路卡住。

**第二，它里面是什么，你看不见。** 看得见一道门、看不见门里是什么，这件事本身就是动机——比在页面上写十行"快来买"都管用。

**第三，学习永远不收费。** 收费的只有"通过"这一个动作。这两件事在用户心里是分得很开的："学东西要钱"让人反感，"拿证明要钱"大家都能接受——四六级、驾照、考证，都是这个结构。

### 4.4 为什么这么定价

**① 信息和事实免费，判断和署名收费**

路线是**信息**，信息在今天基本免费，收费只会把人推走。

"你的 demo 跑起来了没有"是**事实**，机器几秒钟就能查清，收钱不合理，也收不上价。

"你做得怎么样、好在哪、差在哪"是**判断**。判断要一个人的时间，而且只有真人的判断才有人认。**为一个有真实成本、且别人替代不了的东西收费，用户是服的。**

**② 为什么不做订阅制**

订阅制的前提是持续使用。但成长是阵发性的——你可能连走两个月，然后期末停三周。在停下来的月份继续扣钱，是最快毁掉信任的方式。

**按次、按期，用多少买多少。**

**③ 为什么 系统验收是 ¥9，既不免费也不 ¥39**

**不卖 ¥39，是因为不值。** 系统验收的边际成本是四毛钱，判的是"跑不跑得起来"这种机器几秒钟就能查清的事实。为一个近乎零成本的事实收 39 块，用户一旦想明白，信任就没了。**价格要和成本、和它给的东西对得上。**

**不能全免费，是因为免费的东西没人珍惜。** 随手可得的清单，扫一眼就扔了。收 9 块钱，他会认真读完每一条 ✓/✗，会真的去改。这 9 块钱买的不是结论，是"我会认真对待它"。

**但每周必须送一次。** 一个从没体验过 系统验收的人，不会去买学长验收——他不知道那东西长什么样。每周一次刚好够"做完一个东西验一次"，既尝到味道，又不至于变成刷着玩的免费玩具。

为什么是每周而不是每天：一天一次会让人把它当打卡工具刷，一周一次刚好对上"做完一个东西"的真实节奏。

**④ 为什么项目组比零散买划算这么多（这是故意的）**

零散买：系统验收 ¥9 × 若干次 + 学长验收 ¥39 × 6 阶段 = ¥234 起。而项目组 ¥449 多给了不限次 系统验收、每周答疑、互评、答辩和同伴。

这是设计好的锚点：**零散买是交易，一期项目组才是产品。** ¥9 和 ¥39 的存在，是让你用最低成本先试，然后自己算明白这笔账。

**⑤ 关于"仿照多邻国"，我们学了什么、又改了什么**

学的是**位置感**：主线（学习）永远免费，付费只出现在关卡上；还有每周一次的免费额度——这个"会回血的资源"结构，就是多邻国最有效的一招。

**但有一处必须改掉，就是它的扣心机制。**

多邻国你答错几题就没心了，要么等要么付。注意这里的因果：**资源是在你做错的时候减少的**。这等于拿失败惩罚用户，也是它被骂得最多的一条。

我们的每周额度，消耗发生在你**用掉**的时候，跟对错完全无关。这个差别看着小，实际很大：

- 多邻国的心让人**不敢碰难题**——怕扣心，就绕开没把握的关。
- 我们的额度不会让人不敢做验收——验收本来就是**做完才去**的，不是在做的过程里一点点消耗。

一句话：**多邻国在过程里惩罚，我们在结果处定价。**

课搭的用户本来就焦虑，"我是不是选错方向了"是他们来这里的唯一原因。在一个治焦虑的产品里再造一个惩罚失败的机制，方向是反的。**我们收的是"被认可"的钱，不是"别掉队"的钱。**

### 4.5 十四天免费试用：只给项目组，不给陪跑

**为什么给试用**：挡住付费的不是价格，是"我不知道这东西对我有没有用"。而五个产品里，**只有项目组是"不进去就感受不到"的**——星图、同伴、每周答疑，全是体验性的东西，看介绍页看不出来。

系统验收每周送一次、学长验收 ¥39 一单，这两个本身就是低门槛的入口试用，不需要再给。**只有项目组需要。**

**为什么是 14 天**：一期项目组是一个月。14 天正好卡在他走完第二个阶段验收、群里已经混熟、但整条路还没走完的时候。

**关键不在天数，在结束的位置。** 试用不能结束在"第 14 天"这个日期上，得结束在会疼的地方。所以它跟着期走：从开组那天起算，到期时他已经走完 3 个阶段、群里有 27 个人认识他、下周要上台答辩。这些是丢掉会疼的东西。

**为什么陪跑不参与**：陪跑是纯人力。¥1,299/月 = 4 次 1v1 + 20 个工作日答疑。两周就是 2 次 1v1 + 10 天答疑，白送。而且陪跑每期只收 10 人——如果其中一半是试用的，产能直接占满，真正付钱的人反而进不来。

陪跑已经有一道门槛：**必须先通过 2 次学长验收**。这道门槛本身就是比免费试用更好的筛选器，不需要再叠一个。

**防刷：用课搭已有的 edu 邮箱认证。一个 edu 邮箱，一生一次试用。**

这条比设备指纹和手机号都硬——学生换手机号容易，换学号不容易。这是 1.0 留下的真资产，正好用在这里。

**不绑卡、不自动续费、到期不扣款。** 这条既是产品决策也是合规决策，见 4.7。

### 4.6 算一笔账

**系统验收的单位经济：**

| 项 | 金额 |
|---|---|
| 收入 | ¥9 |
| 无头浏览器 + 视觉模型 | −¥0.40 |
| **毛利** | **¥8.60（96%）** |

这是全站毛利最高的一件东西，也是它该便宜的原因——成本几乎为零。它的作用不是赚钱，是**把用户拉进验收这个动作里**：花过 9 块钱的人，才有可能花 39。

**学长验收的单位经济：**

| 项 | 金额 |
|---|---|
| 收入 | ¥39 |
| 系统验收（含在内，不重复买） | −¥0.40 |
| 学长复核（15 分钟） | −¥12.50 |
| **毛利** | **¥26.10（67%）** |

**一期项目组（30 人）的单位经济：**

| 项 | 金额 |
|---|---|
| 收入 30 × ¥449 | ¥13,470 |
| 带组学长 | −¥2,500 |
| 助教 | −¥800 |
| 模型与平台（含组内不限次 系统验收） | −¥300 |
| **毛利** | **¥9,870（73%）** |

**试用期的成本要单独算**：

每期放 10 个试用名额，按 40% 转化 → 4 人付费。试用期对方占用的边际成本 =（学长 ¥2,500 + 助教 ¥800）÷ 30 人 × 10 人 = **¥1,100/期**。

折成获客成本：¥1,100 ÷ 4 人 = **¥275/人**，而客单价 ¥449。**能跑通，但很紧。**

所以有一条硬规矩：**试用名额必须每期封顶。** 一期如果进来 30 个人全是试用的，这个月就是白干——学长照付、助教照付、一分钱收入没有。这不是保守，这是这个模式唯一的死法。

**冷启动推演**（第 3 个月）：

- 免费用户 1,200 人（主要来自信息差专栏 + 探索路线的自然传播）
- 探索路线走完率 35% → 420 人拿到方向建议
- 每 10 个人里约 6 个会走到验收关试一次免费的 → 约 250 次免费 系统验收
- 这些人里约 150 次会额外买 系统验收，约 96 人进入付费
- 其中 70 人进项目组（约 2.3 期），26 人买学长验收
- 月收入 ≈ 70 × 449 + 26 × 39 + 150 × 9 ≈ **¥33,800**
- 毛利 ≈ ¥25,000，减去平台成本 → **净 ≈ ¥24,700**

这个数字不需要融资，也不需要团队——一个人 + 几个兼职学长就能跑。这是这个模式最好的地方：**它的大小由你能找到多少靠谱学长决定，不由流量决定。**

### 4.7 合规红线

这几条会写进服务条款，不是宣传语：

- **不做就业承诺。** 不保证任何 offer、薪资、内推。验收通过只代表"这份产出达到了这条路线设定的标准"。
- **不代做项目、不代写代码。** 发现代做，撤销验收结果且不退款。
- **不做贷款、分期、预付费包。** 不诱导超前消费，不卖年卡。
- **不做大额预收。** 单笔最高 ¥1,299，按月结算，随时可停。
- **系统验收的结论不构成凭证。** 它是一份自查工具，页面上会写明"系统结论不对外背书"。只有学长验收后签发的编号印记才是课搭的凭证。这条既保护用户，也保护印记本身的价值。
- **验收关不能是盲盒。** 关卡内容解锁后才显示，但**付费前必须看得到它验证哪几项能力**——能力清单公开，具体任务和评分细则才隐藏。用户花的钱要买的是"一个我认可的挑战"，不是一次抽奖。这条是底线，越线就变成盲盒生意了。
- **每周免费额度不累积、不折现、不作废收费。** 当周不用，下周照常发一次；不会攒成 4 次，也不会变成"过期就亏了"的焦虑。
- **免费试用不绑卡、不自动续费、到期不扣款。** 不做"到期静默转付费"。一个校园邮箱只能试用一次。
- 不通过无限次免费重提；7 天无理由退款；价格全部公开；带组学长实名可查。

## 六、需要你拍板的事

**产品上**

1. **验收关的价梯**：系统验收 **¥9/关**（免费用户每周送 1 次，项目组/陪跑不限次）→ 学长验收 **¥39/阶段**（含一次 系统验收，不重复买）→ 项目组 ¥449 两样全包。这是这次改动的主干，最需要你点头。
2. **验收关隐藏到什么程度**：我的方案是**能力清单公开、具体任务与评分细则隐藏**——付费前你能看到"这道关验证检索、评估、引用溯源三项能力"，看不到要交什么、按什么判。底线是不能变成盲盒。你要是想要完全隐藏（连考哪几项能力都不说），跟我说，但我还会再劝一次。
3. **每周免费额度送几次**：目前定的是 **1 次/周**。想让人更快尝到味道可以调到 2 次，代价是 系统验收的单卖量会掉。
4. **AI 的判据边界**：限定在**事实**——跑不跑得起来、说好的功能在不在、有没有抄袭特征。**不碰判断**——好不好、漂不漂亮、值不值。让 系统判得更深，印记本身就会跟着贬值。建议维持现状。
