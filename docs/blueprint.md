# 蓝图 · Blueprint（小搭的记忆）

68 档核心。原型设计阶段：本文是**设计规格**，JSON 仅示意，不落库。

---

## 一、它是什么

**平台对你的了解，摊开给你看。**

不是黑箱推荐，是一张你能改的画像。这是"小搭懂你"能被信任的唯一方式——用户看见它记了什么、凭什么记的、可以改。

一句话定位：**没有证据的了解，不许写进蓝图。**

---

## 二、十个字段

| key | 名称 | 值域 | 主要来源 | 谁可写 |
|---|---|---|---|---|
| `basis` | 现在会什么 | 技术栈清单 + 自评 1–4 | 问卷 Q6/Q7、验收通过记录 | 系统 + 用户 |
| `rhythm` | 节奏 | 每周小时（1–40）、活跃时段、连续性 | 问卷 Q9、真实打卡时间分布 | 系统 + 用户 |
| `taste` | 手感 | 6 模块各 1–3 分 | 探索路线 41 站打分 | 系统 |
| `goal` | 目标 | 就业 / 实习 / 竞赛 / 考研 / 兴趣 | 问卷 Q12 | 系统 + 用户 |
| `deadline` | 时间点 | 年级 + 目标月份 | 问卷 Q10 | 系统 + 用户 |
| `stuck` | 常卡在哪 | 计数：装环境 / 看报错 / 不知下一步 / 做出来不知好不好 | 关卡求助记录、对话抽取 | 系统 |
| `mastered` | 已掌握能力点 | 能力点 id 列表 | 验收通过记录 | 系统 |
| `interest` | 方向权重 | 各方向 0–1 | 手感图谱 + 对话 | 系统 + 用户 |
| `style` | 讲解偏好 | 要类比 / 要代码 / 先讲用途 | 对话抽取 + 设置 | 系统 + 用户 |
| `taboo` | 不想学的 | 技术栈黑名单 | **仅用户可写** | 仅用户 |

`taboo` 系统永不推断 —— 不想学什么只有本人能说，猜错了比不猜更糟。

## 三、单个字段的结构

```json
{
  "key": "rhythm",
  "value": { "hoursPerWeek": 6, "activeSlot": "晚上", "streak": "断断续续" },
  "confidence": 0.9,
  "source": { "type": "survey", "ref": "Q9", "at": "2026-09-14" },
  "history": [
    { "value": { "hoursPerWeek": 10 }, "at": "2026-09-01", "source": {...} }
  ],
  "editedByUser": false,
  "lockByUser": false
}
```

| 字段 | 说明 |
|---|---|
| `confidence` | 0–1。低于 0.5 的显示为"猜的"，且**不参与路线重排** |
| `source` | 必须可见，写人话：「来自问卷第 9 题」「来自第 12 站手感」「来自 9-18 的对话」 |
| `history` | 保留最近 3 次变更，可回滚 |
| `editedByUser` | 用户改过的标「你改的」 |
| `lockByUser` | 锁定后系统不再自动改，只在卡片上提示「系统观察到 X，要更新吗？」 |

## 四、小搭只会三件事

| 动作 | 输入 | 输出 | 防幻觉约束 |
|---|---|---|---|
| **讲这个** | 当前知识点 + 蓝图 | 定制讲解：用 `basis` 里他会的东西打比方、跳过 `mastered` 已有的、按 `goal` 讲"为什么学这个" | 不引用不存在的资料 |
| **给我找资料** | 蓝图 + 当前关 | 从**资料白名单**挑 1–3 份 + 一句"为什么是这份" | 必须给 `resourceId` |
| **重排下一步** | 蓝图 + 进度 | `RoutePatch` 序列 | 只能落在 `_spec.md §七` 的枚举内，一次最多 6 条 |

---

## 五、从对话抽取的 Patch（同样是封闭枚举）

```json
BlueprintPatch =
  | setField(key, value)           // key 必须是十个之一，value 必须在值域内
  | adjustConfidence(key, delta)
  | addEvidence(key, source)       // 补一条证据
  | clearField(key)                // 只能清 confidence < 0.5 的
```

- `key` 不在枚举内 → Zod 失败，重试。
- `value` 越界（如 `hoursPerWeek: 200`）→ 失败。
- `taboo` 的 `setField` 只允许由用户动作触发，系统不得发起。
- **一次对话最多落 3 条 patch**，落多了用户看不过来，也不像"记住了"，像"在扒我"。

## 六、页面交互（15-assistant.html）

布局：**左对话流 / 右蓝图画布**，画布常驻可见，不做抽屉、不做弹窗。

**画布**：10 张字段卡。每张卡 = 值 + 置信度条 + 来源标签 + 编辑笔 + 锁定键。

**更新时的表现（关键爽点）**：

1. 抽中一条 → 对应卡片**边缘橙色脉冲** + 角标「刚刚更新」显示 8 秒
2. 卡片下方出一行：`记下了：你更想做能给别人用的东西 · 撤销`
3. **撤销常驻**，不做二次确认弹窗
4. 置信度 < 0.5 的卡片显示虚线边框 + 「猜的，不一定准」

**顶部**：一句话「平台现在对你的了解」
**底部**：一句「这些了解决定：给你讲什么、推什么资料、下一步走哪关」
**三个常驻按钮**：`讲这个知识点` / `给我找资料` / `按这个重排下一步`

**触发原则**：小搭**只被动触发**，不主动推送打扰用户。

---

## 七、红线

1. **每条了解必须有来源**，无证据不写入。
2. **不静默覆盖用户改过的字段**。有冲突证据时只提示，等用户点头。
3. `taboo` 只有用户能写。
4. 置信度 < 0.5 的字段**不参与路线重排**，只显示在画布上。
5. 蓝图内容**只对本人可见**，不做任何形式的对外展示或排行。
