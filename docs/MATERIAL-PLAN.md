## 二、风格提炼（从实样抽出的可复制骨架）

我读了两份完整的实样：`05-黑窗口-探索版.md` 和 `05-黑窗口-精通版.md`。下面是从里头拆出来的骨架，**新资料照这个写**。

### 2.1 探索版骨架（10 段，顺序不能乱）

| # | 段 | 要求 | 实样里的样子 |
|---|---|---|---|
| 1 | **开头：一个画面** | 第一句里不许有他没见过的词 | 「走进一家互联网公司，随便看几个程序员面前的屏幕，大概率是同一个画面」 |
| 2 | **拆混淆** | 常被混用的词先分清 | 终端 / Shell / 命令行，三个词三个东西 |
| 3 | **它能干的 N 类事** | 明说"不列功能清单，直接看例子"。每类 = 场景 + 不用它会怎样 | 六类，每类一个具体场景（三百个文件搜到天黑 vs 一句话几秒） |
| 4 | **一个真实的场景** | 完整故事，带具体数字 | 「下午三点收到告警：注册接口从 200 毫秒涨到 3 秒」→ 五步 → 八百万行的表 → 十几分钟解决 |
| 5 | **它不擅长什么** | N 条，每条给理由 | 看图的活、要"看见才能判断"的活、探索性的活、命令不好记、它不会拦着你 |
| 6 | **不懂的话，怎么让 AI 帮** | 讲判断什么 + 干跑技巧 | 判断三件事：会不会删东西 / 会不会覆盖 / 作用在哪个目录；把 `mv` 先换成 `echo` 干跑 |
| 7 | **认识几条危险的** | 具体命令 + 真实事故 | `rm -rf /` 那个空格是关键 |
| 8 | **先把东西装上** | Windows 详细（含真实坑）/ Mac 简略 / 有"确认装好了" | 「别选 Vim，新手不知道怎么退出」 |
| 9 | **自己试一下** | 5–10 条，每条后写"你会看到…"；有一个"这一步别跳过" | 「打开你的文件管理器，你会看到『我的第一个文件夹』真的出现了」 |
| 10 | **收尾** | "刚才这几条就是核心，剩下的都是变体" + **不用背** | +「这一站只要让你知道一件事：这个窗口不吓人」 |

最后追加两个固定尾巴：

- **「这一站之后你该能回答」**：5–6 个问题 + **「答不上来不用回头翻，去下一站」**
- **「想再往下看」**：最多三条，每条说清适合谁

### 2.2 精通版骨架（8 段）

| # | 段 | 要求 | 实样里的样子 |
|---|---|---|---|
| 1 | **时间 + 产出物** | 开头一行就说清做完手上有什么，时间要含"留给自己卡住" | 「1 小时到 1 个半小时。其中读 20 分钟，动手 40 分钟，**留 20 分钟给自己卡住和试错**。做完你会有一个：整整齐齐的下载文件夹」 |
| 2 | **装环境 + 装好了是什么样** | 把真实提示符贴出来，逐段解释含义 | `zhangsan@LAPTOP-ABC MINGW64 ~` 每个部分讲一遍 |
| 3 | **正文按动作分节** | 标题是动词，不是知识点 | 「你在哪」「先看看这棵树」「走进去，再走出来」「建东西和搬东西」——不是 `cd 命令` `ls 命令` |
| 4 | **每条命令后紧跟"它会回你"** | 输出写全，含真实样例 | `drwxr-xr-x 5 zhangsan staff 160 9月 10 14:22 Desktop` |
| 5 | **一层一层加** | 每层加一点，立刻看到结果 | `ls` → `ls -l` → `ls -la`，每次只多一个参数 |
| 6 | **不用背 + 给方法** | 给的是方法不是叮嘱 | Tab 补全 / 上箭头翻历史 / Ctrl 加 C 中断 / `--help` |
| 7 | **现在来干正事** | 前面都是练手，这里做真实任务 | 真的把下载文件夹整理一遍 |
| 8 | **卡住了看这里** | 7 条左右，格式：现象（加粗）→ 原因 → 怎么办 | 「提示 `command not found`。命令拼错了…先检查拼写，再用 Tab 补全试试」 |

结尾是**「走完之后」**，不是总结——见下面 2.4。

### 2.3 语言特征清单

- 短句，一段 2–4 行，超过四行就分段
- 具体数字和真名：`IMG_0001.jpg`、八百万行、200 毫秒、六十兆
- 大量「你」，直接对话
- **共情句**：「这不是你记性差，所有人都这样，包括写了十年的人」
- 加粗**一段最多一处**
- 无元叙述、无历史由来、无破折号堆叠
- 不用：值得注意的是 / 本质上 / 说白了 / 换句话说 / 综上所述 / 赋能 / 抓手 / 闭环 / 链路
- 不用「不是 A 而是 B」的排比

### 2.4 三个独有的设计（最值钱，必须继承）

这三个是这套资料和外面所有教程拉开差距的地方，新资料一份都不能少：

**① 减压设计（探索版结尾）**

> 答不上来不用回头翻，去下一站。这些概念会在后面每一站里反复出现，走着走着就清楚了。

**② 分流设计（精通版结尾）**

> 站起来走两分钟，然后回答自己一个问题：刚才那一个多小时里，哪一段让你忘了看时间？
> 如果你在敲 `cd` 进去、`ls` 出来的时候觉得顺手 → 后端、运维、测试
> 如果你从头到尾都在想「为什么不用鼠标」→ 第 2 模块的网页、第 3 模块的 AI 应用

不是总结，是**根据体感把人分流到下一站**。这一条直接服务"探索路线"的产品目的。

**③ 伏笔设计（正文中间）**

> 一个一个搬，搬十几个之后你会开始烦。这种烦躁感是好事，先记住它，第 7 站会告诉你怎么办。

**故意制造一个真实的痛感，然后告诉它这是下一站的引子。** 这是把 41 站串成一条线的关键手法。

## 三、去 AI 味自检表

现有资料是"改了无数版"才去掉 AI 味的。下面把那个感觉转成**可逐条打勾的检查项**。每份资料写完过一遍，每条都要过。

| # | AI 味长这样 | 改成这样 |
|---|---|---|
| 1 | 「这一节我们要讲的是…」「下面重点讲…」 | **整句删掉**，直接从内容开始 |
| 2 | 「数据库是一种用于存储和管理数据的系统」 | 换成一个麻烦或一个他见过的画面开头 |
| 3 | 「以下是五个要点：」 | 「不列功能清单，直接看例子」，改成场景 |
| 4 | 「不是 A，而是 B」 | 拆成两句话分别说 |
| 5 | 「总之，掌握 X 非常重要」 | 删。总结句一律不要 |
| 6 | 「值得注意的是…」「本质上…」「换句话说…」 | 删 |
| 7 | 一句话超过三十个字 | 拆 |
| 8 | 破折号连着用 | 换逗号或拆句 |
| 9 | 每个知识点都加粗 | 一段最多一处 |
| 10 | 只讲怎么做，不讲什么时候不能这么做 | 补「它不擅长什么」或「什么时候不该这么干」 |
| 11 | 「某公司遇到一个问题…」 | 换成具体到数字的场景（八百万行、200 毫秒涨到 3 秒） |
| 12 | 结尾喊口号（「祝学习顺利」「继续加油」） | 换成减压句或分流句 |

**两条最硬的检验**：

- **第一段独立读**：把开头第一段单独拿出来，里面有没有一个"连电脑都不太会用的人"可能没见过的词？有就重写开头。
- **标杆对比**：写完之后，把 `05-黑窗口-探索版.md`（或精通版）放在旁边，各读三段，问一句：**语气是同一个人写的吗？**

## 四、资料体系设计（三层，怎么和现有资料共存）

### 4.1 核心判断

现有资料按**技术/概念**切（黑窗口、Shell、Git、数据库…）。
分支路线按**能力进阶**切（让数据存下来 → 让别人安全用 → 让它扛得住）。

**这是两个不同的切分维度。** 所以分支路线的某一关，会横跨好几份现有资料 + 一部分现有资料里没有的内容。

结论：不能靠"复用现有资料"解决，也不能重写一遍。**新增第三层。**

### 4.2 三层关系

| 层 | 回答什么 | 现有 / 新增 | 数量 |
|---|---|---|---|
| **探索版** | 这东西是什么、能干什么、**干不了什么**、我有没有感觉 | 现有 | 41 |
| **精通版** | 从零做到能交出一个东西 | 现有 | 15 |
| **路线专版** | **在这个方向的真实项目里，这一步怎么做才不出事** | **新增** | 待产 |

**路线专版和精通版的区别**（这条要写死，不然会写成又一份教程）：

> 精通版教你把它做出来。
> 路线专版教你在真实项目里**不把它做砸**——为什么这么写上线会出事、几种做法怎么取舍、怎么判断你这个做法行不行。

它的三个必备特征：

1. 有明确的挂点（第几阶段第几关）
2. **有真实的失败场景**：「这样写能跑，但上线会出事」
3. **有取舍讨论**：「为什么这里不能这么干」
4. 结尾是「怎么判断你这个做法行不行」

### 4.3 目录与命名（**现有目录一律不动**）

```

  01-计算机初识/        不动 ┐

  04-产品初识/          不动 │

```

- 路线专版**不重复讲**探索版/精通版讲过的背景与安装基础

## 五、路线 → 资料的映射机制

**每份路线文件末尾的《资料缺口清单》就是资料的排产输入。** 这是路线和资料之间唯一的接口，两边都认它。

已产出的两份清单：

- `java-backend.md` 末尾：10 份（P0 三份、P1 三份、P2 四份）
- `frontend.md` 末尾：10 份（P0 三份、P1 三份、P2 四份）

### 5.1 写之前先填「资料卡」

每份资料动笔前，先填一张卡（写进 `00-总览/资料清单.md` 对应章节，照现有选题说明的格式）：

```
### s4-4 · 慢查询优化 · 路线专版 · 待写

挂在哪一关：Java 阶段 4 第 4 关（5h）
产出物：优化前后对比（explain 结果 + 耗时）
要讲的三件事：索引是什么 / explain 看哪几列 / 什么时候索引会失效
三条真实卡点：① 加了索引没生效（隐式类型转换）② 以为索引越多越好 ③ 只优化查询不管写入
和现有资料不重复的部分：探索版「07-数据库」只讲了索引能加快查询；这里要讲在 10 万行数据上真的定位并优化一次
前置：先看 02-前后端初识/07-数据库-精通版
```

### 5.2 卡点从哪来

卡点三条是这套资料的命根子，不能现场编。来源优先级：

1. **路线文件里每关已写的三条卡点**（Java 25 关、前端 24 关都已写好）
2. 走过这关的人真的卡住的地方（社群复盘会收集）
3. 实在没有就先空着，**不许编**

## 六、写作流程（含两个防劣化机制）

```
填资料卡 → 写初稿（照 2.1 / 2.2 骨架）→ 过自检表（§三 12 条）
        → 冷读（隔一天再读一遍）→ 标杆对比 → 定稿
```

两个机制：

**① 标杆样本机制**
把 `01-计算机初识/05-黑窗口-探索版.md` 和 `05-黑窗口-精通版.md` 定为**标杆样本**。每份新资料定稿前，和标杆各读三段，确认是同一个人的语气。

**② 冷读机制**
写完当天不算数。隔一天重读一遍，重点看：跳跃（有没有默认读者知道某事）、元叙述（当天写的时候最容易混进去）、结尾是不是喊口号了。
