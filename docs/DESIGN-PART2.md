## 4.5.1 交互语言总纲：山径 · 印记

把「推进」做成可感知的地图，把「完成」做成有分量的物证。三层体系：

| 层 | 职责 | 隐喻 | 呈现纪律 |
|---|---|---|---|
| 语义层 | 让推进可感知 | 远征登山：山径、垭口（验收点）、云雾（未解锁）、登顶（拿结果） | 等高线/地形图式克制图形，**禁止卡通插画** |
| 物证层 | 让完成有分量 | 护照与印章：每过一阶段盖一枚印记，8 枚拼合登顶纹章 + 编号证书 | 雕版印章美学（阴刻/阳刻、墨色、纸感），编号可验证 |
| 呈现层 | 让整体高级 | 书卷/章节排印：8 阶段 = 8 章，衬线标题 + 细体编号 + 大留白 | Linear 式纪律：单一字族、200ms 动效基准、色彩仅用于状态 |

一句话定位：**把多邻国的路径骨架，穿上 Linear 的排版工艺，盖上有重量的印章。**

## 4.5.2 五条设计原则（不可违反）

1. **每屏只有一个主行动**：路线页打开时，「继续任务」是全屏唯一高亮按钮，自动滚动定位到当前节点——多邻国 2022 改版被数据验证的核心收益
2. **路线本身即连胜**：走过的路段永久点亮，断卡不熄灯、不清零。连续性用「足迹 + 周窗」表达，彻底规避火焰连胜的焦虑与愧疚（黑暗模式，见反模式 #1）
3. **庆祝 = 停顿 + 物证，不是粒子**：仪式分三档，最高档 ≤4 秒且以一拍静默开场；撒花已被 UX 社区定性为廉价默认
4. **未解锁 ≠ 灰色死区**：后续阶段以「云雾」渐隐——阶段名 + 一句「为什么」可见，任务细节不可见，给期待感不给压迫感
5. **生成等待是开箱仪式**：诚实分步、可离开、可跳过，绝不出现 spinner

## 4.5.3 页面结构（自上而下）

**① 页头**：路线身份（route code · 模板版本 · 定制日期）+ 标题（from→to）+ goal（用户原话的达成陈述，常驻提醒）+ 四格数据（阶段/足迹/已走百分比/印记数）+ **周窗**（7 格小灯，本周推进 4 次；右侧一行「断卡不清零 · 路一直在」）。

**② 印记护照**：8 枚印记槽横排——已获取的 3 枚为红印（补差/速通/筑基），下一枚高亮虚线（Ⅳ 检索），其余空槽，右侧说明「八枚印记 · 终局拼合登顶纹章 + 编号证书」。这是物证层的常驻可见。

**③ 山径主体（核心）**：一条**纵向蜿蜒 SVG 路径**自上而下穿过 8 个垭口节点 + 登顶旗标。技术实现（原型已落地）：JS 动态测量各阶段卡中心坐标 → Catmull-Rom 平滑路径 → 双层 path 叠加（底层灰虚线山路 + 上层云杉实线按当前阶段点亮）。三种阶段状态：

- **已通过**：实线墨绿段 + 散落「足迹」小刻痕 + 节点为 45° 红方印（菱形）+ 阶段卡右上角一枚斜盖的迷你印记；卡内显示「验收通过 · 落印日期 · 用时 · 回看评语」——走过的路是自信来源，永远可回看
- **当前阶段（活跃卡）**：节点放大 + 呼吸光环 + 「YOU ARE HERE」标；卡片升级为大卡（朱砂描边 + 投影）：阶段能力陈述、why-now 因果句、任务清单（勾选即打卡 + 足迹落定微反馈）、底部「任务 n/7 · 继续任务」+ 验收闸口。**自动滚动定位到视口上 1/3**
- **未解锁（云雾）**：虚线没入渐隐遮罩 + 缓慢漂移的雾光动画；阶段名/标题 blur + 半透明，一句「为什么此时学它」清晰可见；点击弹出预告（Brilliant 式预览：「为什么是它：检索练熟了，才轮到让模型自己决定调什么工具」）
- **登顶**：旗标 + 目标陈述（用户原话）+ 预计抵达日期

**④ 背景**：极淡等高线（5% 以下透明度）——这是「地形图气质」与「卡通山」的分界线：**我们画的是地图，不是山的插画**。

## 4.5.4 阶段命名纪律（能力陈述而非知识分类）

阶段标题必须是**可验收的能力陈述**：正确示范「能用 Python 工程化的方式写程序」；错误示范「Python 基础」。标题本身就是验收标准的预告，也是用户向他人解释「我在干嘛」的语言。why-now 句把 8 个阶段缝成一个因果论证：「你刚学会 X，所以现在学 Y 正合适」。

## 4.5.5 免修申请（防强制线性反弹）

已有基础的用户可对任意阶段发起校验：做一道该阶段验收题，通过即盖章跳过。这是多邻国强制线性翻车的对策——既尊重现实，又让验收标准反向变得可信。

# 4.6 节点详情页（原型 06-node.html）

## 4.6.1 章节化排印

章头 = 罗马数字（Ⅰ–Ⅷ，超大字号朱砂）+ 衬线大标题（能力陈述）+ 「为什么是现在」因果句（与前后章缝合）。信息层级借 Codecademy 三层大纲（总路线→阶段→任务）+ MasterClass 分量排印。

## 4.6.2 四拍节奏（学→练→创→验）

多邻国单元内「学→练→测→叙」四拍映射到我们的任务编排：

| 拍 | 内容 | 视觉 |
|---|---|---|
| 学 | 输入：资源与讲解 | 编辑部式资源卡（冷色） |
| 练 | 随堂实践（6 任务按序） | 任务清单（输入冷色/输出暖色） |
| 创 | 阶段作品提交 | 夜墨作品卡（已按偏好选定） |
| 验 | 验收标准 | 可勾选清单（待闭合的环） |

**编辑部式资源推荐（反假选择）**：每个知识点只推荐 **1 个主编资源 + 2 个折叠备选**（论文向/视频向），明确标注时长与「为什么是它」。拒绝「10 个链接全平铺」——那只会让选择负担回流。

## 4.6.3 阶段作品（创）

作品不是题目，是与用户目标绑定的成果：K-02 第Ⅳ章的作品「深大校园问答机器人」直接复用真实资料库（135 份文档），成品即简历素材。作品卡明示「已按你的偏好选定」，提交 = 仓库链接 + 部署链接 + 评测报告 + ≤500 字复盘。

## 4.6.4 验收标准（验）

加权 rubric 逐项公开（如命中率 30% / 坏例归因 25% / 引用溯源 20%…），每项带权重与 good/bad 锚点；可勾选的「待闭合的环」就是进度环的等价物（Apple 圆环的闭合心理学，无需再画一个环）。通过线明确（加权 ≥80 且关键项达标），未过免费复提。

## 4.6.5 卡壳时刻的「向导」

向导（隐藏 Agent 的人格化）只在三个时刻以克制文案出现：卡壳、开题、验收。语气规范（借 Khanmigo）：先问「你现在卡在哪一步」，不倾倒方案。界面形态是一张常驻但低调的卡片，不是弹窗、不是 chat 框。

# 4.7 阶段验收（四层漏斗的用户侧）

## 4.7.1 提交流

提交前强制互评义务（本人须互评 2 份同伴作品才能提交自己的）；提交物 = 仓库/部署/评测报告/复盘。提交后进入四层漏斗（§6.2 的技术侧），用户侧看到的是**状态机可视化**：`AI 初评中 → 互评中 → 助教终审 → 待答辩 → 通过/待修改`，每层都有进度与预计时长。

## 4.7.2 验收结果仪式（原型 05 内置全流程演示）

通过验收时的仪式是三档仪式的第二档，总时长 ≤4 秒：

1. **静默一拍（200ms）**：结果页先出现清单与「通过」，无任何动效——这一拍是高级感的来源
2. **逐项盖印（每项 250ms）**：rubric 每项依次落一枚小「过」印（缩放 1.3→1 + 2° 旋回 + 墨色加深）+ 触觉单脉冲 ≤20ms
3. **阶段大印落下（800ms）**：本阶段印记 1.6×→1 缩放、-8°→0 旋回、落定墨晕扩散收敛（expo-out）
4. **路线延伸（1.5s）**：切回路线总览，新路段 draw-on 一笔画出
5. **云雾散开（600ms）**：下一阶段从雾中显影
6. 唯一按钮「进入下一阶段」；全程可点击任意处跳过

## 4.7.3 登顶仪式（全程完成，第三档）

8 枚印记从四散位置飞向中心拼合为完整纹章（stagger 120ms/枚）→ 呼吸脉冲 → **登顶证书展开**（纸质感、衬线、姓名 + 路线名 + 起止日期 + 唯一编号 + 可验证链接）。可下载 SVG/PDF、生成分享卡（offer 季的自然传播物料）。**编号与可验证性是「有分量」的关键**：真证书有序号，游戏成就没有。

# 5. 闯关与激励系统

## 5.1 状态机

```
节点：LOCKED → AVAILABLE（前置阶段通过）→ IN_PROGRESS → SUBMITTED → PASSED
阶段：MIST(云雾) → ACTIVE → (验收) → SEALED(落印) → 下一阶段 MIST→ACTIVE
路线：GENERATING → ACTIVE → PAUSED → GRADUATED(登顶)
```

解锁语义：阶段通过验收才解锁下一阶段；节点由「任务勾选 + 作品提交」推进。**取消勾选不追溯**（沿用 1.0 DailyCheckin 的边界语义：走过的路永久点亮）。

## 5.2 连续性设计：路线即连胜

- **已点亮路段 = 不可剥夺的积累**：断卡三天，路还是亮的、足迹还在——这是对火焰连胜机制的根本性替代：连续的载体从「天数」改成「路程」，路程只增不减
- **周窗**：当前阶段卡上一行「本周推进 4 次」+ 7 格小灯（周一至周日，点亮为足迹色）
- **休整券**（借 Apple streak freeze）：可预支休整周（考试周），周窗显示「休整中」，不清零不愧疚
- **回归页**只做一件事：「你已走到阶段Ⅴ，从任务 3 继续」——绝不展示「你已离开 23 天」

## 5.3 打卡账本（复用 1.0）

DailyCheckin 引擎（userId+day 唯一、streakDays 写时计算、UTC+8 日界 dayCn8）**完全复用**，但前台表现从「火焰 + 连续 N 天」升级为「足迹 + 周窗 + 路程」。热力图（1.0 已有 7×26 纯 CSS 橙阶网格）保留在成长记录页作为回顾视图。连续打卡的「周榜/月榜」从 1.0 继承但降为次要（避免制造攀比焦虑）。

## 5.4 成就与印章体系（复用 1.0 V8 引擎）

- 引擎层 90% 复用：授予幂等 / 限时卫冕 / 佩戴 / 弹层 / 六阶稀有度视觉
- 内容层重构：AchievementKey 新增「阶段通关（8 枚，对应 8 章）」「登顶（路线毕业）」「连续周推进」；触发点从「下载/赞/藏」换成「验收通过/阶段落印」
- **印章（印记）是成就的物证化表达**：印记收集本身即成就墙，8 枚拼合登顶纹章是最高荣誉

## 5.5 防焦虑设计（贯穿全线的红线程）

- 不标红、不倒数、不展示「落后 X 天」；对「落后于预估」的唯一表达是「重新校准」（阶段时长按实际节奏悄悄放宽）
- 单主线（不做多目标并行打卡环）；周窗是唯一辅助指标
- 通知仅两类：生成完成、验收提醒（用户自设）；文案只指向前方，无损失厌恶

## 5.6 动效三纪律（进设计系统）

1. **一次只有一个动效焦点**（印记落下时其他静止，路线延伸时印记已完成）
2. **全站两档时长**：常规 200ms（Linear 基准）、仪式 600–900ms、路线 draw-on 1.2–1.5s 是唯一例外档
3. **全量降级**：prefers-reduced-motion 下替换为 ≤150ms 淡入 + 文字状态；产品内提供手动动效开关

| 场景 | 时长 | 曲线 | 属性 |
|---|---|---|---|
| 勾选/按压 | 120–150ms | ease-out / spring | scale + 勾选形变 |
| 常规显隐 | 200ms | cubic-bezier(.2,0,0,1) | opacity/transform |
| 阶段卡展开 | 320ms | expo-out | transform + clip-path |
| 印章落下 | 800ms | expo-out + spring | scale 1.6→1、rotate -8°→0 |
| 路线 draw-on | 1200–1500ms | ease-in-out | stroke-dashoffset |
| 云雾散开 | 600ms | ease-out | opacity + blur |

只动画 transform / opacity / stroke-dashoffset（+ 可接受的 filter），绝不动画 layout 属性。

## 5.7 动效技术选型

| 需求 | 选型 | 理由 |
|---|---|---|
| 组件微交互 | Motion（原 Framer Motion） | React 生态最顺、声明式 spring |
| 页面/视图过渡 | View Transitions API（渐进增强） | 零依赖元素级过渡，不支持时回退路由淡入 |
| 路线 draw-on | 原生 SVG + CSS（pathLength=1） | 无需库，多段 transition-delay 编排 |
| 滚动叙事 | CSS scroll-driven animations（@supports 包裹） | 渐进增强 |
| 长页面性能 | IntersectionObserver 只渲染视口 ±2 阶段 | 灵魂页必须流畅 |
| 云雾遮罩 | 预生成半透明噪声 PNG + CSS mask（**不用 SVG feTurbulence**，性能差） | — |

原则：**能用 CSS 的不用 JS，能用原生 API 的不引库**。路线页全部常驻动效（draw-on、点亮、足迹）都是 SVG + CSS，JS 只负责状态类切换。

## 5.8 反模式清单（12 条，含翻车出处）

日连胜+断签清零 / 满屏礼花 / 进度条长年不动 / 强制线性不能跳 / 横向路线塞手机 / 未解锁全灰 / 游戏皮肤错配严肃场景 / 动效过载 / 生成等待假进度 / 假选择（资源平铺）/ 多目标并行 / 损失厌恶通知——每条的对策均已落进本套设计（完整对照见 interaction-design.md §8）。
