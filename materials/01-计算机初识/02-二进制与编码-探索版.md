## 电脑里只有两个数字

你在电脑上看到的一切，文字、照片、音乐、视频，在电脑内部都只是两个数字：0 和 1。

这是字面意思，没有别的隐藏状态。硬盘上一格一格的磁性状态，要么是有，要么是没有；内存里一个个小电容，要么有电，要么没电。就两种状态，没有第三种。

那怎么表示更多的意思？靠数量。

一个位置只能表示两种意思，两个位置就能表示四种，三个位置八种。位置越多，能表示的意思越多。八个位置放在一起，能表示 256 种，刚好够表示英文字母、数字、标点。这八个位置合起来，就叫**一个字节**。

你听到的「这个文件 3 MB」，说的就是它占了大约三百万个这样的八位组合。

## 文字怎么变成数字

既然电脑里只有数字，那文字就得先翻译成数字。

翻译靠一张表。比如约定「65 代表大写 A，66 代表 B，97 代表小写 a」。电脑存一个字母，其实存的是它的编号。

这套约定就是**编码**。

问题在于，约定不止一套。

最早有一套叫 ASCII，只定了 128 个字符，管英文够了。后来别的国家要存自己的文字，就各自加了自己的表。中文有两套常用的，一套叫 GBK，一套叫 UTF-8。

**同一个汉字，在 GBK 里是一串数字，在 UTF-8 里是另一串数字。** 这就是乱码的来源。

## 乱码是怎么产生的

假设一个文件里存了三个字节：`E4 B8 AD`。

如果读它的程序按 UTF-8 的表去查，查到的是「中」这个字。

如果那个程序按 GBK 的表去查，它会把这三个字节拆成两个字的编号，查出来是另外两个字，可能是「涓」加一个看不懂的符号。

**字节没变，表变了，读出来的东西就变了。**

更麻烦的是，如果字节的个数刚好对不上表的分组方式，程序会读出一些根本不存在的位置，屏幕上就出现方块、问号、或者乱七八糟的符号。

你遇到的所有乱码，都是这一件事。

## 一个真实的场景

说一个到现在还在发生的事。

一个学生从学校系统导出学生名单，拿到一个 `.csv` 文件。他用 Excel 打开，中文全是乱码。

他以为是文件坏了，重新导出了三次，都一样。

后来学长告诉他：别直接双击打开，先打开 Excel，用「数据」里的「从文本导入」，在导入过程中手动选编码，选 UTF-8。

中文正常了。

**问题不在文件上，在打开方式上。** 学校系统导出的是 UTF-8 编码，Excel 双击打开时会按系统默认编码去读，中文 Windows 的默认是 GBK，两边对不上。

这个坑从有中文电脑那天起就存在，到今天还没消失。你以后处理表格，遇到中文乱码，第一反应应该是「编码不对」，而不是「文件坏了」。

## 它的边界

**编码这件事只管文字。** 图片、视频、程序也有自己的编码规则，但那是另一套东西。不要把「图片乱码」和「文字乱码」混为一谈，图片显示不正常通常是文件损坏或者格式不匹配。

**UTF-8 已经是主流了。** 新建文件默认都是 UTF-8，大部分乱码问题出现在「老文件」和「老系统」上。你现在写的东西，基本不用担心。

**改编码不等于改内容。** 用工具把一个 GBK 文件转成 UTF-8，里面的文字不变，变的只是它在硬盘上存的那串数字。转对了文字正常，转错了文字就毁了。所以转之前先复制一份。

**有些字符是看不见的。** 空格、换行、制表符也是一个字节或者几个字节，你在屏幕上看不到它们，但它们确实存在。程序读文件的时候能看见。

## 乱码了，怎么办
遇到乱码，让 AI 帮忙的时候，把情况说具体。

**要说清三件事**：文件是从哪来的（哪个软件、哪个网站导出的）、你用什么打开的、乱码长什么样。

乱码的样子能帮你判断原因。「方块和问号」通常是从别的地方复制过来的字符，本地字体里没有。「æ–‡ä»¶」这种奇怪的字母组合，是把 UTF-8 当成别的编码读了。「涓€」这种字，是把 GBK 当成 UTF-8 读了。

**几个能照做的办法**：

Excel 打开 CSV 乱码，别双击，用「数据」里的「从文本导入」，手动选 UTF-8。

用记事本打开一个文件，看右下角显示的编码是什么。如果显示 ANSI，那就是本地默认编码（中文系统上就是 GBK）。

要转编码，搜「XX 转 XX 在线」有网页工具，但**转之前先复制一份原文件**。

**一条原则**：改编码之前先备份。转错了，原来的内容就找不回来了。

## 先把东西装上

下面要在终端里敲几条命令看字节。Windows 用户先装 Git Bash，Mac 用户不用装。

**Windows**

1. 打开浏览器，搜「git 下载」，第一个就是官网
2. 下载 Windows 版，双击安装，一路点「Next」用默认选项。问你默认编辑器选什么的时候别选 Vim，新手不知道怎么退出来
3. 装完在开始菜单里搜 `Git Bash` 打开

**Mac**

按 Command 加空格，输入「终端」，回车。

装好之后敲 `pwd`。Windows 上显示 `/c/Users/你的名字`，Mac 上显示 `/Users/你的名字`，看到路径就对了。

## 自己试一下

### 看看一个字母和一个汉字各占几个字节

```
cd ~
mkdir 试试编码
cd 试试编码
printf 'A' > 字母.txt
printf '中' > 汉字.txt
wc -c < 字母.txt
wc -c < 汉字.txt
```

第一条输出 `1`，第二条输出 `3`。

**一个英文字母占 1 个字节，一个汉字占 3 个字节。** 这就是为什么同样字数的中文文档，文件比英文大好几倍。

（`printf` 和 `echo` 的区别：`printf` 不会在末尾自动加换行，所以字节数更干净。）

### 把汉字在硬盘上真正存的那串数字打出来

```
od -An -tx1 汉字.txt
```

输出是这样：

```
 e4 b8 ad
```

这三个十六进制数，就是「中」这个字在硬盘上的真实样子。`e4` 是 228，`b8` 是 184，`ad` 是 173。电脑里存的就是这串数字，你的编辑器看到这三个数，查表，才知道该显示成「中」。

（如果提示找不到 `od`，换成 `xxd 汉字.txt` 试试，效果一样。）

### 现在你懂了乱码是什么

```
printf '中' | od -An -tx1 -c
```

`-c` 是让它顺便把每个字节当字符显示一遍。你会看到 `e4`、`b8`、`ad` 各自对应的那个看不懂的符号。

**乱码就是这些单个字节。** 程序读文件时如果从中间断开，读到的就是这些零碎的字节，显示出来就是你平时看到的乱码。
