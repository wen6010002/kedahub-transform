## 三种你一定遇到过的怪事

第一种。你在网上找到一个 PDF，想把里面一段话复制到 Word 里。复制出来是这样：

```
æ–‡ä»¶æ ¼å¼
```

第二种。别人发给你一个表格，后缀是 `.csv`。你用 Excel 打开，里面的中文全是方块和问号。

第三种。你打开一个 `.json` 文件，里面密密麻麻一堆花括号和引号，看着像天书。

这三件事看着没关系，其实是一个原因：**文件里的内容，和读它的程序，对不上。**

## 文件格式是人为约定的

你电脑里的每个文件，说到底都只是一串数字。一串 0 和 1。

同样的这串数字，用不同的方式去读，会读出完全不同的东西。所以需要一个约定：这个文件里的数字该怎么解释。

这个约定就是**格式**。

举个例子。假设文件里存着这些字节：`4E 2D 65 87`。

如果约定是「按 UTF-8 读，这是两个汉字」，你看到的就是「中文」。

如果约定是「按 GBK 读，这也是两个汉字」，你看到的是另外两个字。

如果约定是「按图片读，这是一小块像素的颜色」，你看到的是一小片颜色，比如两个橙色像素。

**同一串数字，三种读法，三种结果。** 这就是为什么格式不对就会出现乱码：程序按它的约定去读，读出来的东西跟你写的对不上。

后缀名（`.txt`、`.jpg`）是给人看的提示，告诉系统「该用哪个程序打开」。但文件里到底是什么，取决于当初是谁用什么格式写进去的。

## 常见的格式各自解决什么

### 纯文本：`.txt`

最简单的一种，里面只有文字，没有任何样式。记事本能打开，任何系统都能读。

优点是不会坏，二十年后还能打开。缺点是不能加粗、不能插图片、不能排版。

### 标记文本：`.md`

也是纯文本，但里面可以用几个符号表示格式。比如开头加 `#` 就是标题，两边加 `**` 就是加粗。

它的好处是：内容还是纯文本（简单、不会坏），但能表达一点格式。现在写技术文档大多用它。

### 结构化数据：`.json`

给程序看的一种格式。它用花括号和方括号把数据组织起来，比如：

```json
{
  "名字": "小明",
  "年龄": 18,
  "爱好": ["打篮球", "看小说"]
}
```

看着乱，但结构非常清楚，程序一眼就能读懂哪部分是名字、哪部分是年龄。你在网页上填的表单，提交给服务器的时候多半就是这个样子。

### 表格数据：`.csv`

纯文本，一行一条记录，字段之间用逗号隔开：

```
名字,年龄,专业
小明,18,计算机
小红,19,中文
```

好处是任何软件都能打开，Excel 也行，记事本也行。缺点是只能存表格，存不了别的。

**这个格式最容易出中文乱码**，原因下面单独讲。

### 带样式的文档：`.docx`、`.pdf`

这两种都不是纯文本。

`.docx` 其实是一个压缩包，里面装着一堆描述「这段字用什么字体、多大、什么颜色」的文件。

`.pdf` 是给「不管在哪台电脑上打开，长得都一样」这个需求做的。它把每一页的排版都固定下来了，所以你看到的就是作者看到的。代价是里面的文字不容易拿出来用，复制出来经常是乱的。

### 图片：`.jpg`、`.png`

这两种都存图片，但取舍不同。

`.jpg` 会丢掉一部分细节来把文件变小，适合照片。放大会看到模糊的方块。

`.png` 不丢细节，颜色更准，但文件大得多。适合截图、图标、需要透明背景的图。

### 压缩包：`.zip`、`.rar`、`.7z`

把一个文件夹压成单个文件，方便传输。里面可以装任何东西，包括别的压缩包。

### 视频：`.mp4`、`.mov`

和图片一样，不同的格式是不同取舍的结果。`.mp4` 兼容性最好，几乎所有设备都能放。

## 一个真实的场景

说个每个做数据的人都会遇到的麻烦。

一个学生从学校系统里导出学生名单，系统给的是 `.csv` 文件。他用 Excel 打开，中文全是乱码。

他以为是文件坏了，重新导出了三次，都一样。后来他问了学长，学长让他别直接双击打开，而是先打开 Excel，再用「数据」里的「从文本导入」，在导入的过程中手动选编码，选 UTF-8。

中文就正常了。

**问题不在文件上，在打开的方式上。** 学校系统导出的是 UTF-8 编码的 CSV，而 Excel 双击打开时会按系统默认的编码去读。中文 Windows 的默认编码是 GBK，两边对不上，就乱码了。

这个坑到今天还没消失。你以后处理表格，遇到中文乱码，第一反应应该是「编码不对」，而不是「文件坏了」。

## 它的边界

**扩展名不能证明文件是什么。** 你把一张图片改名成 `.txt`，它还是张图片，只是双击打不开了。系统按后缀名找程序，程序按真实内容去读，两边可能对不上。

**纯文本最保险，但表达力最弱。** 如果你希望这份东西十年后还能打开，就用 `.txt` 或者 `.md`。如果你需要排版、图片、公式，就必须用 `.docx` 或者 `.pdf`，代价是十年后可能要靠特定软件才能打开。

**格式转换会丢东西。** 把 `.docx` 转成 `.pdf`，排版会变。把 `.png` 转成 `.jpg`，画质会降。转来转去，信息只会少不会多。

**有些格式是私有的。** 不是所有 `.docx` 都能被所有软件正确打开，尤其是一些国产办公软件生成的特殊排版。

## 打不开、乱码了，怎么办
遇到打不开或者乱码，让 AI 帮你判断时，要提供足够的信息。

**要说清三件事**：文件是从哪来的（哪个网站、哪个软件导出的）、你想用它做什么、屏幕上具体是什么现象（乱码长什么样、报什么错）。

只说「我的文件打不开」，AI 只能猜。

**几个你该知道的判断**：

看到一堆方块、问号、`æ–‡ä»¶` 这种奇怪字母组合，多半是编码问题，跟文件本身坏没坏无关。

`.csv` 用 Excel 打开中文乱码，是编码问题。让 AI 告诉你「怎么用指定编码导入 CSV」，它能给你步骤。

一个文件在别人电脑上能打开，在你这里打不开，多半是你缺对应的软件，或者版本太旧。

**一条原则**：改文件格式之前先复制一份。格式转换经常出意外，原件留着最保险。

## 先把东西装上

下面要用终端敲几条命令。Windows 用户先装 Git Bash，Mac 用户不用装。

**Windows**

1. 打开浏览器，搜「git 下载」，第一个就是官网
2. 下载 Windows 版，双击安装，一路点「Next」用默认选项。问你默认编辑器选什么的时候别选 Vim，新手不知道怎么退出来
3. 装完在开始菜单里搜 `Git Bash` 打开

**Mac**

按 Command 加空格，输入「终端」，回车。

装好之后敲 `pwd`。Windows 上显示 `/c/Users/你的名字`，Mac 上显示 `/Users/你的名字`，看到路径就对了。

## 自己试一下

### 造一次乱码出来

```
cd ~
mkdir 试试格式
cd 试试格式
echo "中文" > 中文.txt
cat 中文.txt
```

屏幕上显示「中文」。再看一眼这个文件有几个字节：

```
wc -c < 中文.txt
```

输出 `7`。两个汉字加一个换行，一共 7 个字节。一个汉字占 3 个字节。

现在把它砍到只剩 4 个字节：

```
head -c 4 中文.txt > 半个字.txt
cat 半个字.txt
```

屏幕上出现「中」，后面跟一个看不懂的符号。

**这就是乱码的来源。** 一个汉字由好几个字节组成，读到一半就断了，剩下那半个字节没法翻译成字，程序只好显示一个占位符号。你平时看到的乱码，原理跟这个一样，只是断的位置更乱。

### 扩展名骗不了电脑

```
echo "这其实是一句话" > 假装是图片.png
cat 假装是图片.png
```

虽然名字叫 `.png`，`cat` 照样把里面的文字念出来。因为 `cat` 只管读字节，不管文件叫什么名字。

但如果你去文件管理器里双击它，系统会按 `.png` 去找一个看图软件，然后报错打不开。

**系统不在乎扩展名，应用程序在乎。** 这就是为什么改后缀名不能让一个文件真的变成另一种格式。
