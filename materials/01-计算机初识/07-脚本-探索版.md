## 两小时的活变成三秒

先讲一件真事。

有个学生每周要做一次作业整理：老师发的资料散在十几个文件夹里，命名乱七八糟，他得手动把同一门课的挑出来，重命名成统一格式，再按周次放进对应的文件夹。一次一个多小时。

后来他写了个脚本。第一次写完花了三个小时，调试又花了两个小时。从第四周开始，这件事变成双击一下，三秒。

算一下总账：写脚本花五小时，省下的是每周一小时，乘以剩下的十四周，是十四小时。净赚九小时，还顺手多了一项能写进简历的技能。

这个故事的重点不在省钱，在于**判断什么样的活值得写脚本**。判断标准很朴素：这件事我要做几次。做一次的事，手动做；做三次以上的，就值得写。

## 脚本到底是什么

很多人听到「脚本」会紧张，以为要学编程。

其实脚本的定义非常朴素：**一个装着命令的文本文件。**

你在终端（就是那个黑窗口）里敲的命令，说到底就是一行文字。把这十几行文字写进一个文件，起个名字，以后敲这个名字，里面所有命令就从头到尾跑一遍。这就是脚本。

它和「编程」的关系是：脚本是编程里最简单的一类。不用理解算法，不用管数据结构，就是把你会做的动作记下来，让电脑照着做。

当然，脚本语言也能写复杂的东西。但绝大多数脚本的形态就是「一长串命令 + 几个判断 + 一个循环」。

判断和循环是脚本里仅有的两个「逻辑」。判断是「如果文件是图片就搬到图片文件夹」，循环是「对每一个文件都做这件事」。学会这两个，日常脚本你就能写了。

## 脚本能干的六类事

### 一、整理和改名

上一站说的按类型分文件，按日期重命名照片，把下载的文件按来源分类。这类活的特点是「规则简单，数量巨大」。

### 二、定时任务

每天凌晨三点把数据库备份一份，每周一早上把上周的数据汇总成一张表，每个月一号清理掉三个月前的日志。这些不需要人盯着，写一次，之后它自己跑。

这是脚本最被低估的用途。你写一次，它替你工作几年。

### 三、批量处理文本

你有一个表格文件，需要从里面挑出符合某些条件的行，改一下格式，再输出成另一个文件。或者你有五十个文档，需要把里面的某个词全部替换掉。

这类活用鼠标做要几小时，用脚本是一句话。

### 四、把多个程序串起来

你下载了一个视频，想提取音频、压缩、再传到一个地方。三个程序各自只会做一件事，写个脚本把它们串起来，一条命令搞定。

### 五、检查东西

部署之前检查配置文件里有没有写错的地址，提交代码之前检查有没有不小心写进去的密码，每周检查一遍服务器上有没有异常登录。

这类脚本的价值在于「防患于未然」。它不产生直接成果，但能让你少踩坑。

### 六、给复杂操作包一层

有些操作要敲五条命令，参数还长。写成一个脚本，以后敲一个名字就行。团队里所有人都能用，还不会敲错。

这是「把经验固化下来」的一种方式。

## 脚本语言的家族

听到「学脚本」的时候，很多人不知道该学哪个。这里说清楚。

**Bash（或者 Shell 脚本）** 是终端原生的那个。它的优势是直接操作文件和系统，不用装任何东西，任何一台 Linux 服务器上都有。适合：文件整理、系统操作、把命令串起来。

它的缺点是处理复杂逻辑很别扭。比如处理一个二维表格、算一个稍微复杂的数学公式，写起来很痛苦。

**Python** 是现在用得最广的。优势是语法接近英语，第三方库多到夸张，处理文本、表格、网络请求、数据都有现成的工具。适合：数据处理、爬取网页、自动化办公、AI 相关的活。

它的缺点是跑之前要装环境。别人拿你的脚本，得先装 Python 和一堆依赖才能跑。

**JavaScript** 主要在网页里跑，但它也能在电脑上跑（叫 Node.js）。适合：跟网页有关的自动化、前端构建。

**一句话的判断方法**：跟文件和系统打交道为主，用 Bash；跟数据和网络打交道为主，用 Python。

不过这条判断现在的重要性在下降，原因下面讲。

## 一个真实的场景

说个很多人都会遇到的。

你在做一个项目，用 Git 管理代码，每次提交之前都该做三件事：跑一遍测试、格式化代码、检查有没有把密码写进去。

手动做的话，你总有忘的时候。忘了跑测试，提交了坏代码；忘了检查密码，把密钥推到公开仓库了。

有个工程师写了个脚本，挂在一个叫 Git 钩子的机制上。每次他执行提交，脚本自动跑这三件事。测试没过就拦住，代码格式不对就自动改好，发现疑似密码就直接报错。

他写这个脚本花了两小时。之后两年里，他再也没有手动检查过这三件事，也再没出过这两类事故。

这就是脚本真正的位置：**它不解决难题，它把重复的、容易忘的、容易出错的流程，变成不会忘也不会错的一步。**

## 它不擅长什么

**一次性的活。** 写脚本加调试至少要一小时，你手动做十分钟就完了，不值得。判断标准还是那句：这件事你会做几次。

**需要判断的活。** 脚本只能执行你写清楚的规则。凡是需要「看一眼再决定」的，脚本做不了。比如判断一篇文章写得好不好，判断一个设计合不合理。

**经常变的活。** 如果这件事的规则每周都在改，那脚本改起来比手动做还累。

**涉及敏感操作的活。** 会自动删东西、会自动覆盖文件、会往外发数据的脚本，写错一次的代价可能很大。这类脚本要格外小心，跑之前先干跑。

**图形界面的活。** 脚本擅长处理文字和文件，不擅长操作界面。虽然也有工具能让脚本点鼠标，但很脆弱，界面一改就失效。

## 不会写脚本，让 AI 帮你写
你有一个重复的活想自动化，但你不会写脚本。现在不用会了。把需求描述清楚，让 AI 写。

**关键在于怎么描述。** 描述得好，一次就成；描述得含糊，改十遍也不对。需要说清楚的有四件事：

第一，**输入是什么**。文件在哪个文件夹，什么格式，大概多少个。

第二，**规则是什么**。什么情况往哪走，遇到冲突怎么办。规则要说全，尤其是「例外情况」。

第三，**输出是什么**。结果放在哪，要不要打印一句话告诉我做完了。

第四，**不许做什么**。这条最重要。「不许删除任何文件」「不许覆盖已有文件，遇到同名就跳过」「不许动这个文件夹之外的东西」。

举个例子，对比一下。

含糊的说法：「帮我写个脚本整理下载文件夹」。

清楚的说法：「写一个 Bash 脚本，整理 `~/Downloads` 文件夹。按扩展名分类：图片放 `图片` 子文件夹，文档放 `文档`，压缩包放 `压缩包`，其他放 `其他`。子文件夹不存在就创建。如果目标位置已经有同名文件，跳过并在屏幕上说一句。不要删除任何文件。子文件夹不要移动。最后打印一共移动了多少个文件。」

第二种描述 AI 一次就能写对。而且你回头看一眼，就能判断它写的对不对，因为你的要求都在里面。

**拿到脚本之后，做三件事。**

第一，**读一遍，找 `rm`、`mv`、`>` 这三个东西**。有 `rm` 就问它删什么，有 `mv` 就问它搬到哪、覆盖了怎么办，有 `>` 就问它覆盖的是哪个文件。

第二，**先干跑**。让它把动手的那一步换成打印，看看输出跟你预期的是不是一样。

第三，**先在假数据上跑**。建个测试文件夹，放几个假文件进去试。确认没问题再用在真数据上。

## 先把东西装上

下面要在「终端」里敲命令。终端就是那个黑窗口，你打一行字，电脑照着做。

### Windows

Windows 自带的「命令提示符」和 PowerShell 用不了这一站的命令，敲了会报错。要先装一个 Git Bash，它给你一套和 Mac 一样的命令行环境。

1. 打开浏览器，搜「git 下载」，第一个就是官网
2. 下载 Windows 版，安装包大概六十兆，下完双击打开
3. 一路点「Next」。中间会问你一堆问题，全部用默认选项就行
4. 只有一处要注意：问你默认编辑器（Default editor）选什么的时候，别选 Vim。Vim 是给熟手用的，新手进去不知道怎么退出来。选「Use Notepad as Git's default editor」，或者列表里的 VS Code
5. 装完，在开始菜单里搜 `Git Bash`，点开它

还有一个更快的打开方式：在任意文件夹里点右键，菜单里有一项「Open Git Bash here」，点它就在那个文件夹里直接打开了。

### Mac

Mac 不用装。按 Command 加空格，输入「终端」，回车。

### 确认装好了

打开 Git Bash（Mac 就是终端），敲：

```
pwd
```

Windows 上会显示 `/c/Users/你的名字`，Mac 上会显示 `/Users/你的名字`。看到路径就对了。

Windows 上如果提示「不是内部或外部命令」，说明你打开的是系统的命令提示符，不是 Git Bash，回去重新打开。

## 自己试一下

### 写第一个脚本

```
cd ~
mkdir 试试脚本
cd 试试脚本
echo 'echo "这是我写的第一个脚本"' > 你好.sh
bash 你好.sh
```

最后一条是运行这个脚本，屏幕上出现「这是我写的第一个脚本」。

**这就是一个脚本。** 它现在只打印一句话，但结构已经完整了。

### 给它加一行

```
echo 'echo "今天是 $(date +%F)"' >> 你好.sh
bash 你好.sh
```

屏幕上多了一行，比如「今天是 2026-09-14」。`$(date +%F)` 的意思是「把今天的日期填进来」，运行的时候才会被替换。

你在文件里多写十行，它就打印十句话。写进去的命令换成整理文件的，它就成了整理脚本。

### 让脚本自己看一遍所有文件

```
touch 一号.txt 二号.txt 三号.txt
echo 'for f in *; do echo "这里有个东西叫 $f"; done' > 看文件.sh
bash 看文件.sh
```

屏幕上把当前文件夹里的东西一个个念了出来。这就是 `for` 循环：把一堆东西里的每一个轮流交给 `f`，然后对每个执行一遍中间那段。

### 让它真的干活

```
echo 'mkdir -p 归档; for f in *.txt; do mv "$f" 归档/; done' > 归档.sh
bash 归档.sh
ls
ls 归档
```

`ls` 一看，三个 txt 文件都不见了；`ls 归档`，它们整整齐齐躺在里面。

刚才你做了一件什么事？**你把三条命令写进一个文件，然后打一个名字，电脑就照着做了一遍。** 明天、下个月、换台电脑，只要再打一次这个名字，它还会做一遍。

---

刚才这几条命令就是脚本的核心：把命令写进文件，让电脑照着跑。`echo` 是打印，`for` 是循环，`mkdir` 是建文件夹，`mv` 是移动。剩下的都是这些的组合。
