## 双击安装包之后发生了什么

你下载了一个安装包，双击，弹出一个窗口问你「安装到哪个文件夹」，你点「下一步」，进度条走几秒，然后开始菜单里多了一个图标。

这中间电脑做了三件事。

**第一，解压。** 安装包其实就是个压缩包，里面装着一堆文件。安装程序把它们解压到你指定的文件夹里。

**第二，登记。** 它要告诉系统「我装在这儿了」。这样你双击图标的时候，系统才知道该去哪儿找。

**第三，做配置。** 建一个快捷方式、写几条设置、注册文件类型（比如告诉系统「以后 `.psd` 文件用我打开」）。

装软件说到底就是这三件事：**把文件放进去、告诉系统它在哪、写几条设置。**

理解了这一点，你就能解释很多奇怪的现象。

## 为什么装完找不到

最常见的一种情况：装完了，开始菜单里没有，桌面也没有。

原因通常是：**安装程序没有登记，或者登记到了你没看的地方。**

有些软件是「绿色版」或者「免安装版」，它就是一堆文件，解压到哪儿就在哪儿，不需要安装。你得自己进那个文件夹，找到里面那个 `.exe`，双击才能开。

还有一种是安装程序默认装到了 `C:\Program Files` 下面，但开始菜单的快捷方式建在了一个折叠的子文件夹里，你展开才能看到。

**判断方法**：去 `C:\Program Files` 或者 `C:\Program Files (x86)` 下面找，看有没有那个软件名字的文件夹。找到了，里面有一个 `.exe`，双击它就能开。

## 为什么卸载了还有残留

你把软件卸载了，但硬盘空间没怎么变多。或者过一阵子重装，发现上次的设置还在。

因为卸载程序只删它记得的东西。

它删了主程序的文件，但删不掉这些：你用它生成的文件（比如你在软件里保存的文档）、它写在系统里的设置（Windows 上叫「注册表」）、它下载的缓存、以及你放在别的文件夹里的插件。

这些加起来可能比软件本身还大。

**判断方法**：卸载之后，去这几个地方看一眼有没有残留的文件夹：`C:\Program Files`、`C:\Users\你的名字\AppData`、`C:\ProgramData`。看到了确认没用再删。

## 包管理器：程序员的装法

前面说的都是「下载安装包、双击、下一步」，这是给普通人用的方式。

程序员用的方式叫**包管理器**。它的做法是在终端里敲一句命令，不用去官网下安装包：

```
brew install git
```

然后它自己去网上找、自己下载、自己装好、自己登记。整个过程你不用点任何东西。

Mac 上叫 Homebrew，Linux 上叫 apt 或者 yum，写网页用的叫 npm，写 Python 用的叫 pip。

**为什么程序员喜欢它？**

一是快。装十个软件就是十行命令，不用点十遍「下一步」。

二是干净。它知道每个软件依赖什么，会自动把缺的一起装上。手动装的话，你经常装到一半发现「缺少某个组件」，然后要去找那个组件，那个组件又缺别的东西。

三是能一键卸载。`brew uninstall git` 就干净了，不用满硬盘找残留。

四是可以写进文档。团队里新来一个人，把几条安装命令复制给他，他的环境和老同事一模一样。

**包管理器也有代价**：它默认装在特定的位置，你不能随便选。它管的软件通常是命令行工具和开发用的东西，微信、PS 这类桌面软件还是得手动装。

## 一个真实的场景

一个学生要开始学写代码。他照着教程装环境，教程上写着需要 Python。

他去官网下载了安装包，双击，装好。然后教程让他敲一句 `python --version` 检查装好了没有。

他敲了，屏幕上说找不到这个命令。

他以为自己没装成功，又装了一遍，还是找不到。

后来他发现问题了：安装的时候有一个复选框，写着「Add Python to PATH」，默认是**没勾**的。他一路点「下一步」，跳过了那一项。

**这个复选框干的事，就是把 Python 装在哪儿登记到系统里。** 没勾，系统就不知道有这个程序，你敲命令它就找不到。

解决方法是重新运行安装包，选「Modify」，把那一项勾上。或者手动把 Python 的安装目录加进 PATH。

这个坑每年都会绊住成千上万的新手。这跟你的操作水平没关系，是安装程序的默认选项设得不友好。**装开发工具的时候，看到「Add to PATH」这类选项，一律勾上。**

## 它的边界

**包管理器管不了所有软件。** 桌面软件、游戏、设计工具，大部分还是得手动装。它主要管命令行工具和开发用的库。

**它也不能保证装上的东西能用。** 它只负责把文件放到位，如果软件本身有问题，或者你的系统版本不兼容，照样跑不起来。

**「装上了」和「能用了」是两件事。** 装上了是把文件放好了，能用了是配置也对、依赖也齐。新手经常卡在这两步之间。

**版本会打架。** 同一个软件，A 项目需要 1.0 版，B 项目需要 2.0 版。装了两个版本，系统不知道该用哪个。这是开发环境里最烦人的问题之一，有专门的工具来解决（虚拟环境、容器），但那是后面的事了。

## 装不上，怎么办
**装不上或者装完找不到，先说清三件事**：从哪下的、装的时候有没有遇到提示、你想敲什么命令。

**几个能照做的办法**：

装完在开始菜单找不到，去 `C:\Program Files` 下面找同名文件夹，里面通常有 `.exe`。

敲命令说「不是内部或外部命令」，多半是 PATH 没配好。让 AI 告诉你「怎么把这个程序的目录加到 PATH 里」，它能给你步骤。

卸载之后想清干净，卸载完再手动看一眼 `C:\Program Files` 和 `C:\Users\你的名字\AppData` 里有没有残留。

**一条原则**：装开发工具的时候，安装界面上凡是提到「PATH」「环境变量」「Add to」的选项，都勾上。勾错了顶多多一条记录，不勾可能就要重装。

**让 AI 帮你装东西的时候，把系统说清楚。** Windows 和 Mac 的步骤完全不一样，不说清它可能给你一套 Mac 的命令，你敲了全是报错。

## 先把东西装上

下面要在终端里敲几条命令，看看「一个程序在硬盘上长什么样」。Windows 用户先装 Git Bash，Mac 用户不用装。

**Windows**

1. 打开浏览器，搜「git 下载」，第一个就是官网
2. 下载 Windows 版，双击安装，一路点「Next」用默认选项。问你默认编辑器选什么的时候别选 Vim，新手不知道怎么退出来
3. 装完在开始菜单里搜 `Git Bash` 打开

**Mac**

按 Command 加空格，输入「终端」，回车。

装好之后敲 `pwd`。Windows 上显示 `/c/Users/你的名字`，Mac 上显示 `/Users/你的名字`，看到路径就对了。

## 自己试一下

### 找一个程序，看它在硬盘上的哪儿

你平时敲的 `ls`，其实是一个躺在硬盘上的文件。敲这句看看它在哪：

```
which ls
```

Windows 上输出大概是 `/usr/bin/ls`，Mac 上大概是 `/bin/ls`。

**这就是「装软件」的结果：一个文件被放进了某个目录。** 你敲 `ls` 的时候，系统就是去这个位置找这个文件，找到就运行它。

### 看看它有多大

```
ls -lh /usr/bin/ls
```

输出大概是这样：

```
-rwxr-xr-x  1 root  wheel   138K  9月 10 12:00 /usr/bin/ls
```

138K，一百多 KB。一个你天天用的程序，就这么大。

### 数一数你电脑上装了多少个这样的程序

```
ls /usr/bin | wc -l
```

输出的数字通常是几百到一千多。

你装的那些软件，就在这些目录里一个文件一个文件地堆着。它们加起来能占几百兆甚至几个 G。

### 看一眼它们一共占多大

```
du -sh /usr/bin
```

这个数字会让你对「装软件占多少空间」有个具体的概念。
