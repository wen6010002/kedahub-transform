# 脚本 · 精通版

计算机初识 · 第 7 站

时间：1 个半小时到 2 小时。其中读 25 分钟，动手 60 分钟，留 30 分钟给自己调试。  
做完你会有一个：敲一下就把下载文件夹整理干净的脚本。

---

## 先把环境弄好

**Windows 先装 Git Bash。** 这一站写的是 Bash 脚本，Windows 自带的命令提示符和 PowerShell 跑不了。

装法：搜「git 下载」，进官网，下 Windows 版，双击，一路点 Next。只有一处要注意：问你默认编辑器选什么的时候，选 VS Code 或者记事本，别选 Vim，新手不知道怎么退出。装完在开始菜单里搜 `Git Bash` 打开。

**Mac 不用装**，按 Command 加空格，输入「终端」，回车。

**再装一个写脚本用的编辑器。** 后面要反复打开、修改、保存脚本文件，用命令往文件里写内容只适合第一次。

搜「VS Code 下载」，它是免费的，以后写网页、写 Python 都能用。装完之后，在终端里敲 `code 文件名` 就能用它打开文件。装好敲 `code --version` 验证一下，看到版本号就对了。

不想装也行，用系统自带的记事本。但 Windows 记事本有个坑：保存的时候它会自动加 `.txt` 后缀，你的 `你好.sh` 会变成 `你好.sh.txt`。保存时把「保存类型」改成「所有文件」就不会了。

## 上一站你烦了

上一站最后那一步，是让你一条一条 `mv`，把下载文件夹里的东西搬进分类文件夹。搬到十几个的时候你开始烦了。

这个烦是这一站的入口。

因为「烦」背后是一个很具体的判断：这个动作我做了十几遍，而且长得一模一样。凡是长成这样的动作，电脑都能替你做。你只需要把做过的那十几条命令写下来，交给它。

写下来的那个文件，就叫脚本。

## 把命令装进一个文件

打开上一站建的 `练手` 文件夹，在里面建一个文件：

```
cd ~/练手
touch 打招呼.sh
```

用编辑器打开它（装了 VS Code 的话）：

```
code 打招呼.sh
```

没装 VS Code 就用记事本：

```
notepad 打招呼.sh
```

在里面敲两行：

```
#!/bin/bash
echo "我在写脚本"
```

存盘。VS Code 是 Ctrl 加 S（Mac 上是 Command 加 S），记事本是点「文件」里的保存。

现在试着跑一下：

```
./打招呼.sh
```

你大概率会看到一句报错：

```
bash: ./打招呼.sh: Permission denied
```

这个报错很重要，先说清楚它。

## 为什么它不让你跑

在 Linux 和 Mac 里，一个文件能不能被执行，是一件需要单独授权的事。

你 `touch` 出来的文件，默认只有「读」和「写」两个权利，没有「执行」。这是故意的设计。万一你从网上随便下了一个文件，它不会因为名字里有 `.sh` 就自动能跑。要跑，得你亲口说一声。

这一声是 `chmod`：

```
chmod +x 打招呼.sh
```

`chmod` 是 change mode，`+x` 是加上执行权限。敲完再跑一次：

```
./打招呼.sh
```

这次你会看到：

```
我在写脚本
```

恭喜，你写完了人生第一个脚本。虽然它只做了一件事。

顺便解释开头那两行。第一行 `#!/bin/bash` 有个外号叫 shebang，作用是告诉系统「用 bash 来执行这个文件」。你现在可能觉得它多余，但如果去掉它，脚本在某些系统上会以奇怪的方式失败，而且不报错，很难查。写脚本第一行就写它，不要省。

第二行的 `echo` 是「把后面这东西打印出来」。它是你以后调试脚本时用得最多的命令，因为脚本不会自己说话，你得让它把中间结果喊出来给你看。

## 让脚本记住东西

试试这个：

```
#!/bin/bash
name="小张"
echo "你好，$name"
```

跑出来是「你好，小张」。

`name="小张"` 这一行叫变量赋值，意思是「以后我说 name，指的就是小张」。用的时候在前面加一个 `$`，表示「取它的值」。

这里有三条规则，每条都会让你踩坑。

**第一，等号两边不能有空格。**

```
name="小张"    这样对
name = "小张"   这样错
```

第二种写法，Bash 会理解成「运行一个叫 name 的命令，参数是 `=` 和小张」，然后告诉你找不到这个命令。这个错你一定会犯，早点犯一次比晚点犯好。

**第二，变量名用英文。**

这条属于硬要求。Mac 自带的 bash 是 3.2 版，它不认中文变量名。你写 `下载=/tmp`，它会报：

```
bash: 下载=/tmp: No such file or directory
```

这个报错信息完全看不出真正的原因，你会以为是路径写错了，然后在那儿查半天。变量名一律用英文，变量里装的内容是中文没关系，注释和输出也都可以用中文。

**第三，取变量值的时候加双引号。**

```
echo "$name"    这样对
echo $name      这种写法以后会让你出事
```

原因在下面讲 `for` 循环的时候会说清楚。

## 让脚本自己看一遍所有文件

上一站你是一条一条搬文件。现在换一种写法：

```
#!/bin/bash
cd ~/练手
for f in *; do
  echo "这里有个东西叫 $f"
done
```

跑一下，它会把 `练手` 文件夹里的每个东西都念一遍。

这段的结构是固定的：

```
for 变量名 in 一堆东西; do
  对每个东西做的事
done
```

`for` 的意思是「把这堆东西里的每一个，轮流交给这个变量，然后执行中间那段」。中间那段写什么，它就做什么。刚才写的是打印，你可以换成任何命令。

`in` 后面那个 `*` 是通配符，代表「当前目录下的所有东西」。

把打印换成移动，就成了整理文件的核心：

```
for f in *; do
  mv "$f" 某个文件夹/
done
```

现在说清楚为什么要给 `$f` 加引号。假设有个文件叫 `我的 照片.png`，不加引号的时候，Bash 会先按空格把它拆成两段，你的脚本就收到了两个东西，然后试图移动两个不存在的文件。加上引号就不会拆。所以养成习惯，**所有变量都加双引号**，加了不会有坏处，不加迟早出事。

## 让脚本会判断

现在有个问题：所有文件都往同一个地方搬，那不叫整理。你得让脚本看一眼扩展名，再决定搬到哪。

先学会取扩展名。假设变量 `f` 的值是 `报告.pdf`，怎么拿到 `pdf`？

```
ext="${f##*.}"
```

`##*.` 的意思是「从左边开始，删掉最长的、以点结尾的部分」。翻译成人话：把最后一个点之前的东西全扔掉，剩下的就是扩展名。

这个写法看着怪，但它比调用别的程序快得多。先照抄，第 6 站会讲清楚它为什么长这样。

有了扩展名就能判断了：

```
if [ "$ext" = "pdf" ]; then
  echo "这是个 PDF"
elif [ "$ext" = "png" ]; then
  echo "这是张图"
else
  echo "不知道是什么"
fi
```

格式也是固定的：`if [ 条件 ]; then 做什么 elif [ 另一个条件 ]; then 做什么 else 都不满足做什么 fi`。末尾那个 `fi` 就是 `if` 倒过来写，表示结束。Bash 就是这么设计的。

方括号里面的空格不能省。`[ "$ext" = "pdf" ]` 是对的，`["$ext"="pdf"]` 是错的。

不过要判断七八种扩展名的话，写一长串 `elif` 太啰嗦。这种情况用 `case` 更合适：

```
case "$ext" in
  png|jpg|jpeg|gif|webp) target=图片 ;;
  pdf|doc|docx|txt|md)   target=文档 ;;
  zip|rar|7z)            target=压缩包 ;;
  dmg|exe|pkg)           target=安装包 ;;
  *)                     target=其他 ;;
esac
```

读法是：看扩展名，如果它是 `png` 或者 `jpg` 或者……，就把 `target` 设成图片。竖线是「或者」。最后那行 `*)` 是兜底，前面都没匹配上就走它。每个分支末尾的 `;;` 表示「这一支结束了」。

注意 `target` 的值写成中文完全没问题，中文只在变量名上有坑，在内容上没有。

## 现在把它拼起来

下面是完整版。不要直接抄，先自己写一遍，写不出来再看。

```
#!/bin/bash

# 要整理的文件夹。改这一行就能换地方。
DIR=~/Downloads

cd "$DIR" || { echo "进不去 $DIR"; exit 1; }

mkdir -p 图片 文档 压缩包 安装包 其他

count=0

for f in *; do
  [ -f "$f" ] || continue

  ext="${f##*.}"

  case "$ext" in
    png|jpg|jpeg|gif|webp) target=图片 ;;
    pdf|doc|docx|txt|md)   target=文档 ;;
    zip|rar|7z)            target=压缩包 ;;
    dmg|exe|pkg)           target=安装包 ;;
    *)                     target=其他 ;;
  esac

  if [ -e "$target/$f" ]; then
    echo "跳过，那边已经有同名的了：$f"
    continue
  fi

  mv "$f" "$target/"
  count=$((count + 1))
done

echo "整理完了，一共移动了 $count 个文件。"
```

下面几处容易出错，单独说一下。

`cd "$DIR" || { echo "进不去 $DIR"; exit 1; }` 的意思是「进这个目录，进不去就报一句然后退出」。`||` 读作「或者」，意思是前面失败了才执行后面。这一行很重要，因为如果 `cd` 失败了（比如你把下载文件夹改了名字），后面的 `mv` 就会在错误的目录里执行，后果不可控。

`[ -f "$f" ] || continue` 是「如果这不是一个普通文件，就跳过它，进入下一轮」。`-f` 判断是不是文件，`continue` 是「这一轮到此为止，跳到下一个」。不加这一行，脚本会尝试移动子文件夹，把刚建好的分类文件夹自己也搬走。

`if [ -e "$target/$f" ]` 是「如果目标位置已经有同名文件」。`-e` 判断这个东西存不存在。存在就跳过并说一声，不然 `mv` 会直接覆盖掉原来那个文件，而覆盖是没法撤销的。

`count=$((count + 1))` 是算术运算，`$(( ))` 里面可以写加减乘除。

## 跑之前先做两件事

**第一件，先在一个假的文件夹上试。** 别拿真的下载文件夹当第一次实验。在家目录建个 `试运行` 文件夹，随便放十几个不同类型的小文件进去，把脚本里的 `DIR=~/Downloads` 改成 `DIR=~/试运行`，跑一遍看效果。

**第二件，把 `mv` 先换成 `echo`。** 这样脚本只会打印「我准备把某某文件搬到某某地方」，不会真的动手。看完输出觉得对，再换回 `mv`。

这两件事叫干跑。以后你写任何会改动文件的脚本，都先干跑一遍。这个习惯能省掉你几次想砸电脑的下午。

## 卡住了看这里

**提示 `Permission denied`。** 忘了 `chmod +x`。加上就行。或者临时用 `bash 文件名` 跑，这样不需要执行权限。

**报错说变量赋值那一行「No such file or directory」。** 变量名用了中文。Mac 自带的 bash 3.2 不认中文变量名，改成英文就行。

**提示 `name: command not found`，可那明明是个变量。** 赋值的时候等号两边有空格了。改成紧贴着。

**脚本跑完了，什么都没发生。** 九成是路径问题。在脚本开头加一句 `pwd`，看看它到底在哪个目录里跑的。注意脚本里的相对路径是相对于「你运行它的位置」，不是相对于脚本文件的位置，这两个经常不是一回事。

**文件名里有空格就出错。** 变量没加引号。把 `$f` 改成 `"$f"`，全篇都改。

**文件被搬到了奇怪的地方。** 目标目录不存在，`mv` 就把它当成「改名」了，直接原地改了个名字。在移动之前先 `mkdir -p` 目标目录，养成习惯。

**中文变成乱码。** 文件编码不是 UTF-8。用 VS Code 打开，看右下角的编码，改成 UTF-8 再存。

**改了脚本但跑起来还是老样子。** 你改的可能是另一个同名文件。敲 `pwd` 和 `ls -l 脚本名` 确认一下，看看修改时间对不对。

## 走完之后

这一站和上一站的感觉很不一样。上一站你在跟电脑对话，这一站你在给它下指令，让它在你不在的时候自己干活。

判断自己对不对路子，问自己一个问题：写完这个脚本之后，你有没有开始想「还有哪些事可以这样搞掉」？

如果有，哪怕只是想到「每周整理一次照片」这种小事，那说明你身上有工程的那一面。后端开发、运维、测试开发，这三个岗位的日常就是把重复的事写成脚本，然后去写更多的脚本。

如果你觉得调试脚本很烦，改一次跑一次，半天搞不定一个空格，那也很正常。这部分确实枯燥。先别急着下结论，第 3 站（文件与目录）走完，去第 2 模块做网页，那边有立刻能看见的东西，说不定更对你胃口。
