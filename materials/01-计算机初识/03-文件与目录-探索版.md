## 你桌面上的东西，是怎么放着的

你电脑桌面上有一些图标，点两下就能打开一个软件。你建过文件夹，往里拖过几张照片。你下载过东西，知道它们大概在某个地方，但具体在哪说不清。

这两件事背后是同一套机制：**电脑里的所有东西都放在一棵树上，每个东西都有它的位置。**

你用鼠标点来点去，其实是在这棵树上走来走去，只不过那棵树被画成了窗口的样子，让你感觉不到。

下面看这棵树长什么样，怎么描述一个东西的位置，以及为什么有时候你明明看得见一个文件，却动不了它。

最后一类问题几乎每个用电脑的人都遇到过，但很少有人知道原因。

## 树是怎么回事

先看一个你已经见过的画面。

你打开「此电脑」或者「访达」，看到几个大类：桌面、文档、下载、图片。点进「文档」，里面是你自己建的文件夹。点进其中一个，里面是文件。

一层一层往下，这就是树。

那树的根在哪里？根就是最上面那一层，你看不到更上面了。在 Windows 上叫「此电脑」，在 Mac 上叫「Macintosh HD」，在 Linux 和服务器上，它就是一个斜杠：`/`。

从根往下走，经过哪些层，最后到那个文件，把这一路上每一层的名字写下来，用斜杠隔开，就是这个文件的**路径**。

比如：

```
/Users/zhangsan/Desktop/报告.pdf
```

读作：根目录下的 Users，Users 下的 zhangsan，zhangsan 下的 Desktop，Desktop 下的报告.pdf。

用鼠标的时候你不需要知道路径，因为文件夹是点出来的。但一旦离开图形界面，路径就是唯一能说清「这个东西在哪」的方式。你跟别人描述一个文件的位置，最后总得落到一串这样的东西上。

## 树上哪几个地方放着什么

这棵树有几层是系统自己安排的，不是你建的。认识一下，以后遇到问题能对上号。

在 Mac 和 Linux 上：

`/Users`（Linux 上是 `/home`）是每个用户自己的地盘。你的桌面、文档、下载都在这里面。

`/etc` 放各种软件的设置。你以后改配置，多半是改这里的文件。

`/var` 放会不断变大的东西。日志在这里，缓存也在这附近。单独分出来是因为这类东西会把硬盘撑满，放在一起方便清理。

`/usr` 放你装的大部分软件。

`/tmp` 放临时文件。重启可能就清空了，所以别往里放重要的东西。

Windows 上结构不太一样，它有 `C:\` 这样的盘符，但「一层套一层」这件事是一样的。

这套安排有个正式名字叫文件系统层级标准。它存在的意义很实际：**换一台电脑，你照样知道设置在哪里、日志在哪里。** 这是你换机器时唯一能指望的东西。

## 为什么有的文件你打不开

现在讲开头说的那类问题。

同一台电脑上，文件是有主的。每个文件都记着三件事：**它是谁的、谁能看它、谁能改它。**

为什么要记这些？因为一台电脑不只你一个人用。同一个实验室、同一个公司的几个人可能共用一台机器，或者共用一套代码。张三的文件，李四不能随便看，更不能随便改。

规矩的内容是：把所有人分成三类（文件的主人、主人所在的小组、其他所有人），然后对每一类分别设置三种许可（能不能看、能不能改、能不能运行）。

合起来九种组合。你在文件属性里看到的那一排勾选，就是这九种。

现在说你遇到的情况。最常见的一种是：**文件明明是你的，你也看得见，但就是打不开、改不了、删不掉。**

原因通常不在这个文件本身，而在它**上面那一层**。

在 Mac 和 Linux 上，文件夹有一个容易被忽略的规则：一个文件夹除了「能不能看里面的东西」，还有一个单独的「能不能进去」。你能看见里面有啥，但没有「进去」的许可，那里面所有东西你都碰不到，哪怕每个文件的许可都开着。

所以那个让人抓狂的现象就有了答案：文件的许可没问题，是它所在的那个文件夹，你没被允许进去。

另一种情况是你想改一个系统的东西，但你不是管理员。系统把这些东西锁起来，是为了防止误操作把电脑搞坏。这时候需要管理员身份。

## 为什么「改成所有人可读写」是个坏建议

遇到打不开、改不了的情况，网上最常见的建议是「把权限改成所有人可读写」。

它确实能解决问题。但它同时也把这道门整个拆掉了：这台电脑上任何人都能改这个文件。

如果这只是一张你自己的照片，问题不大。但如果这是一个正在跑的服务，或者一个存放密码的文件，那这个改动就留下了隐患。

更好的做法是先搞清楚是谁没有许可，然后只给那一个身份加上，而不是给所有人开门。

还有一条更要小心的建议：**不要对系统目录用「递归」的方式改权限。** 递归的意思是「这个文件夹和它下面所有东西一起改」。在系统目录上用它，可能让电脑起不来。你以后会看到 `-R` 这个字母，它就是这个意思。

## 一个文件出现在两个地方

树有个绕不开的代价：**一个东西只能待在一个位置。**

你有一份资料，既属于「课程」，又属于「项目」。在树里你只能把它放在其中一个下面。想让它出现在两个地方，就得复制一份，然后两份会慢慢变得不一样，你不知道哪份是最新的。

这个问题困扰了文件系统几十年。有个折中的办法叫**链接**。

链接像是一个指路牌。它本身几乎不占地方，里面只写着「真正的东西在哪」。你打开它，系统替你跳到那个真正的东西上去。真正的东西被删了，这个指路牌就失效了。

这个想法在后面到处都会出现。数据库里有外键，编程里有引用，网页上有超链接，说的都是同一件事：不复制一份，只指向它。

## 树之外还有什么

树形结构统治了五十多年，但它不是唯一的答案。现在很多地方在用别的方式组织数据。

**云盘和图片服务**大多不用文件夹。你存进去一个东西，它给你一个很长的地址，找东西靠搜索或者标签。好处是可以无限扩容，坏处是没有「一层一层」这个概念了。

**数据库**里的数据也存在硬盘上，但你看不到文件。数据库自己管存储，因为它要处理的查询方式和「打开一个文件」完全不同。

**标签**越来越流行。你给一张照片打上「旅行」「2025」「海边」三个标签，想找的时候搜。这解决了「一个东西只能在一个地方」的老问题。

**容器**是现在部署程序常用的方式，它把程序和一个完整的文件系统打包在一起。同一台机器上可以跑几十个互相看不见的文件系统。

这些不是来取代文件系统的，它们跟文件系统管的是不同的事。但知道它们存在，你就不会以为「电脑里的东西只能这么放」。

## 权限的问题，怎么问 AI
打不开、改不了这类问题，现在可以让 AI 帮你解决。但问法很重要。

**不要直接问「怎么解决权限不够」。** 这么问，你多半会得到「改成所有人可读写」或者「用管理员身份运行」这两个答案。问题看起来解决了，但可能留了坑。

**要说清情况再问原因。** 告诉它：你想做什么、操作的是哪个文件或文件夹、报错原文是什么。然后问「是什么原因导致的，有没有范围更小的办法」。

几个你以后会经常看到的词，认识一下：

**权限**就是前面说的那套许可。

**管理员身份**是「以最高权限执行」的意思。Windows 上右键菜单里的「以管理员身份运行」，Mac 和 Linux 上的 `sudo`，都是这个东西。

**递归**是「连同它下面的所有东西一起处理」。看到这个词要格外小心。

一条简单的原则：**遇到权限问题，先问「是谁没有许可」，别急着「给所有人开门」。**

## 先把东西装上

下面要在「终端」里敲命令。终端就是那个黑窗口，你打一行字，电脑照着做。

### Windows

Windows 自带的「命令提示符」和 PowerShell 用不了这一站的命令，敲了会报错。要先装一个 Git Bash，它给你一套和 Mac 一样的命令行环境。

1. 打开浏览器，搜「git 下载」，第一个就是官网
2. 下载 Windows 版，安装包大概六十兆，下完双击打开
3. 一路点「Next」。中间会问你一堆问题，全部用默认选项就行
4. 只有一处要注意：问你默认编辑器（Default editor）选什么的时候，别选 Vim。Vim 是给熟手用的，新手进去不知道怎么退出来。选「Use Notepad as Git's default editor」，或者列表里的 VS Code
5. 装完，在开始菜单里搜 `Git Bash`，点开它

还有一个更快的打开方式：在任意文件夹里点右键，菜单里有一项「Open Git Bash here」，点它就在那个文件夹里直接打开了。

### Mac

Mac 不用装。按 Command 加空格，输入「终端」，回车。

### 确认装好了

打开 Git Bash（Mac 就是终端），敲：

```
pwd
```

Windows 上会显示 `/c/Users/你的名字`，Mac 上会显示 `/Users/你的名字`。看到路径就对了。

Windows 上如果提示「不是内部或外部命令」，说明你打开的是系统的命令提示符，不是 Git Bash，回去重新打开。

## 自己试一下

### 一次建三层文件夹

```
cd ~
mkdir -p 练习/课程/笔记
cd 练习/课程/笔记
pwd
```

`mkdir -p` 的意思是「把路径上缺的文件夹都建出来」。一条命令建了三层。

打开你的文件管理器进到个人文件夹，你会看到「练习」出现在那儿。点进去一层层展开，最里面是「笔记」。

### 看看你电脑上的权限长什么样

```
cd ~
ls -l
```

每行开头那一串像 `-rw-r--r--` 或者 `drwxr-xr-x` 的东西就是权限。开头是 `d` 的是文件夹，是 `-` 的是普通文件。

后面九个字符分三组，每组三个。第一组是文件主人能干什么，第二组是同组的人，第三组是其他人。`r` 是能看，`w` 是能改，`x` 是能执行（对文件夹来说是能进去）。

### 造一个连自己都打不开的文件

```
cd ~/练习
echo "测试" > 试试权限.txt
chmod 000 试试权限.txt
cat 试试权限.txt
```

`chmod 000` 是「把三种人的三种权限全部去掉」。`cat` 想读它，屏幕上会跳出：

```
cat: 试试权限.txt: Permission denied
```

这就是你在网上教程里总看到的那个报错。系统在按规矩办事，它没有坏。

改回来：

```
chmod 644 试试权限.txt
cat 试试权限.txt
```

现在能读了，屏幕上出现「测试」。

---

`mkdir -p` 建多层文件夹，`cd` 走进去，`ls -l` 看权限，`chmod` 改权限。剩下的都是这些的变体。
