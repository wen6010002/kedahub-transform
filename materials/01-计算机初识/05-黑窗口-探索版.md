# 黑窗口 · 探索版

计算机初识 · 第 5 站

时间：1 小时左右。读 35 分钟，自己敲 25 分钟。

---

## 先看一眼别人在干什么

如果你走进一家互联网公司，随便看几个程序员面前的屏幕，大概率是同一个画面：上面开着三四个黑色的窗口。

每个窗口里都在刷字。有的在滚日志，一行接一行往上跑。有的停在某一行不动，等着他敲什么。他会时不时切到某个窗口，敲一串你看不懂的字符，回车，然后盯着输出看几秒，再敲下一串。

这些窗口在他那儿一直开着，一天都不关。他上班第一件事是打开它们，下班前最后一件事也是它们。

这个东西叫终端，也叫命令行。大一新生第一次见到它，普遍的反应是「这什么年代的东西，为什么不用鼠标」。

下面看它能干什么、为什么快、什么情况下比鼠标好用，以及它不擅长什么。不用背命令，也不用学会用它干活。

## 那个黑框到底是什么

先拆一个常见的混淆。终端、Shell、命令行，这三个词经常被混着用，其实是三样东西。

**终端**是你看到的那个窗口本身。它负责显示文字、接收你的键盘输入。Mac 上叫「终端」，Windows 上你要装的那个叫 Git Bash。

**Shell** 是跑在终端里的那个程序。它负责听懂你敲的东西，然后去找对应的程序执行。你在用哪个 Shell，敲 `echo $SHELL` 就能看到。常见的有 bash、zsh、fish。

**命令行**是你敲的那一行字。它是一个完整的指令，按回车才算数。

所以那句「你会用命令行吗」，准确的说法应该是「你会在终端里跟 Shell 打交道吗」。

三者里真正有分量的是 Shell。它本身不干任何活，不列文件、不算数、不联网。它只做两件事：找程序，把程序接起来。

## 它能干的六类事

不列功能清单，直接看例子。

### 一、在一堆文件里找东西

假设你在做一个项目，代码分散在三百个文件里。你想知道「这个函数到底在哪些文件里被调用过」。

用鼠标的话，你得一个个文件打开，用查找功能搜，三百个文件搜到天黑。

在终端里是一句话：

```
grep -rn "函数名" .
```

意思是「从当前目录开始，递归地搜所有文件，把含有这个词的行挑出来，并且告诉我行号」。

几秒钟，结果出来了。这类「在大量文本里定位」的活，命令行比鼠标快几个数量级，而且结果是可以复制的。

### 二、批量干活

你手机拍了两千张照片，全都堆在一个文件夹里，名字是 `IMG_0001.jpg` 这种。你想按拍摄日期分到不同的文件夹里。

鼠标做不到这件事。因为「读取拍摄日期」这个动作，文件管理器不提供。

终端里可以。因为照片的拍摄日期存在文件内部，有一个专门的程序能把它读出来，还有一个程序能按这个信息改文件名，第三个程序能按日期建文件夹。三个程序接起来，两千张照片分好，几秒钟。

这类「同一个动作重复几千遍」的活，是命令行的主场。

### 三、操作你看不见的电脑

你的网站部署在一台机房里，或者云上。那台机器没有屏幕，没有鼠标，你摸不到它。

但它有 Shell。

你在自己电脑的终端里敲一句 `ssh 用户名@服务器地址`，接下来的事就像你坐到了那台机器前面。你敲的每个命令，都在那边执行。

这是所有服务器管理的基础。你在网页上点一下「重启」，背后就是有人写好的命令在服务器上跑。

### 四、装东西、跑东西

开发环境里的大部分工具，装的时候都是一句话。

装完了怎么用？也多半是敲命令。跑一个程序、启动一个服务、跑一遍测试、编译一遍代码，都是在终端里完成。

图形界面的软件也有，但很多专业工具只有命令行版本，因为它们的用户就是开发者，做一个界面反而多余。

### 五、看日志、查问题

程序出问题的时候，它会把过程写进日志文件。日志文件动辄几百兆，几百万行。

你想知道「昨天下午三点前后，哪些请求失败了」。

在终端里：

```
grep "2026-09-13 15:" 日志文件 | grep "失败" | wc -l
```

三段接起来：挑出那个时间段的行，再挑出其中带「失败」的，最后数一下有几条。

几百万行里定位到几十条，几秒钟。这是排查线上问题的基本动作。

### 六、把工具接起来

上面几个例子都出现了同一件事：**一个程序的输出，直接喂给下一个程序。**

这个能力叫管道，用一根竖线表示。它是 Shell 最核心的设计。

它的意义在于：每个程序只需要把一件小事做好，不用管别人怎么用。你想完成一件复杂的事，就把几个小工具串起来。而这些工具之间谁都不认识谁，是临时被你拼在一起的。

这解释了为什么终端里的工具都长得很简陋，只管一个功能，连个好看的界面都没有。因为界面不是它们的活。

## 一个真实的下午

讲个具体场景，你感受一下这些能力是怎么合起来用的。

下午三点，一个工程师收到告警：网站的注册接口变慢了，从平均 200 毫秒涨到了 3 秒。

他做的第一件事是连上服务器：

```
ssh 服务器地址
```

第二件事是看服务器现在忙不忙：

```
top
```

屏幕上跳出实时数据。CPU 用了 90%，是平时的三倍。往下看，占 CPU 最多的那个进程是数据库。

第三件事是去看数据库在忙什么。他连上数据库，敲一句查询当前正在执行的语句，发现有一张表正在被反复全表扫描，而那张表有八百万行。

第四件事是查这张表怎么突然变慢了。他去看最近的改动，发现两个小时前有一次上线，加了一个新的查询条件，而那个条件对应的字段没有索引。

到这里原因清楚了：新上线的功能每次查询都要扫全表，用户一多，数据库就顶不住了。

第五件事，加索引，验证，恢复正常。从收到告警到解决，十几分钟。

这整个过程，鼠标做不了。这里的问题不在快慢，是压根没有对应的界面。**服务器上没有屏幕，你唯一的入口就是那个黑框。**

## 它不擅长什么

说了这么多好处，得说清楚它的边界，不然你会用错地方。

**看图的活它干不了。** 终端里的一切都是文字。你要看一张设计稿、调一个图片的颜色、拖动一下页面上的元素，都得回到图形界面。前端开发里最花时间的部分，恰好都是图形界面的活。

**需要「看见才能判断」的活它干不了。** 比如你调一个页面的间距，得看着效果改，改一下看一眼。这种活终端帮不上忙。

**探索性的活它不占优势。** 你想知道一个陌生的文件夹里都有什么、哪些文件大、结构长什么样，用鼠标点两下更快。终端里 `ls` 出来的是一串名字，你脑子里得自己拼出结构。

**命令本身不好记。** 常用的几十条，用一个月就熟了。但那些一年用两次的，每次都得查。这不是你记性差，所有人都这样，包括写了十年的人。

**它不会拦着你。** 鼠标操作里，删除会进回收站，覆盖会弹窗确认。终端里没有这些。你敲了删，它就删，不问你第二遍。这是它最需要小心的地方，下面单独讲。

## 不会敲命令，让 AI 帮你写
假设你完全不懂命令行，但你有一个需求：把下载文件夹里所有 PDF 挑出来，按月份分到子文件夹里。

三年前，你得先学会这门手艺才能做这件事。现在不用了。你把需求描述给 AI，它给你一段命令，你复制粘贴到终端里跑。

**这个变化很大。** 它意味着命令行的门槛从「你得会写」降到了「你得会判断」。

判断什么？三件事，每次跑之前都要看一遍：

**第一，它会不会删东西。** 命令里出现 `rm`、`mv`、`> `（重定向覆盖）、`truncate` 这些词，都要停下来看清楚。删的是哪些文件，删到哪里去。

**第二，它会不会覆盖已有的东西。** `>` 是覆盖写，`mv` 遇到同名文件默认也是覆盖。问问自己：如果目标位置已经有东西了，会发生什么。

**第三，它作用在哪个目录。** 命令里的相对路径是相对于「你现在站的位置」。如果 AI 给你的命令里有一堆 `*.jpg`，而你恰好站在一个重要的文件夹里，那这个 `*` 展开的就是这个文件夹里的所有东西。

再补一句更实际的：**让 AI 给你的命令先跑一个「干跑」版本。** 就是把真正动手的那句（比如 `mv`）先换成 `echo`，它只会打印「我准备做什么」，不会真的动手。看完输出觉得对，再换成真的。

这个习惯能救你很多次。

## 认识几条危险命令

不用背，但要认识。看到这几条的时候，停一下。

**`rm -rf 目录`** 删除目录及其下所有内容，不确认，不进回收站。这个组合最出名的一次事故是有人敲了 `rm -rf /`，把整个系统删了。那个空格是关键，`/` 是根目录。

**`> 文件`** 用空内容覆盖文件。如果你打错了文件名，正好覆盖掉一个重要文件，它是不可恢复的。

**`mv 文件 已存在的目录/`** 如果那边有同名文件，会被直接覆盖。

**`chmod -R 777 目录`** 把目录及其下所有东西的权限开成所有人都能读写执行。很多网上教程会教你这么干来解决权限问题。它能解决问题，但同时也把安全边界全拆了。看到这个，先想想有没有别的办法。

**`sudo` 开头的命令** 是以管理员身份执行。系统目录里的东西被改坏了，电脑可能起不来。新手阶段，看到自己写的命令里有 `sudo`，先停下来问问。

## 先把东西装上

下面要在「终端」里敲命令。终端就是那个黑窗口，你打一行字，电脑照着做。

### Windows

Windows 自带的「命令提示符」和 PowerShell 用不了这一站的命令，敲了会报错。要先装一个 Git Bash，它给你一套和 Mac 一样的命令行环境。

1. 打开浏览器，搜「git 下载」，第一个就是官网
2. 下载 Windows 版，安装包大概六十兆，下完双击打开
3. 一路点「Next」。中间会问你一堆问题，全部用默认选项就行
4. 只有一处要注意：问你默认编辑器（Default editor）选什么的时候，别选 Vim。Vim 是给熟手用的，新手进去不知道怎么退出来。选「Use Notepad as Git's default editor」，或者列表里的 VS Code
5. 装完，在开始菜单里搜 `Git Bash`，点开它

还有一个更快的打开方式：在任意文件夹里点右键，菜单里有一项「Open Git Bash here」，点它就在那个文件夹里直接打开了。

### Mac

Mac 不用装。按 Command 加空格，输入「终端」，回车。

### 确认装好了

打开 Git Bash（Mac 就是终端），敲：

```
pwd
```

Windows 上会显示 `/c/Users/你的名字`，Mac 上会显示 `/Users/你的名字`。看到路径就对了。

Windows 上如果提示「不是内部或外部命令」，说明你打开的是系统的命令提示符，不是 Git Bash，回去重新打开。

## 自己试一下

### 先看你在哪

```
pwd
```

它会回你一个路径。Windows 上大概是 `/c/Users/你的名字`，Mac 上大概是 `/Users/你的名字`。这就是你现在站的位置。

### 看看这儿有什么

```
ls
```

屏幕上列出一串名字，这就是你个人文件夹里的东西。跟你在文件管理器里看到的是同一批。

### 让电脑建个文件夹

```
mkdir 我的第一个文件夹
```

敲完先别急着敲下一条。**打开你的文件管理器，进到个人文件夹，你会看到「我的第一个文件夹」真的出现在那儿了。**

这一步别跳过。你在黑窗口里打了一行字，图形界面里多了一个文件夹出来。这两个东西操作的是同一台电脑，你刚才干的事和你右键新建文件夹是一回事。

### 走进去

```
cd 我的第一个文件夹
pwd
```

`cd` 是走进去。`pwd` 再看一眼，路径变了，说明你真的进去了。

### 写个文件

```
echo "这是我用命令行写的第一行字" > 笔记.txt
```

再用编辑器打开看看：Windows 上敲 `notepad 笔记.txt`，Mac 上敲 `open 笔记.txt`。你会看到那句话躺在文件里。

### 退出来

```
cd ..
```

`..` 是上一级，回到刚才那个文件夹。

---

刚才这几条命令就是黑窗口的核心：`pwd` 看你在哪，`ls` 看有什么，`cd` 走进走出，`mkdir` 建文件夹，`echo` 往文件里写东西。剩下的命令都是这些的变体。

不用背。这一站只要让你知道一件事：这个窗口不吓人，它就是在等你说一句它能听懂的话。
