## 先把东西装上

**Windows 用户先装 Git Bash。** 这一站的命令在 Windows 自带的命令提示符和 PowerShell 里跑不了。

1. 打开浏览器搜「git 下载」，第一个就是官网
2. 下载 Windows 版，双击安装，一路点「Next」用默认选项。问你默认编辑器选什么的时候别选 Vim，新手不知道怎么退出来
3. 装完在开始菜单里搜 `Git Bash` 打开

**Mac 不用装**，按 Command 加空格，输入「终端」，回车。

装好之后敲 `pwd`。Windows 上显示 `/c/Users/你的名字`，Mac 上显示 `/Users/你的名字`，看到路径就对了。

## 你一直在用它，只是没细想过

前两站你敲的每一条命令，都是通过一个叫 Shell 的东西完成的。

Shell 本身什么都不干。它不列文件、不改文件、不算数。它只做两件事：**找程序，把程序接起来。**

你敲 `ls`，它就去一堆目录里挨个翻，找到一个叫 `ls` 的程序，把它跑起来，把结果接回来显示给你。你敲一个不存在的命令，它翻遍了也没找到，于是告诉你找不到。

这个「接起来」的能力，才是 Shell 存在的理由。下面从一根竖线开始讲。

## 一根竖线

上一站你用过一次这个：

```
ls ~/Downloads | wc -l
```

那根竖线叫管道。它做的事很朴素：把左边命令吐出来的东西，塞进右边命令的嘴里。

单看这句还是抽象，换个具体的。你想知道下载文件夹里有多少张图片：

```
ls ~/Downloads | grep png
```

`grep` 是「从一堆文字里挑出含有某个词的行」。整句的意思是：先列出下载文件夹里的东西，再从这些名字里挑出带 `png` 的。

再加一层：

```
ls ~/Downloads | grep png | wc -l
```

三个程序串在一起：列出来，挑出 png，数一下有几个。

这就是 Shell 最核心的想法。每个程序只干一件小事，谁也不认识谁，用竖线串起来就能干成一件大事。以后你看到一条很长的命令，不要被吓到，从左往右拆，一段一段读，每段都在干一件小事。

## 输出还能存下来

竖线是把输出递给下一个程序。如果想存进文件呢？

```
ls -la > 文件列表.txt
```

`>` 叫重定向，把左边的输出写进右边的文件。

这里有个坑：`>` 是覆盖写。如果 `文件列表.txt` 里原来有内容，会被清空。想追加，用两个：

```
ls -la >> 文件列表.txt
```

还有反向的，从文件读进来：

```
wc -l < 文件列表.txt
```

## 错误信息走的是另一条道

试一句会报错的：

```
ls 不存在的文件夹 > 结果.txt
```

你会发现屏幕上照样出现了错误信息，而 `结果.txt` 里是空的。因为错误信息默认不走 `>`，它走另一条通道，叫标准错误。

两条道可以合并到一条：

```
ls 不存在的文件夹 > 结果.txt 2>&1
```

`2>&1` 的意思是「把 2 号通道接到 1 号通道上」。数字的含义现在不用记，记住这个写法就行，以后看到它知道是在把错误也一起接走。

## 为什么你敲 ls 就能找到 ls

你敲一个词，电脑怎么知道那个词对应的是哪个程序？

答案是它去一个列表里挨个目录翻。那个列表叫 PATH：

```
echo $PATH
```

会输出一长串用冒号隔开的路径，大概是这样：

```
/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin
```

Shell 就按这个顺序，一个一个目录翻，找到第一个叫 `ls` 的程序就用它。

这解释了一个你以后一定会遇到的问题：**装了新工具，敲命令却提示找不到。** 九成是因为它装到了 PATH 里没有的目录。

把那个目录加进去就行：

```
export PATH="$PATH:/新工具所在的目录"
```

这样加只在当前这个窗口有效，关掉就没了。要永久生效得写进配置文件，下面讲。

## 让终端记住你的习惯

每打开一个新终端，Shell 会先读一个文件，把里面的设置跑一遍。这个文件就是你的配置文件。

Mac 上默认用 zsh，配置文件是 `~/.zshrc`。
Linux 上一般用 bash，配置文件是 `~/.bashrc`。

先看一眼里面有什么：

```
cat ~/.zshrc
```

（用 bash 的话换成 `~/.bashrc`。不确定自己在用哪个，敲 `echo $SHELL`。）

现在往里面加一个别名。别名就是给一条长命令起个短名字：

```
echo 'alias ll="ls -lah"' >> ~/.zshrc
source ~/.zshrc
```

第一行把内容追加进配置文件，第二行让它立刻生效，不用重开窗口。现在敲 `ll` 试试，它等于 `ls -lah`。

`source` 这个命令值得记住。以后你每次改了配置文件，都要 source 一下才生效，否则会以为自己改错了。

## 两件趁手的工具

**grep，在一堆文字里找东西。**

```
grep "关键字" 文件名
```

加 `-r` 可以搜整个目录，加 `-n` 会告诉你结果在第几行：

```
grep -rn "TODO" ~/练手
```

这条命令的意思是：在 `练手` 文件夹里递归地搜，把所有含 `TODO` 的行挑出来，并且标上行号。以后你在一堆文件里找「这个词我到底在哪儿写过」，就是它。

**find，按名字找文件。**

```
find . -name "*.txt"
```

`.` 是「从当前目录开始」。`-name` 后面跟你要找的名字，支持通配符。

这两个跟管道接起来能干很多事。比如找出所有 Python 文件，按行数从少到多排：

```
find . -name "*.py" | xargs wc -l | sort -n
```

`xargs` 的作用是「把前面吐出来的东西，一个一个当作参数交给后面」。`sort -n` 是按数字排序。

这条命令你不用背。你现在要做的是能看懂它的结构：三段，每段干一件小事，中间用竖线接起来。

## 动手任务

一、**看看自己有多少个文件。** 敲 `ls -la | wc -l`，说出这个数字是什么。再敲 `history | grep cd | tail -5`，看你最近 `cd` 去过哪几个地方。

二、**用一次重定向。** 敲 `ls -la > /tmp/文件列表.txt`，然后用 `cat /tmp/文件列表.txt` 看结果。再敲一次 `ls -la >> /tmp/文件列表.txt`，看文件是不是变长了一倍。这一步是为了让你亲眼看懂 `>` 和 `>>` 的区别。

三、**看你的 PATH。** 敲 `echo $PATH`。随便挑一个目录，用 `ls` 进去看看里面装了什么程序。

四、**加两个别名。** 除了 `ll`，再想一个你自己常用的。比如 `alias ..='cd ..'`。

五、**用 grep 搜一次你自己的东西。** 挑一个你写过的文件夹，用 `grep -rn` 搜一个词。

六、**写这一站的正式产出。**

## 正式产出

**产出 A：一个用着舒服的终端。**

不用好看，但要做到三件事：敲 `ll` 能列出详细信息；提示符能看出你在哪个目录、在哪个 Git 分支；打开终端不报错。

第三条听着像废话，但新手改配置文件最容易搞出的就是「终端一打开就刷一屏错误」。改之前先把原文件复制一份，改坏了能退回来。

**产出 B：一条你自己的搜索命令。**

要求能一次搜遍整个文件夹的所有文本内容，并且告诉你结果在第几行。提示在 `grep -rn` 那里。

写完把它做成别名或者一个脚本，起一个你自己记得住的名字。做完在群里发一下，这是你第一次「配环境」，以后每换一台电脑都要重做一遍，值得认真对待。

## 卡住了看这里

**改了配置文件，重启终端没生效。** 先 `source` 一下。还不行就 `echo $SHELL` 确认你改的是不是对的那个文件，zsh 改 `.bashrc` 是不会生效的。

**改完配置文件，终端一打开就报错。** 配置里有语法错误。别慌，终端还能用。把最后改的那几行注释掉（行首加 `#`），再逐行打开，找到出错的那一行。

**提示 `command not found`，但明明装了。** `echo $PATH` 看有哪些目录，把新工具所在的目录加进去。记得要写进配置文件，`export` 只在当前窗口有效。

**管道右边没收到东西。** 左边那个程序报错了，或者它的输出走了错误通道。加 `2>&1` 把错误也接过去。

**`>` 用错把文件清空了。** `>` 是覆盖，`>>` 是追加。养成习惯：写文件之前先 `ls` 看一眼目标存不存在。

**别名不生效。** 别名只在当前 Shell 有效。写进配置文件，然后 `source` 一次。

**`Ctrl + Z` 之后程序好像卡住了。** 它被挂起了，没结束。敲 `fg` 让它回到前台，或者敲 `jobs` 看有哪些挂起的任务。

这一站比前两站抽象：前面是「怎么做」，这里是「为什么这样做」。抽象的东西不容易有感觉，判断的方法也要换一个。

问自己：刚才看那些命令的时候，你是觉得「哦，原来是这么回事」，还是觉得「这些符号好烦，反正能搜」？

如果是前者，你会很自然地开始琢磨「这两个命令能不能接起来」。后端开发、运维、SRE 这三个岗位，核心工作就是在命令行里把东西拼起来，这种琢磨的欲望就是入门的信号。
