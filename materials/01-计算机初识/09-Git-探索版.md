## 一个项目被改了几千次

网上有个地方叫 GitHub，全世界的程序员把代码放在那儿，谁都能看。

随便点开一个项目，里面有个地方列着这个项目的每一次修改。大的项目有几千条，每条都记着改了什么、谁改的、什么时候。点开一条，能看到具体改了哪几行。点开一个文件，能看到它从建出来到现在的完整变化。

做这件事的工具叫 Git。全世界的程序员都在用它。

## Git 到底在干什么

你有一个文件夹，里面是你正在写的东西。每次改完一些内容，你告诉 Git「记一下」，它就把文件夹里所有文件当时的样子存一份。

存下来的每一份叫一个**提交**。每个提交带着三样东西：文件内容、谁存的、你写的一句说明。

所有提交按时间排成一条线，就是你的**项目历史**。想回到哪个时刻，就回到哪个时刻。

## 先把东西装上

**Windows**

1. 打开浏览器，搜「git 下载」，第一个就是官网
2. 下载 Windows 版，安装包大概六十兆，下完双击打开
3. 一路点「Next」。中间会问你一堆问题，全部用默认选项就行
4. 只有一处要注意：问你默认编辑器（Default editor）选什么的时候，别选 Vim。Vim 是给熟手用的，新手进去不知道怎么退出来。选「Use Notepad as Git's default editor」，或者列表里的 VS Code
5. 装完，在开始菜单里搜 `Git Bash`，点开它

还有一个更快的打开方式：在任意文件夹里点右键，菜单里有一项「Open Git Bash here」，点它就在那个文件夹里直接打开了。

**以后就用 Git Bash，别用系统的命令提示符和 PowerShell。** 网上几乎所有教程讲的都是 Linux 风格的命令，在 Git Bash 里能直接照做。

**Mac**

Mac 一般自带 Git。按 Command 加空格，输入「终端」，打开，敲：

```
git --version
```

如果显示版本号，说明有，跳到下一步。如果弹出一个小窗口让你安装「命令行开发者工具」，点安装，等它装完。

### 确认装好了

Windows 在开始菜单里搜 `Git Bash` 打开，Mac 用终端。敲：

```
git --version
```

看到类似 `git version 2.43.0` 这样的输出就成功了。看到「不是内部或外部命令」或者 `command not found`，说明没装好，回去重装一遍。

## 自己试一下

**建一个练习用的仓库。** 敲这几行（`&&` 是「前面成功了再执行后面」，可以一行写多条）：

```
mkdir ~/练手 && cd ~/练手
mkdir 试试 && cd 试试
git init
git branch -m main
```

`git init` 会输出一句「已初始化空的 Git 仓库」，意思是 Git 在这个文件夹里建好了仓库。你的全部历史都存在里面一个叫 `.git` 的隐藏目录里。

最后那行是把主分支改名叫 `main`。Git 老版本默认叫 `master`，GitHub 现在用 `main`，改成一样以后不容易混。

**提交第一次。** 建个文件：

```
echo "第一行" > 笔记.txt
git add 笔记.txt
git commit -m "写下第一行"
```

三行的意思分别是：把「第一行」写进一个叫 `笔记.txt` 的文件、告诉 Git 要管这个文件、把它存进历史。最后那句引号里的话是这次提交的说明。

**再改一次，提交第二次。**

```
echo "第二行" >> 笔记.txt
git add 笔记.txt
git commit -m "加上第二行"
```

注意这次是两个大于号 `>>`，意思是追加到文件末尾，不会覆盖原来的内容。

**看看历史。**

```
git log --oneline
```

```
ac27b8f (HEAD -> main) 加上第二行
1dfe8a0 写下第一行
```

两次提交都在里面，最近的在最上面。前面那串字符是提交的编号，你敲出来的会不一样。

**现在回到过去。** 把第一次提交的编号复制下来（上面例子里是 `1dfe8a0`，你的是别的），敲：

```
git checkout 1dfe8a0
cat 笔记.txt
```

屏幕上只剩「第一行」，「第二行」不见了。**你的文件真的回到了那一刻。**

看够了回来：

```
git checkout main
cat 笔记.txt
```

两行都回来了。

刚才这几条命令就是 Git 的核心：`init` 建仓库，`add` 挑出要提交的东西，`commit` 存下来，`log` 看历史，`checkout` 回到某个时刻。剩下的命令都是这五条的变体。

## 它解决什么

**敢改。** 刚才你试过回到过去了。有了这个能力，你改东西的心态会变，从反复确认变成先试试，坏了再说。写代码本来就是不断试错。

没有 Git 的时候，大部分人靠复制文件备份，于是文件夹里出现这些名字：

```
项目
项目_备份
项目_最终
项目_最终_真的最终
```

三个星期后你有二十个文件夹，没人知道哪个是哪天的。

**能一起做。** 两个人改同一个项目，怎么知道谁改了什么？没有工具只能靠喊，人一多就乱。Git 把「谁在什么时候为什么改了什么」变成能查的记录。

这带来一个更重要的东西：代码审查。想往一个项目里加东西，先提一个请求，别人能看到你改的每一行，逐行评论，要求你改，改到满意才合并进去。

## 分支是什么

这是 Git 里最有用的功能，但名字起得不好，听着很抽象。

想一个具体的场景。你写了一份文档，现在想试试换个完全不同的写法。但你不确定新的写法好不好，也不想把现在这版改乱。

一个办法是先复制一份，改复制的那份。改得好就替换回来，改得不好就删掉。

分支做的就是这件事，但它不复制文件。它只是记下「从这里分出去一条新的线」。你在这条线上改东西、提交，主线上的文件一个都没动。

等你在新线上做完了，觉得可以，就把它合回主线。觉得不行，把这条线删掉，主线还是原样。

为什么不用复制文件的办法？因为复制出来两份会慢慢变得不一样，你也记不清哪个是最新的。分支和主线共享同一份历史，只是往前走的路不一样，合起来的时候 Git 知道两边各改了什么。

所以分支真正的价值是：你可以放心大胆地试，试错不要成本。

刚才那个练习里其实已经用过一次了。`git log` 输出里那个 `HEAD -> main` 就是分支，`main` 是主分支的名字。

## 一个真实的例子

有个程序员发现常用的一个工具在中文环境下会乱码。他去项目的页面提了问题，几天没人理，决定自己修。

他把项目复制到自己电脑上，开了一条分支，改代码，测试，提交。然后把这条件分支传到自己账号下，在项目页面上发起一个请求，说明自己改了什么、为什么。

维护者看到了，在某一行下面评论：「这里可以简化。」他改了，再提交一次，请求自动更新。维护者点了合并。他的改动进了主线，名字留在贡献者列表里。

从头到尾两人没见过面，可能隔着好几个时区。

## 它不适合干什么

**大文件。** 每次提交都存一份完整快照。几个几百兆的视频进去，仓库会涨到几个 G，复制一次要等很久。

**图片视频这类文件。** 能存，但算不出「改了哪里」，每次都是一整份新的。

**它不是备份工具。** 它管的是项目的版本，不管你的文档、照片、桌面。

## 让 AI 碰 Git，要小心
现在很多编辑器都带 Git 的图形界面，点按钮就能提交、看历史、开分支，不用敲命令。

但让 AI 帮你处理 Git 问题时要小心。「撤销」有好几种，含义完全不同，有的会真的丢东西。

`git reset --hard` 会把你还没提交的改动彻底抹掉，找不回来。

`git revert` 是做一个反向的修改，历史还在，只是多了一条抵消的记录。这个安全。

`git checkout -- 文件` 会把文件恢复成上次提交的样子，之后改的全没了。

让 AI 帮忙时，先把 `git status` 和 `git log` 的输出贴给它，让它看清你现在的状态，再问怎么办。别只说「我想撤销一下」。

拿不准就先 `git stash`，它把改动暂时收起来，随时能拿回来。
