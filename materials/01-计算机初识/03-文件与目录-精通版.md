# 文件与目录 · 精通版

计算机初识 · 第 3 站

时间：1 小时到 1 个半小时。其中读 30 分钟，动手 40 分钟。
做完你会有一个：一份你自己电脑的目录地图。

## 先把东西装上

**Windows 用户先装 Git Bash。** 这一站的命令在 Windows 自带的命令提示符和 PowerShell 里跑不了。

1. 打开浏览器搜「git 下载」，第一个就是官网
2. 下载 Windows 版，双击安装，一路点「Next」用默认选项。问你默认编辑器选什么的时候别选 Vim，新手不知道怎么退出来
3. 装完在开始菜单里搜 `Git Bash` 打开

**Mac 不用装**，按 Command 加空格，输入「终端」，回车。

装好之后敲 `pwd`。Windows 上显示 `/c/Users/你的名字`，Mac 上显示 `/Users/你的名字`，看到路径就对了。

## 你在树的哪个位置

用鼠标的时候，你不太需要想「文件在哪」这件事。双击进去，双击出来，位置感是模糊的。

命令行不行。你敲的每条命令都作用在「你现在站的地方」，站错了地方，命令就作用在错的东西上。前几站你可能已经吃过这个亏：明明文件就在眼前，`ls` 却看不见。

你要建立的就是这种位置感。

电脑里所有东西都挂在一棵树上，树根是一个斜杠 `/`。你的每一个文件，都是这棵树上的一个节点，都有一个从树根一路走下来的位置。

## 路径的两种写法

```
/Users/zhangsan/Desktop/照片
```

这是绝对路径，开头带斜杠，永远从树根开始算。不管你现在站在哪，它指向的都是同一个地方。

```
照片
```

这是相对路径，不带斜杠，从你现在站的地方开始算。你站在桌面的时候它指的是桌面上的照片，站在下载文件夹的时候它指的是别的东西。

**搞混这两种写法是新手最常见的错误来源。** 一个简单的判断方法：看开头有没有斜杠。有就是绝对的，没有就是相对的。

## 三个要记住的符号

```
.    当前目录
..   上一级目录
~    你的家目录
```

`~` 是家目录的简写。Mac 上家目录在 `/Users/你的用户名`，Linux 上在 `/home/你的用户名`。这两个路径写起来长，所以有了 `~`。

`..` 可以连着用。`cd ../..` 是往上退两级，`cd ../../..` 是三级。

## 根目录下面都放了什么

敲 `cd /` 走到树根，然后 `ls`。你会看到这样一堆目录：

```
bin   etc   opt   sbin  tmp   var
dev   home  private  usr  ...
```

它们各自负责什么，看一遍就有数了：

`/usr` 里装的是绝大部分软件。你以后用包管理器装的东西，大多在这里。`/usr/bin` 是放可执行程序的地方。

`/etc` 里全是配置文件。系统和各种软件的设置都在这儿。

`/var` 是「会不断变大的东西」的集中地。日志在 `/var/log`，数据库文件、缓存也都在这附近。

`/tmp` 是临时文件，重启可能就清空了。往里放东西不用太心疼，但也别放重要的东西。

`/home` 是 Linux 上用户自己的地盘。Mac 上对应的是 `/Users`。

`/bin` 和 `/sbin` 放的是最基础的系统命令，`/sbin` 里那些一般只有管理员用得上。

`/opt` 是给第三方软件留的位置，有些软件会装在这儿。

`/dev` 是设备文件。这里的「文件」其实对应着硬件，比如磁盘、终端。这是个很有意思的设计，Unix 把硬件也当成文件来操作。

这套规矩有个名字叫 FHS，文件系统层级标准。它存在的意义很实际：换一台 Linux 机器，你照样知道配置在 `/etc`、日志在 `/var/log`。这是你跨机器时唯一能依赖的东西。

**最后一条要记住的：`/` 下面的东西归系统管。** 在 `/etc` 里乱改可能让系统起不来。所有练习都在自己的家目录里做。

## 权限

敲 `ls -l`，每行开头那一串是这样的：

```
drwxr-xr-x   5 zhangsan  staff   160  9月 10 14:22 Desktop
-rw-r--r--   1 zhangsan  staff  1024  9月 12 20:11 笔记.txt
```

第一个字符是类型，`d` 是目录，`-` 是普通文件，`l` 是软链接。

后面九个字符分三组，每组三个：

```
rwx  r-x  r-x
│    │    └── 其他人
│    └─────── 同组的人
└──────────── 文件的所有者
```

每组里 `r` 是读，`w` 是写，`x` 是执行，没有那个权限就显示 `-`。

所以 `-rw-r--r--` 读作：所有者能读能写，同组的人能读，其他人也能读。`笔记.txt` 是这么一份文件，你改了别人也能看见。

用数字写更省事。`r` 是 4，`w` 是 2，`x` 是 1，加起来就是那一组的值：

```
rwx = 7
rw- = 6
r-x = 5
r-- = 4
```

所以 `-rw-r--r--` 就是 `644`，`drwxr-xr-x` 就是 `755`。

改权限用 `chmod`：

```
chmod 644 文件
chmod +x 脚本.sh
chmod -x 脚本.sh
```

`+x` 和 `-x` 是加减的写法，比数字好记。第 7 站你用的 `chmod +x` 就是它。

这里有一条很容易被忽略的规则：**目录上的 `x` 和文件上的 `x` 意思不一样。**

文件上的 `x` 是「这个文件能被执行」。目录上的 `x` 是「这个目录能进去」。一个目录如果只有 `r` 没有 `x`，你能看见里面有哪些文件名，但打不开任何一个，也进不去。

所以那个经典的怪现象：文件权限明明是 `644`，你还改不了它，因为**路径上某一级目录**你没有权限。这种时候用 `namei -l 路径` 一路看下去，就能找到卡在哪一级。

## 隐藏文件

`ls` 默认不显示以 `.` 开头的文件。加 `-a` 才会显示：

```
ls -la
```

你会看到 `.zshrc`、`.gitconfig`、`.ssh` 这些。它们大多是配置，平时不显示是因为不需要天天看见。

`.` 开头表示隐藏，这个约定来自 Unix 早期的一个偷懒决定。它没有更深的原因，记住就行。

## 软链接和硬链接

有时候你希望一个文件出现在两个地方，但不想复制两份。链接就是干这个的。

```
ln -s 原文.txt 快捷方式.txt
```

`-s` 表示软链接。它创建出来的 `快捷方式.txt` 是个很小的文件，里面只存了「原文.txt 在哪」这个信息。打开它会打开原文，删除原文它就成了断掉的指针。

不加 `-s` 就是硬链接：

```
ln 原文.txt 另一个名字.txt
```

硬链接看起来像给同一个文件起了两个名字。两个名字指向的是同一份数据，删掉任意一个，另一个照样能用。只有两个都删了，数据才真的没了。

日常用得最多的是软链接。最典型的场景是「某个程序必须在 `/usr/local/bin` 里找命令，但你的程序装在别的地方」，做一个软链接过去就行了。

## 动手任务

一、**在根目录下逛一圈。** 敲 `cd /` 然后 `ls`，逐个 `cd` 进去看 `bin`、`etc`、`var`、`usr` 里有什么。只许看，不许改。

二、**练习两种路径。** 从家目录出发，用相对路径走到 `Downloads`，再用绝对路径走一遍。对比两次敲的命令。

三、**读一次权限。** 敲 `ls -l`，挑一行，逐字说出开头那十个字符是什么意思。再用 `ls -ld ~` 看你自己家目录的权限。

四、**做一次权限实验。** 建一个测试文件，`chmod 000` 它，试试 `cat` 还能不能读。再 `chmod 644` 恢复。只在自己建的文件上做这件事。

五、**制造一个软链接。** 建一个 `原文.txt`，然后 `ln -s 原文.txt 快捷方式.txt`。删掉 `原文.txt`，再看 `快捷方式.txt` 还能不能打开。这个实验能让你一次记住软链接的特性。

六、**找出你电脑里最占空间的地方。** 敲 `du -sh ~/* | sort -h | tail -10`。这条命令会算出你家目录下每个文件夹的大小，按从小到大排，取最后十个。

## 正式产出

**一份你自己电脑的目录地图。**

要求：

列出 `/` 下面的所有目录，每个写一句它是干什么的；标出哪几个你永远不该手动改；画出你的家目录结构，标出你平时最常去的三个位置；附上你刚才用 `du -sh` 查出来的空间占用前十名。

写成 markdown，放在 `练手` 文件夹里。以后你换电脑或者装双系统，照着这份地图走一遍，能省很多时间。

## 卡住了看这里

**提示 `Permission denied`，但文件明明是我自己的。** 检查路径上每一级目录的权限。用 `ls -ld` 看目录本身，用 `namei -l 完整路径` 一路看下去，找到是哪一级卡住了。记住目录的 `x` 意思是「能进去」。

**`cd` 到一个目录，提示「不是目录」。** 你 `cd` 的是一个文件。先 `ls -l` 看清楚，第一列是 `d` 开头的才是目录。

**文件名以 `-` 开头，命令报错。** Shell 把它当成选项了。加 `--` 分隔：`rm -- -文件名`。或者写成 `./-文件名`。

**软链接打不开了。** 原文件被删了或者被移走了。软链接只是个指针，原文件没了它就断了。这就是它和硬链接的区别。

**改了扩展名，程序打不开了。** 系统靠内容判断文件类型，但应用程序往往看扩展名。给图片改名要保留原来的扩展名。

**`chmod 777` 之后还是不行。** 问题不在这个文件上，在路径上某一级目录。用 `namei -l` 查。

**不小心在 `/` 里建了文件。** 立刻 `pwd` 确认自己在哪，用 `sudo rm` 删掉。以后动系统目录之前先敲一次 `pwd`。

## 走完之后

这一份内容很干，全是名词和规则，不太会有「哇」的时刻，判断方法也换一个。

问自己：看到「原来 `/etc` 是专门放配置的」这种信息时，你是觉得踏实了，还是觉得「记住这些有什么用」。

觉得踏实的人，通常对「结构」这件事有天然的敏感。运维、后端、系统方向都比较适合这种性格。

觉得没用的人也不少。这一站是纯基础，枯燥是正常的。它的作用不在当下，在后面：等你遇到路径和权限问题时，不至于卡住。走完直接去第 9 站，那一站开始就有能拿出手的东西了。

## 想再往下看

权限这一块还有一层没讲：`umask`，它决定了你新建的文件默认是什么权限，以及 `setuid`、`sticky bit` 这些特殊权限位。这些东西日常用不到，真需要的时候，去看 Arch Wiki 上的 File permissions 那一页，它讲得比任何中文资料都准。
