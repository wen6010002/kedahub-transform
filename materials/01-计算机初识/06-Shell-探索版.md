# Shell · 探索版

计算机初识 · 第 6 站

时间：1 小时左右。读 25 分钟，跟着做 25 分钟。

---

## 双击图标和打一行字，背后是同一件事

你双击桌面上那个图标，软件就打开了。

这一下背后发生了一件事：电脑去某个地方找到了那个软件，然后把它运行起来。只不过平时是图标替你说了一句话，那句话的意思是「运行这个」。你点一下，就等于说了那句话。

还有另一个地方，你可以自己打字说出那句话。那个地方叫终端，就是那个黑窗口。

先把它打开。Windows 用户在开始菜单里搜 `Git Bash` 点开，Mac 用户按 Command 加空格、输入「终端」、回车。还没装的，看这一站最后「先把东西装上」那一节。

打开之后你会看到一个窗口，里面有一行字，末尾有个光标一闪一闪。那个光标就是在等你说那句话。

现在敲这两个字母，然后回车：

```
ls
```

屏幕上列出一串名字。那些就是你个人文件夹里的东西，跟你在文件管理器里看到的同一批。

你刚才做的事，和双击一个图标是同一件：都是告诉电脑「运行这个」。`ls` 就是一个程序，它的作用是把当前文件夹里的东西列出来。如果你敲一个电脑不认识的词，它会告诉你找不到。

用图标的时候，是图标替你说那句话。用终端的时候，是你自己打字说。这就是 Shell 在做的事。

Shell 这个词是「壳」的意思，因为它是包在系统外面的一层。系统最里面是硬件，那一层你碰不到，也不该碰，你所有的操作都要通过外面这层壳转达。

壳本身什么都不干。它只做两件事：听懂你说的话去找对应的程序，以及把找到的程序接起来。

第一件事很普通。第二件事才是它真正的本事。

## 一根竖线

看这一行：

```
ls | wc -l
```

不用看懂，看结构。中间那根竖线叫**管道**。

它的作用很朴素：把左边那句话的结果，直接交给右边那句话去处理。

具体到这个例子：`ls` 是「列出当前文件夹里有什么」，`wc -l` 是「数一下有多少行」。合起来就是：列出这个文件夹里的东西，然后数一下有多少个。

左边说完，右边接着用，中间不用你管。

## 四个程序，一条命令

再看这一行：

```
find . -name "*.py" | xargs wc -l | sort -n | tail -20
```

四个程序，三根竖线，串在一起。

拆开读，从左往右：先找出所有名字以 `.py` 结尾的文件，把这些文件名一个一个交给「数行数」的程序，把结果按数字从小到大排，最后取末尾二十行。

翻译成人话：**列出这个项目里最长的二十个代码文件，从短到长排。**

关键的地方在这里：**这四个程序，谁也没为谁设计过，谁也不知道彼此存在。** 它们是临时被你拼在一起的。

这件事在别的软件里做不到。你没法把微信和 Excel 拼起来，也没法把浏览器和记事本拼起来。它们都是完整的产品，功能包在里面，不给你拆开用的接口。

命令行里的工具正好相反：每一个都小得可怜，只管一件事，然后靠一根竖线互相连接。

## 一根竖线能拼出什么

看几个例子。

**找出哪个文件夹最占地方。** 算出每个文件夹的大小，按大小排，取最大的十个。

```
du -sh * | sort -h | tail -10
```

**数一篇文章里哪个词出现得最多。** 把空格换成换行（这样每个词占一行），排序，把相邻的重复项合并并计数，再按次数排，取前二十。

```
cat 文章.txt | tr ' ' '\n' | sort | uniq -c | sort -rn | head -20
```

**盯着日志，只看出错的行。** 前半段是「跟着文件末尾看，有新内容就显示」，接上后半段就只显示含「错误」的行。这个命令很多工程师开着就不关了。

```
tail -f 日志文件 | grep "错误"
```

这些命令你不用记。要看的是结构：每一段都在干一件小事，竖线把它们串起来，合起来干成一件大事。以后你看到一条很长的命令，不要被吓到，从左往右拆，一段一段读。

## 为什么你敲一个词，电脑就认识

你打 `ls`，电脑怎么知道 `ls` 是什么？

它其实不知道。它是去一个名单里挨个地方找，找到第一个叫这个名字的程序，然后运行它。那个名单叫 PATH，你可以打这个命令看它长什么样：

```
echo $PATH
```

它会输出一串用冒号隔开的路径。Shell 就按这个顺序，一个一个文件夹翻过去。

这解释了一个你以后一定会遇到的问题：**装了新软件，敲名字却提示找不到。** 九成是因为它装到了名单里没有的文件夹，解决办法是把那个文件夹加进名单。

也解释了另一个现象：同一台电脑上换个人登录，能用的命令可能不一样，因为每个人的名单不同。

## Shell 不止一种

这件事会让人困惑，理清楚一下。

**sh** 是最早的那个，功能很少，但几乎所有系统都有它。

**bash** 是 sh 的升级版，之后二十多年是 Linux 的默认。你在网上看到的绝大多数教程，讲的是它。

**zsh** 是另一支，功能更多。2019 年苹果把它设成 Mac 的默认，所以现在 Mac 用户大多是 zsh。

**fish** 是后来者，主打对人友好，会自动提示、自动补全、出错标红。代价是它的写法和 bash 不兼容，网上抄来的脚本它跑不了。

日常用，Mac 上用自带的就行，Windows 上用 Git Bash 里带的。写脚本的时候，在文件第一行明确写清楚用哪个，别依赖默认，这样换台电脑也能跑。

## 一个真实的场景

有个团队要分析一份服务器访问日志。日志记录的是每个来访者的地址和访问时间，两千万行。他们想知道：哪些地址在短时间内访问了特别多次。这种情况通常是爬虫或者攻击。

一行命令：

```
cut -d' ' -f1 访问日志 | sort | uniq -c | sort -rn | head -20
```

拆开读：把每行的第一个字段（也就是来访者的地址）切出来，排序，统计每个地址出现了多少次，按次数从多到少排，取前二十。

两千万行，十几秒。

结果出来，前几个地址的访问次数是正常访客的几百倍。封掉，问题解决。

这件事用编程语言写程序也能做，大概三十行代码，还要装环境、调试。但一行命令更快，不用装任何东西，在任何一台服务器上都能直接跑。

## 它的边界

**只能处理文字。** 管道的本质是「把一段文字交给下一个程序」。它能处理表格、日志、配置这些文本，处理不了图片、音频、视频的内容。

**程序之间的约定很脆弱。** 竖线两边靠文字传递，而文字没有结构。如果左边的输出格式变了一点，右边就可能读错。

**复杂逻辑写起来难受。** 一旦要在管道里做复杂的判断、处理层层嵌套的数据，你会发现自己在跟语法较劲。这种时候换一门正经的编程语言更明智。

**出错不好查。** 一条命令串了五个程序，中间某一步出问题，你得一段一段试，看是哪一步。

**对新手不友好。** 一堆符号加简写，第一眼看不懂。

## 不会拼命令，让 AI 帮你拼
不会写这些命令，不代表用不上它们。

**让 AI 帮你拼。** 把需求说清楚，让它给你一条命令。描述的时候讲清三件事：数据在哪、要做什么、结果想看到什么样。

**拿到之后先拆开读。** 从左往右，每根竖线断一次，问自己每一段在干什么。有一段看不懂就直接问 AI 这一段是什么意思。能拆开读，你就能判断它有没有危险。

**重点看这几个词。** 命令里出现这几个，要停下来确认一遍：

删除类的命令会把东西删掉，而且一般不进回收站。

大于号表示把结果写进一个文件，注意它是覆盖，原来那个文件里的东西会被清空。

移动类的命令，如果目标位置已经有同名文件，会被直接盖掉。

`xargs` 这个命令的作用是「把前面得到的结果，当成命令去执行」。如果前面得到的东西不对，后果会很奇怪。

**先干跑。** 把真正动手的那一段删掉，只看前面几段输出什么。比如要批量替换文件里的词，先只跑「找出哪些文件含这个词」那一段，看看它到底找出了哪些文件。确认没错再跑完整的。

## 先把东西装上

下面要在「终端」里敲命令。终端就是那个黑窗口，你打一行字，电脑照着做。

### Windows

Windows 自带的「命令提示符」和 PowerShell 用不了这一站的命令，敲了会报错。要先装一个 Git Bash，它给你一套和 Mac 一样的命令行环境。

1. 打开浏览器，搜「git 下载」，第一个就是官网
2. 下载 Windows 版，安装包大概六十兆，下完双击打开
3. 一路点「Next」。中间会问你一堆问题，全部用默认选项就行
4. 只有一处要注意：问你默认编辑器（Default editor）选什么的时候，别选 Vim。Vim 是给熟手用的，新手进去不知道怎么退出来。选「Use Notepad as Git's default editor」，或者列表里的 VS Code
5. 装完，在开始菜单里搜 `Git Bash`，点开它

还有一个更快的打开方式：在任意文件夹里点右键，菜单里有一项「Open Git Bash here」，点它就在那个文件夹里直接打开了。

### Mac

Mac 不用装。按 Command 加空格，输入「终端」，回车。

### 确认装好了

打开 Git Bash（Mac 就是终端），敲：

```
pwd
```

Windows 上会显示 `/c/Users/你的名字`，Mac 上会显示 `/Users/你的名字`。看到路径就对了。

Windows 上如果提示「不是内部或外部命令」，说明你打开的是系统的命令提示符，不是 Git Bash，回去重新打开。

## 自己试一下

### 先准备一点数据

```
cd ~
mkdir 试试管道
cd 试试管道
printf "苹果\n香蕉\n苹果\n橘子\n香蕉\n苹果\n" > 水果.txt
cat 水果.txt
```

最后一条把文件内容打出来，你会看到六行，三种水果。

### 数一数苹果出现了几次

```
cat 水果.txt | grep 苹果
```

`grep` 是「从一堆文字里挑出含某个词的行」。屏幕上剩下三行苹果。

再数一下有几条：

```
cat 水果.txt | grep 苹果 | wc -l
```

输出 `3`。

### 换成统计每种水果各出现几次

```
cat 水果.txt | sort | uniq -c
```

```
   1 橘子
   3 苹果
   2 香蕉
```

`sort` 是排序，`uniq -c` 是把相邻的重复行合并起来并数个数。之所以要先排序，是因为 `uniq` 只认挨在一起的重复。

### 加一个条件看看

```
cat 水果.txt | grep -v 苹果 | sort | uniq -c
```

`-v` 是取反，意思变成「挑出不含苹果的行」。输出就只剩橘子和香蕉了。

---

刚才这几条命令，每一段都只干一件小事：`cat` 把文件打出来，`grep` 挑行，`sort` 排序，`uniq -c` 合并计数，`wc -l` 数行数。

这五个小工具谁都不认识谁，是你用竖线把它们串起来的。这就是 Shell 的核心，剩下的都是这个思路的变体。
