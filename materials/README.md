# 新生引路资料库

课搭自己写的学习资料。用户跟着定制路线走到某一站，点进来看的就是这些东西。

## 先想清楚读者是谁

这一条比后面所有规则都重要。写每一句话之前，脑子里要有一个具体的人。

他是大一新生。高考完的那个暑假他刚拿到自己的电脑。他会用微信，会写 Word，会刷视频，会装游戏。除此之外，他没干过别的。

他不知道「目录」和「文件夹」是同一个东西。他不知道文件有扩展名，也不知道 `.docx` 和 `.pdf` 的区别在哪。他没听过「服务」「部署」「接口」「模型」这些词，或者听过但完全不知道是什么意思。他电脑里的文件大部分堆在桌面上，因为「保存到哪」这个问题他想过但没想明白。

他不知道自己不知道什么。所以**他也不会主动去搜那些他看不懂的词**，看不懂就直接关掉了。

再强调一遍：他不会的东西比我们以为的多得多。「打开终端」这四个字对他来说就包含三个陌生信息：什么是终端、终端在哪、怎么打开。

写之前我读了很多别人的东西：MIT 那门课、阮一峰的教程、鸟哥的教材、Wooledge 的 Wiki。读它们是为了搞明白怎么讲最清楚、新手最容易在哪一步卡住。但落到纸面上的每一句都得是自己写的，因为直接搬别人的教程有三个绕不过去的问题：语气不对，例子不对，顺序不对。

---

## 每个技术都有两份

一份探索版，一份精通版。

**探索版放在探索路线里。** 它不是精简版的教程，它是科普。走这一站，目的是搞清楚这个东西是什么、能干什么、干不了什么、在真实工作里长什么样。学会这门手艺是后面的事。走完这一站，他应该能判断自己对这个方向有没有感觉，也应该能在完全不会写的情况下，让 AI 帮他写出能用的东西。

**精通版放在后面。** 走完探索路线、确定想往这个方向走的人，回来学精通版，那才是真正把手艺学到手。

两份的关系不是「简单版和详细版」。探索版讲能力边界，精通版讲怎么做出来。探索版可以很长，但不许写成教程；精通版可以很深，但不许重复探索版已经讲过的背景。

---

## 探索版写什么

探索版是这一整套资料里最需要花心思的部分，因为它要解决一个很难的问题：让一个连目录都不知道是什么的人，在不下手做的情况下，也能明白这个东西是干什么的。

按这个顺序走：

**一、开头必须是最基础的那个画面。**

不要从「刚学部署网站的人会遇到……」这种话开头，因为读者连部署是什么都不知道。也不要用定义开头，定义是写给已经知道的人看的。

正确的开头有两种。一种是**他见过的东西**：「你电脑桌面上那些图标，点两下就能打开一个软件。这件事背后有一套机制。」另一种是**他关心的问题**：「你肯定遇到过这种情况：下载了一个文件，过两天找不到它在哪了。」

判断标准很简单：**开头的第一句话里，有没有他可能没见过的词。** 有就重写。

**二、它到底是什么，用他见过的东西打比方。**

讲 Shell 的时候，不能只说「Shell 是一个命令解释器」。要说清楚它在他每天用电脑的过程里对应着哪一步。比方可以用，但不能为了好懂而说错，讲完之后要能对得上真实情况。

**三、它能干什么，五六类，每类一个真例子。**

例子要具体到能感觉到差距。说「很方便」没用，要说「这件事用鼠标得点几百下，用这个是一句话」。而且要挑他生活里能对上号的例子，不要用「处理两千万行日志」这种离他很远的场景开头，那可以放在后面当补充。

**四、一个真实场景。**

讲一个完整的故事：某个岗位上的人，用这个东西解决了一个什么问题，从发现到解决走了哪几步。这一节最值钱，因为它是「真实工作长什么样」的直接证据。

故事里出现的每个专业词都要当场解释，不能假设他认识。

**五、它的边界。**

明确说什么它干不了，什么情况下用它是错的。这一节和「能干什么」同等重要。一个人只知道某个工具能干很多事，不知道它干不了什么，用起来会处处碰壁。

**六、这一节标题跟着内容走。** 讲「不会做的人怎么把事做成」（怎么让 AI 帮忙 + 拿到结果检查哪几点），但标题不许用「不懂原理也能用」这种模板句，按实际内容起名。

讲清怎么让 AI 帮忙做这件事，以及拿到结果之后要检查哪几点。这是这一代学生最需要的一节，也是这一整套资料跟十年前那些教程最大的不同。

要写到能照做的程度：怎么描述需求、要交代哪几件事、拿到结果先看什么、怎么先跑一个不会造成破坏的版本。

**六、安装要单独成节，写全。**

任何需要装东西的技术，探索版和精通版都要有一节专门讲安装，标题就叫「先把东西装上」这类。**探索版也要教安装**，不能因为它是科普就跳过。不装东西，读者探索个什么。

一节安装要写清：去哪儿下、下哪个版本、安装过程中会遇到什么选择、装完怎么验证装好了、装完了在哪儿打开。

不能写「假设你已经装好了」。所有会让人犹豫的地方都要提前说，比如 Git 安装时会问你默认编辑器选什么，不写清他可能选了 Vim 然后不知道怎么退出。

Windows 的步骤写详细，Mac 的可以简略。安装这一节放在动手那节的前面。

**七、终端要说清用哪个。**

这套资料里的命令都是 Linux 风格的（`mkdir -p`、`grep`、`cat`、`chmod` 这些），Windows 自带的命令提示符和 PowerShell 里用不了。

所以 Windows 用户要先装 Git Bash，用它来敲命令。每一份用到终端的资料，开头都要说清这一点，不能让读者自己猜。Mac 用户直接用系统自带的终端。

**八、自己试一下。**

带他动手做一个小 demo，五到十条命令，十分钟内做完。

不能只是「看看装没装」或者「去别人的网站上翻一翻」。他得自己敲命令、自己看到结果。每一条命令都要说清是干什么的，输出要写在资料里，让他能对照自己屏幕上的一样不一样。

这个 demo 要有两个特点：

一是**能跑起来**。敲完他手上有个真实的东西，不是一堆概念。

二是**有一个让他「哇」的时刻**。比如 Git 里回到过去那一下：他敲一条命令，文件真的变回了之前的样子。这个时刻比讲十句道理都有用。

做完之后告诉他：刚才这几条就是这东西的核心，剩下的都是变体。这句话能让他知道「我已经摸到门了」。

**九、走完之后该能回答什么。**

列五六个问题，答不上来也没关系，去下一站。

## 精通版写什么

精通版是给已经决定往这个方向走的人看的，按「从零做到能交出一个东西」来写：

一、从一个具体的东西开头。一个现象、一个麻烦、一件你本来就想做的事。

二、讲清它是什么，为什么会是这样。

三、让你动手敲第一遍。越早越好，别等到「讲完理论再练」。

四、一层一层往上加。每一层都要能立刻看到结果。

五、给一个真正要交出来的东西，具体到能拿给室友看。

六、你可能会卡住的地方，写成「现象 → 原因 → 怎么办」。

七、走完之后，怎么判断自己适不适合走这条路。

---

## 时间怎么标

每份标一个时间区间，比如「1 小时左右」，并且拆开写清时间花在哪：

```
看和读      35 分钟
自己试      25 分钟
```

精通版要多一行「卡住调试」。新手不知道卡住也是要算时间的，写完三行代码调半小时太正常了，不算进去会让他以为是自己笨。

---

## 别人家的资料放哪

正文里不出现链接。正文是教学，教学就该一路讲到底，中间插一个「详情见某某教程」会把人赶走。

只在文末放一小节，叫「想再往下看」，最多三条，写清每条适合什么样的人。没有合适的就不写这一节。

---

## 写作红线

**先说三条最容易犯的，这三条决定了读者会不会看两眼就关掉。**

一、**不许有元叙述。** 不要写「先说一件事」「这一节讲的是」「下面重点讲」「判断标准很简单」这类话。这些话是在讲「我要开始讲东西了」，不是在讲东西。直接从内容开始。

二、**不许讲技术的历史和设计理由。** 不要写「上世纪七十年代内存很小，所以被迫这么设计」「因为当年很多人共用一台机器，所以有了权限」。这些是背景知识，学生不需要。他需要的是这东西现在能干什么。只有一个例外：这个「为什么」直接决定他下一步该怎么做，才写，而且一句话写完。

三、**不许讲这一站的意义。** 不要写「这一站要解决的就是这个问题」「这一站只解决一件事」「走完这一站你会知道」。读者读完自然知道。开头、段中、结尾都别加这类话。

下面这些是老问题，一样不许犯。

四、**不许跳跃。** 这是 AI 写教程最大的毛病。人讲课是环环相扣的，AI 会从 A 直接跳到 C，中间那步默认你知道。

具体长这样：

让你敲一条命令，但没说在哪儿敲、那个窗口怎么打开。提到一个程序的名字，但没说它是干什么的。从「你平时怎么用」直接跳到「你应该这么做」，中间没有过渡。冒出一个没解释过的词就往下讲。

**检查方法**：把自己当成一个完全不懂的人，从第一句开始一行行读。每读到一条指令，停下来问一句「这一步我该在哪儿做、从哪儿开始」。答不上来就是跳了。

五、**不许预设任何前置知识。** 每写完一段回头问：这段话里有没有他没见过的词？「部署」「服务」「接口」「模型」「目录」「进程」「端口」，对我们来说是日常用语，对他来说全是新词。有就当场解释，或者换个说法。

六、**不许有 AI 腔。** 禁用词：值得注意的是 / 本质上 / 说白了 / 换句话说 / 综上所述 / 也就是说 / 恰恰 / 赋能 / 抓手 / 闭环 / 颗粒度 / 对齐 / 沉淀 / 链路 / 心智。禁用「不是 A 而是 B」这种排比。破折号换成逗号或者拆句。

七、**不许写口号句。** 像「没撞过墙别看，看了也记不住」这种能截图的短句，像「出现以下任意一条，就是该看的信号」这种清单式判断，都是 AI 最爱写的。人讲课不这么说话。

八、**不许用模板小标题。** 「一句话说清」「三分钟看懂」「你需要知道的 N 件事」「核心要点」「常见误区」，一律不要。小标题跟着内容走，讲什么就叫什么。

九、**句子要短，但不是让你把该讲的删掉。** 这一条最容易被做过头，说清楚它到底指什么。

要删的是**没有信息量的表达**：这东西是谁发明的、上个世纪为什么这么设计、这个功能在行业里有多重要、「这一步很重要」、「先说说我为什么要讲这个」。这些话删掉，读者一点损失都没有。

不能删的是**概念和步骤**。分支是什么、一次提交里有什么、怎么装 Git、Windows 上该用哪个终端，这些一个都不能少。新生看不懂，是因为该解释的地方被当成废话删了，跟资料长短没关系。

判断方法：删掉一句话之前问自己，读者读完这句话知道了什么新东西。答不上来就删。答得上来就留，哪怕它读起来有点啰嗦。

一句话超过三十个字就拆开，一段超过四行就分段。但这跟「把话说全」不冲突，拆成两句说，别直接不说。

十、**默认写 Windows。** 大部分学生用的是 Windows。写操作步骤的时候，Windows 的步骤放前面、写详细，Mac 的放后面、可以简略。涉及命令的地方要说明在哪敲（Windows 用 Git Bash 还是命令提示符，Mac 用终端），不能让读者自己猜。

十一、**加粗要少。** 一段里最多一处。加粗多了等于没加粗。

十二、**不许堆链接。** 正文零链接。文末最多三条。

十三、**不许写「视情况而定」「根据个人基础」。** 这是在推卸判断。给具体的时间、具体的人、具体的建议。

十四、**不许用术语解释术语。** 每个术语第一次出现，用一句人话带过。

十五、**代码必须自己跑过。** 写进资料里的每一段脚本、每一条命令，都要在真的终端里执行一遍，确认输出和资料里写的一样。变量名一律用英文，因为 Mac 自带的 bash 3.2 不认中文变量名，会报一个看不出原因的错。

## 怎么判断一篇写完了

不管哪一份，先拿这六个问题过一遍：

一、**把自己当成一个完全不懂的人，从第一句开始一行行读。** 每读到一条指令就停下来问「这一步我该在哪儿做、从哪儿开始」。答不上来就是跳了。

二、**把每一段的第一句话连起来读，像不像在讲「我要开始讲东西了」。** 像就说明元叙述没清干净。

三、**有没有在讲这东西的历史、由来、谁发明的、设计理由。** 有就删掉。

四、**通读一遍，有没有哪句话读完你不知道它给了什么信息。** 有就删。

五、**里面出现的每个概念，是不是都解释清楚了。** 特别是那些我们觉得「这还用解释吗」的词。分支是什么、仓库是什么、终端在哪打开、命令在哪敲，这些都要写到。

六、**有没有一节专门讲安装，写清了去哪下、装的时候会遇到什么、装完怎么验证。** 探索版也要有。

七、**有没有一个他自己敲得出来的小 demo，做完手上有个真实的东西。** 光看别人网站、光看概念，不算。

探索版再过这五个：

一、**把开头第一段单独拿出来看，里面有没有一个连电脑都不太会用的人可能没见过的词？** 有就重写开头。

二、**读完能不能说出这个东西能干什么、干不了什么。** 说不出就是「边界」那一节写虚了。

三、**有没有一个真实的场景，让人看到这行人在真实工作里长什么样。** 没有就是纯知识，不是探索。

四、**不懂代码的人读完，知不知道怎么让 AI 帮他做出一个能用的东西，以及要检查哪几点。** 不知道，这一站就白走了。

五、**能不能直接当定制 Agent 的输入？** 读它的人要能准确说出「走完这一站，这个人了解什么、能指挥 AI 做出什么」。

精通版再过这三个：

一、**一个卡在这一站的学生，能不能在里面找到自己卡在哪？** 找不到就是「卡住的地方」写虚了。

二、**有没有一个真正要交出来的东西？** 没有就是纸上谈兵。

三、**把文末那三条链接全删掉，这篇还有没有价值？** 删掉就什么都不剩，说明写成了书单。

## 目录

文件命名规则：`站号-主题-探索版.md`、`站号-主题-精通版.md`。**同一个站的两份用同一个站号**，读的时候一眼能看出哪个跟哪个是一对。站号按建议的行走顺序排，中间会留空号，因为有些站还没写。

```
00-总览/          六个模块的地图 · 资料清单（全部选题和进度）
01-计算机初识/     9 站
02-前后端初识/     11 站
03-AI/           10 站
04-产品初识/       5 站
05-测试与运维初识/  3 站
06-算法工程师初识/  3 站
```

**动笔之前先看 `00-总览/资料清单.md`。** 那里有全部 41 个探索版选题和每个选题要讲什么，别漏。

前三个模块是主干，走完大约 22 到 26 小时。后三个模块是看看别的岗位在干什么，走完主干再挑着看。
