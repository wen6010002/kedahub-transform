## 你敲下回车之后的那一秒

你在浏览器地址栏里敲 `www.example.com`，按下回车，不到一秒，网页出来了。

就这一秒，中间发生了一长串事。你一点感觉都没有，因为都太快了。

这一站把这一秒拆开，看清楚数据是怎么从你的电脑，跑到世界另一头的一台机器上，又跑回来的。

---

## 数据不是一块传过去的

先说一个反直觉的事。

你以为你打开一个网页，是这个网页「整块」从服务器飞到你的电脑上。

不是。**你的请求和数据，在路上被切成一个个小包，各自找路走，到了再拼起来。**

就像寄一箱书，不整箱搬。把每一本书单独包好，各自寄快递，可能走的还不是同一条路，最后在你家门口重新堆成一箱。

为什么要这样？因为路可能会断、会堵。整块运，断一下就全没了；切成小包，丢了哪个补哪个，别的包继续走。

这个「切成小包」的设计，解释了后面你会遇到的很多现象：为什么视频看一半会缓冲、为什么两个网页一个快一个慢、为什么有时候一个网页里图片出得来、文字出不来。

## 每一台电脑都有一个门牌号

要在网络上找到另一台电脑，你得先知道它的地址。

这个地址叫 **IP 地址**，长得像 `111.63.65.247` 这样，四段数字，每段 0 到 255。

你可以在终端里看自己电脑的地址（怎么敲，下面的「自己试一下」会讲）。

但这里有个容易绕晕的点：**你的电脑其实有两个地址。**

一个是内网地址，比如 `192.168.1.5`。它只在你自己家的 WiFi 这个范围里有效。你室友的电脑、你的手机，也都有类似的地址，全世界有几百万台设备都在用 `192.168.1.5` 这个数字。

另一个是公网地址，是你家整个网络对外的那一个地址。外面的人要找你的电脑，先找到这个公网地址，再由路由器转到你具体那台设备上。

这就像大学宿舍：你的床位号是内网地址，只有楼里的人能找到你；你的学校加宿舍楼号是公网地址，外面的人先找到学校，再查到你的床位。

**你平时访问别人，用的是别人的公网地址。别人想访问你，除非你把服务放到一个公网地址固定的地方，不然默认是连不进来的。**

## 域名是给人记的，不是给机器记的

IP 地址是一串数字，谁记得住 `111.63.65.247`？

所以有了**域名**。`www.example.com` 就是一个域名。它长得像一串英文加小数点，好记。

但机器只认数字。于是中间需要一个「查号台」：你给它一个域名，它告诉你对应的 IP 地址。

这个查号台叫 **DNS**。你敲 `www.example.com`，电脑先去问 DNS「这个名字对应哪个 IP」，拿到 IP 之后，才真正开始连接。

**这件事解释了为什么改了 DNS 设置要等一会儿才生效。** 因为电脑查过一次之后会把结果记下来，下次直接用，过一段时间才重新问。你刚改完设置，电脑还在用旧的记录。

## 一次请求在路上过的关

现在把「敲回车」这一秒拆开，看数据经过了哪几关。

**第一关，查域名。** 电脑拿你敲的域名去问 DNS，拿到一个 IP 地址。

**第二关，发出请求。** 电脑把请求切成小包，往那个 IP 地址发。

**第三关，经过很多个中转站。** 小包不是直接飞到目的地的。它们要经过你家的路由器、运营商的机房、可能跨好几个城市甚至几个国家，每一站都把包往正确的方向传一下。这就像你寄快递，中间要经过好几个转运中心。

**第四关，到达服务器。** 对方的服务器收到这些小包，把它们重新拼成完整的请求。

**第五关，服务器处理，返回数据。** 服务器把网页的内容打包，同样切成小包，沿着原路发回来。

**第六关，你的电脑收到，拼好，浏览器画出来。**

这六关，加起来通常不到一秒。

## HTTP 是什么，为什么有的网站是 https

浏览器和服务器之间说话，要遵守一套约定，不然两边互相听不懂。

这套约定叫 **HTTP**。它规定了「怎么打招呼、怎么要东西、怎么给东西、怎么结束」。

你访问一个网站，地址栏里有时是 `http://` 开头，有时是 `https://` 开头。多出来的那个 `s`，意思是「加密」。

`http://` 的问题是：你和服务器之间的对话是**明文**的，谁在半路上截住都能看。你在一个 http 网站输入密码，密码就像写在明信片上寄出去，经过的每一个中转站都能瞄一眼。

`https://` 把这套对话加密了。截住的人看到的是一堆乱码，只有你和服务器能看懂。所以现在几乎所有正经网站都用了 https，浏览器也会给没加密的网站标一个「不安全」。

**记住一条：要输密码、输银行卡、输任何私人信息的网站，地址栏必须是 `https://` 开头。不是就别输。**

## 一个真实的场景

一个做后端的人，早上到公司，发现用户反馈「网站打不开了」。

他做的第一件事，是搞清楚问题出在哪一段。因为「打不开」可能是一百种原因，不定位就瞎修。

他先在自己电脑上敲一条命令，去连那台服务器，看连不连得上。连不上，说明是网络断了，跟网站代码没关系。

连得上，他再敲一条命令，问 DNS「这个域名现在指向哪个 IP」，看 IP 对不对。如果 IP 变了或者查不到，就是域名的问题。

再往下，他用工具看请求有没有真的到达服务器、服务器有没有回应。一步步缩小范围，最后定位到「是服务器上某个服务挂了」，才登录上去处理。

**这个场景要说明的是：网络问题排查，核心动作是把「哪一段断了」找出来。** 网络是一长串环节串起来的，任何一段出问题，表现出来都是「连不上」。老手和新手的区别，就是老手知道一段一段地试，新手只会重启路由器。

## 它的边界

**网络不是「稳定」的。** 小包会丢、会延迟、会绕远路。所以你才会遇到：视频卡顿、游戏延迟忽高忽低、网页刷半天出不来。网络本身的设计就是「尽力送达，不保证」，跟谁偷不偷懒没关系。

**网络不是无限快的。** 你家的带宽是「水管的粗细」，但你访问的服务器离你多远、中间堵不堵，决定了「水要多久才到」。所以有时候带宽很宽，网页照样慢。

**有些网站就是访问不到。** 一个网站能不能打开，取决于你和它之间的路通不通。路可能因为各种原因不通，这不是你电脑坏了。

## 网站打不开，按这个顺序查
遇到「网站打不开」，别急着重启。按这个顺序收集信息，再让 AI 帮你判断。

第一，这个网站是你一个人打不开，还是别人也打不开？换一个网站试试，别的能开、就这个不能开，说明是你到那个网站之间的路的问题，不是你电脑的问题。

第二，把下面两条命令的结果抄下来（命令在「自己试一下」里）：

- `ping 网站域名` 的结果
- `nslookup 网站域名` 的结果

第三，把你看到的报错截图，连同上面两条结果，一起丢给 AI，说「这个网站打不开，帮我判断问题出在哪一段」。

**让 AI 帮你的时候，别说「上不了网」，要说清具体是什么**：是某个网站打不开、还是所有网站都打不开、浏览器提示的什么字、什么时候开始的。信息越具体，它判断越准。

## 自己试一下

### 第一，查一个域名的 IP

敲：

```
nslookup example.com
```

你会看到类似这样的输出：

```
Name:	example.com
Address: 104.20.23.154
Name:	example.com
Address: 172.66.147.243
```

**这就是查号台给你的答案**：example.com 这个域名，对应这些 IP 地址。一个域名对应多个 IP 是正常的，说明那个网站有好几台服务器在同时扛着。

### 第二，看你的电脑到它有多远

敲：

```
ping example.com
```

你会看到一行一行在跳：

```
64 bytes from 172.66.147.243: icmp_seq=0 ttl=49 time=169.013 ms
```

`time=169.013 ms` 的意思是：你的电脑发个小包过去，169 毫秒后收到回应。毫秒是千分之一秒。**这个数字就是「你和那台服务器之间有多远」的直接体现**，越小越近。

按 Ctrl 加 C 停下来。

### 第三，亲手看一次请求长什么样

敲：

```
curl -v https://example.com
```

屏幕上会刷出很多东西。找这几行：

```
> GET / HTTP/2
> Host: example.com
< HTTP/2 200
< content-type: text/html
```

开头带 `>` 的，是你发出去的话；带 `<` 的，是服务器回给你的。

`GET /` 是「我要首页」。`Host: example.com` 是「我要的是这个域名」。`200` 是「成功」。`content-type: text/html` 是「我回你的是网页」。

**你刚才敲的那一下，就是一次完整的 HTTP 请求。** 你在浏览器里敲网址，浏览器做的也是这件事，只是它帮你把结果显示得更好看。

网络是用 IP 找到机器、用域名方便人记、用 DNS 做查号、把数据切成小包传过去、再用 HTTP 约定怎么说话。

## 几个常见的误解

**「IP 地址就是我这台电脑唯一的身份。」** 你有两个地址。内网地址全世界无数台设备共用，公网地址才对外唯一，而且还会变。所以别人没法只凭一个 IP 就定位到具体哪个人。

**「网址和 IP 是一回事。」** 域名是给人记的名字，IP 是机器认的门牌号，中间靠 DNS 查号台翻译。同一个 IP 可以挂好几个域名，同一个域名也能对应好几个 IP。

**「网速慢就是带宽不够。」** 带宽是水管粗细，延迟是水流多久到，还有丢包。水管很粗，但对方服务器在很远的地方、中间还堵，照样慢。

**「打开一个网页，是网页整块传过来的。」** 数据被切成一个个小包，分开走，到了再拼。所以才会出现「图片出来了文字没出来」这种一半的情况。

**「加了 s 的 https 跟我没关系。」** 不加 s，你的密码在路上是明文，经过的每一站都能看。凡是输密码的网站，地址栏必须是 `https://` 开头。
