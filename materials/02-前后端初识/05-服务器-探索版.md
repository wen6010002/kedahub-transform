## 半夜被叫醒的人

凌晨两点，一个做运维的人被手机吵醒。

告警短信说他负责的网站打不开了。他爬起来打开电脑，连上那台机器，敲了几条命令，发现硬盘满了，日志文件把空间吃光了。

他删掉几天前的旧日志，重启了一下服务，网站恢复了。前后二十分钟。

**这二十分钟里，他做的事全都发生在一台他摸不到的机器上。** 那台机器不在他家，在一个机房里，上面跑着几百个人的工作成果。

那台机器就是服务器。

## 服务器就是一台一直开着的电脑

先把神秘感去掉。

服务器和你面前这台笔记本，硬件上几乎一样：有 CPU、有内存、有硬盘、有网卡。

区别只有三点：

**第一，它一直开着。** 你的电脑晚上关机，服务器不关。别人半夜三点访问网站，它得在。

**第二，它放在机房里。** 机房有空调、有备用电源、有专人看着。你那台笔记本放宿舍，断电就没了。

**第三，你摸不到它。** 它没有屏幕、没有键盘、没有鼠标。你唯一能跟它打交道的方式是从别的电脑连过去。

**第三点是最容易让人困惑的一点。** 一台没有屏幕的电脑怎么操作？答案是：它不需要屏幕，它需要的只是一个能收指令的通道。你从自己电脑连过去，敲的命令在那边执行，结果传回来显示在你这边的屏幕上。

## 为什么需要它

因为你的电脑会关机。

你在自己电脑上做了一个网页，想发给同学看。如果网页文件就在你电脑上，同学访问的时候得连到你这台机器。你一合上笔记本，网页就打不开了。

服务器解决的就是这件事：**它一直在，所以别人随时都能访问。**

## 云服务器是什么

十几年前，你要让一个网站上线，得自己去买一台机器，找人搬进机房，拉网线，装系统。花的钱是几万块，时间是好几天。

现在不用了。有一批公司建了巨大的机房，里面有几万台机器，你把其中一小块租出来，按小时或者按月付钱。这就是云服务器。

租一台最便宜的，一个月几十块。点几下鼠标，几分钟之后你就有一台自己的服务器了，有 IP 地址、有系统、能连上去敲命令。

**这件事改变了整个行业。** 现在一个学生想做个小网站，成本是几十块钱，不是几万块。

## 一台机器上怎么跑几十个网站

这是很多人第一次听到会愣一下的事。

一台服务器上可能同时跑着几十个不同的网站，属于几十个不同的公司。它们互相看不见对方的数据，一个崩了不影响另一个。

怎么做到的？

**靠「隔离」。** 那台物理机器被切成了很多块，每一块看起来都像一台独立的电脑：有自己的文件系统、自己的进程、自己的网络地址。上面跑的程序完全不知道自己是在一块切出来的地方。

这种切法叫**虚拟机**或者**容器**。它们是现代服务器管理的基础，第 17 站讲云服务的时候会再提一次。

## 一个真实的场景

一个学生做了一个校园二手交易的网站，在自己电脑上跑得好好的。

他想让同学也能用，于是买了台云服务器，把代码传上去，敲了启动命令。

结果同学访问不了。

他检查了半天，代码没问题，服务也起来了。后来发现两件事。

第一，**服务只监听了本机。** 代码里写的是 `localhost`，意思是「只听这台机器内部的访问」。要让外面的人也能访问，得改成监听所有网络地址。

第二，**服务器的防火墙没开端口。** 云服务商默认会把大部分端口关掉，你得手动在控制台里把自己要用的那个端口打开。

改完这两处，同学能访问了。

**这两个坑几乎每个第一次部署的人都会踩。** 它们说明一件事：服务器和你的电脑虽然硬件一样，但网络环境的规则完全不同。你的电脑默认是「别人连不进来」，服务器要你主动把门打开。

## 它的边界

**服务器不是「更高级的电脑」。** 一台便宜云服务器的配置可能还不如你的笔记本。它的优势在于一直开着、网络好，不在于算得快。

**服务器也会挂。** 硬件会坏，网络会断，磁盘会满，程序会有 bug。所以重要的服务都会做备份和容灾，一台挂了另一台顶上。

**服务器不是免费的。** 除了租机器的钱，流量也要钱。一个视频网站每个月的带宽费用可能比机器本身贵好几倍。

**自己电脑上跑的东西，别人默认访问不到。** 这是设计如此，跟你的配置无关。全世界有几百万台设备用着同样的内网地址（比如 `192.168.1.5`），如果外面能直接访问，就全乱了。

## 别人访问不到，按这个查
**「别人访问不到我做的网站」是最常见的问题。** 按这个顺序检查：

第一，服务有没有起来。在你自己的电脑上访问 `localhost:端口` 能不能打开。打不开就是程序的问题，跟服务器无关。

第二，服务监听的是哪个地址。如果代码里写的是 `localhost` 或者 `127.0.0.1`，外面的人访问不到，要改成 `0.0.0.0`。

第三，端口有没有开。云服务商的控制台里有个「安全组」或者「防火墙」的地方，要手动把端口加进去。

第四，域名有没有解析到这台服务器。这一步在第 6 站讲。

**让 AI 帮你排查的时候，把这三件事的结果说清楚**：本地能不能访问、代码里监听的是什么地址、控制台里端口开了没有。说清这三样，它就能定位问题。

**一条原则**：先在自己电脑上跑通，再往服务器上搬。反过来做的话，出了问题你分不清是代码的问题还是服务器的问题。

## 先把东西装上

下面要在终端里看自己电脑的网络地址，不用装任何东西。

Windows 用户如果还没装 Git Bash，看第 5 站的黑窗口精通版第一步。Mac 用户直接用系统自带的终端。

## 自己试一下

### 看看你自己电脑的地址

**Windows** 打开 Git Bash，敲：

```
ipconfig
```

**Mac** 打开终端，敲：

```
ifconfig | grep "inet "
```

你会看到几个地址，其中有一个像 `192.168.1.5` 或者 `10.0.0.3` 这样的。

**这个就是你这台电脑在局域网里的地址。**

### 想想这个地址意味着什么

`192.168` 开头的地址是内网地址，意思是「这个地址只在当前这个局域网里有效」。

同一个 WiFi 下的其他设备（你室友的电脑、你的手机）可以用这个地址访问到你这台电脑。

但外面的人访问不到。

**原因是全世界有无数台设备都用着 `192.168.1.5` 这个地址。** 如果外网能直接访问，路由器根本不知道该把请求送到哪一台。

所以你的电脑从外面看，只有一个运营商分配的地址（叫公网 IP），而那个地址通常也一直在变。想让自己电脑上的东西被外面访问到，要么去做端口映射（麻烦，而且很多宽带不给公网 IP），要么把东西放到一台真正的服务器上。

**这就是服务器的第一个价值：它有一个固定的、外面能访问到的地址。**

### 用手机试一下

如果你有手机，连上同一个 WiFi，在手机浏览器里输入刚才那个 `192.168.x.x` 的地址，后面加个端口号（比如 `192.168.1.5:3000`）。

如果那台电脑上正好跑着一个服务，你手机上就能打开它。

**这就是「局域网内可以互相访问」的具体样子。** 你的手机和电脑在同一个网里，所以找得到。

（如果没跑服务，打不开是正常的。这一步只是让你知道地址长什么样。）

## 几个常见的误解

**「服务器是很高级的电脑。」** 一台便宜云服务器的配置可能还不如你的笔记本。它的优势在于一直开着、网络好、有固定地址，不在于算得快。

**「买了服务器别人就能访问。」** 还差好几步：服务要监听对外的地址、防火墙要开端口、域名要指向它。这三步任何一步没做，别人都打不开。

**「云服务器很贵。」** 最便宜的一个月几十块，学生还有优惠。贵的是流量和更高配置，不是入门那一档。

**「自己电脑也能当服务器。」** 技术上可以，实际上很难。你的电脑会关机、IP 一直在变、大多数宽带不给公网地址。别人访问不到，跟你的配置没关系。
