# 网络初识 · 精通版

前后端初识 · 第 6 站

时间：1 小时到 1 个半小时。动手 50 分钟，留 30 分钟自己试不同的网站。

做完你会有一个：一份自己记录下来的「请求报告」，看清一次请求从头到尾发生了什么。

---

## 先把东西装上

这一站用的工具叫 `curl`，是个专门发网络请求的命令行工具。

Mac 系统自带，不用装。Windows 的 Git Bash 里也自带，不用装。

打开终端（Windows 用 Git Bash），敲：

```
curl --version
```

看到类似 `curl 8.11.1` 这样一行字，就是有了。

如果提示「不是内部或外部命令」，说明你打开的不是 Git Bash。Windows 上一定要用 Git Bash。

---

## 浏览器帮你藏起来的事

你在浏览器里敲一个网址，看到网页出来，整个过程你只看到「网址」和「结果」。

中间那一段，你的电脑发了什么、服务器回了什么，浏览器全帮你藏起来了。

这一站用 `curl` 把这个过程摊开看。它是个命令行工具，专门发请求，而且有个 `-v` 参数，能让它把「自己发了什么、收到了什么」都打印出来。

---

## 第一次，看一次完整的请求

敲这一句：

```
curl -v https://example.com
```

屏幕上会刷出很多行。别怕，我们一段一段看。

开头的几行是 curl 在准备工作：

```
* Connected to example.com (172.66.147.243) port 443
```

这是说：它先查了 DNS，拿到 example.com 的 IP 是 `172.66.147.243`，连到了那台机器。**这一步就是探索版里讲的「查域名」，你能亲眼看到它查到 IP 之后才连接。**

然后是带 `>` 的行，这些是你电脑发出去的话：

```
> GET / HTTP/2
> Host: example.com
> User-Agent: curl/8.11.1
> Accept: */*
```

`GET /` 是「我要首页」。`Host: example.com` 是「我要的是这个域名」。后面几行是一些补充信息。

空一行之后，是带 `<` 的行，这些是服务器回你的话：

```
< HTTP/2 200
< content-type: text/html
< server: cloudflare
< date: Mon, 14 Sep 2026 13:20:42 GMT
```

`HTTP/2 200` 里的 **200 是响应码**，意思是「成功」。`content-type: text/html` 是「我回你的是网页」。`server` 是那台服务器用什么软件扛的。

再往后，屏幕上会刷出一大段 `<!doctype html>...` 的东西，那就是网页本身的内容，也就是 `content-type: text/html` 里说的那个 html。

**你刚才看到的，就是一次请求的完整样子**：先查域名，再发请求，服务器回响应头和内容。

---

## 第二层：只看响应头，不看内容

网页内容太长了，有时候你只想看服务器回了什么头，不想看内容。加一个 `-I`：

```
curl -I https://example.com
```

`-I` 是「只问头部，不要正文」。你会看到：

```
HTTP/2 200
date: Mon, 14 Sep 2026 13:20:42 GMT
content-type: text/html
server: cloudflare
```

**响应头里装的是「关于这次回复的信息」**，不是内容本身。做后端的人经常用这一招快速看一个网站用什么服务器、支不支持某些功能。

---

## 第三层：只看响应码

很多时候你只关心一件事：这个地址通不通、返回的是成功还是失败。

敲：

```
curl -s -o /dev/null -w "状态码: %{http_code}\n" https://example.com
```

这一串很长，拆开看：`-s` 是「别输出进度条」，`-o /dev/null` 是「把内容丢掉，不显示」，`-w` 是「按我给的格式输出」。最后那个 `\n` 是「换行」。

你会看到：

```
状态码: 200
```

200 是成功。再试一个不存在的地址：

```
curl -s -o /dev/null -w "状态码: %{http_code}\n" https://example.com/no-such-page
```

你会看到：

```
状态码: 404
```

**404 就是「没找到」**，你在浏览器里偶尔也会看到这个数字，它就是从服务器的响应码来的。

常用的响应码记住这几个就够：

- `200` 成功
- `301` 或者 `302` 这个地址搬家了，去别的地方
- `404` 没找到
- `500` 服务器自己出错了

## 第四层：看这次请求花了多久、传了多少

再加两个参数，看这次请求的「成本」：

```
curl -s -o /dev/null -w "下载字节: %{size_download}\n总耗时: %{time_total} 秒\n" https://example.com
```

你会看到类似：

```
下载字节: 559
总耗时: 0.525524 秒
```

`size_download` 是下载了多少字节，`time_total` 是总共花了多少秒。

**这两个数字就是「打开这个网页有多贵」的直观体现。** 一个网页如果下载了 2MB、花了 3 秒，你就能理解它为什么慢。

试试对比一下：访问一个文字为主的网站，和一个图片很多的网站，看它们的 `size_download` 差多少。

---

## 第五层：看 DNS 到底做了什么

前面 `curl` 每次都帮你查了 DNS，但你也能自己查。

敲：

```
nslookup baidu.com
```

你会看到：

```
Name:	baidu.com
Address: 111.63.65.247
Name:	baidu.com
Address: 111.63.65.103
```

**这就是「查号台」的工作**：你给它域名，它给你 IP。一个域名对应多个 IP，说明那家网站在多台服务器上跑。

再用 `ping` 看你和它之间的距离：

```
ping baidu.com
```

按 Ctrl 加 C 停下。看里面的 `time=` 后面的数字，是毫秒，越小越近。

## 动手任务

一、用 `curl -v` 看一次完整请求，找到 `>` 开头的行和 `<` 开头的行，数一数各有多少行。

二、用 `curl -I` 看三个不同网站的响应头，比较它们的 `server` 字段有什么不同。

三、用 `-w` 那个命令，分别测一个文字网站和一个图片多的网站，比较它们的 `size_download`。

四、用 `-w` 命令访问一个不存在的地址，确认返回 404。

五、用 `nslookup` 查三个你常用的网站，看它们的 IP 地址。

六、用 `ping` 测一个国内网站和一个国外网站，比较它们的 `time` 数字。

## 正式产出

**一份请求报告，记录你自己做的三次测量。**

用你喜欢的任何方式（Word、记事本、截图），记下：

- 一个网站的完整响应头（用 `curl -I` 拿到）
- 它首页的 `size_download` 和 `time_total`
- 它的 IP 地址（用 `nslookup` 拿到）

做完这份报告，你就能对着任何一个网站，说出「它的服务器在哪、首页多大、打开要多久、用的什么服务器软件」。

## 卡住了看这里

**提示 `curl: (6) Could not resolve host`。** 域名查不到，可能是你拼错了域名，或者 DNS 有问题。换一个网站试试，如果都这样，看下一行。

**提示 `curl: (7) Failed to connect`。** 域名查到了，但连不上那台机器。可能是对方服务器挂了，也可能是你到它之间的网络不通。换 `ping` 试试同一个域名，看通不通。

**提示 `curl: (60) SSL certificate problem`。** 那个网站的安全证书有问题，可能是证书过期了。浏览器也会提示「不安全」。换 `http://` 开头试试能绕过去，但正经网站不建议这么访问。

**屏幕上刷出一大段 html，看不清前面的头。** 用 `curl -I` 只看头，或者把命令改成 `curl -v https://example.com | head -30`，`head -30` 是「只显示前 30 行」。

**`nslookup` 提示找不到命令。** 你用的不是 Git Bash。Windows 上打开 Git Bash 再敲。

## 走完之后

这一站你做的事，本质是「把浏览器藏起来的东西，一件件扒出来看」。

做后端的人天天在跟这些东西打交道：看响应码判断哪里出错、看响应头判断服务器状态、看耗时和字节数判断性能。

判断自己对不对路子，看一个感觉：当你看到 `200`、`404` 这些数字，觉得「原来网页的背后是这些数字在说话」，而不是「好无聊」。如果你喜欢这种「把表面现象拆成底层数据」的感觉，网络和后端这条线适合你。
