## 为什么前端不能直接碰数据库

你已经知道：网站分前端和后端，数据存在后端的数据库里。

那前端能不能直接去读那个数据库？技术上能。但没有人这么做，因为会出大乱子。

想想看：前端代码是下载到你浏览器里跑的，任何人按 F12 都能看到、都能改。如果前端代码里直接写了「怎么连数据库、数据库密码是多少」，那任何一个懂点技术的人，都能连上你的数据库，看到所有用户的信息，甚至删光。

所以真实的结构是：**数据库只对后端开放，前端想要数据，只能通过后端开出来的一个「口子」去拿。** 这个口子，就是接口。

---

## 接口就是一个约定好的地址

接口这个词听起来高级，拆开就是一句话：**一个约定好的地址，加上一套约定好的格式。**

地址，就是 `https://api.github.com/users/torvalds` 这样一串。格式，就是「你访问这个地址，我给你返回一段 JSON 数据」。

前后端之间靠这个约定配合：后端说「我这里开了个接口，地址是 X，你访问它，我给你返回什么样的数据」。前端照着这个约定去访问，拿到数据，显示给用户。

**接口的核心是「约定」。** 就像你和室友约好「东西放在门口鞋柜上」，以后你不用进门，他到鞋柜上拿就行。地址是「鞋柜」，约定是「放这里」。两边都守这个约定，事情就顺了。

---

## 一个接口长什么样

拿一个真实的公开接口看。浏览器地址栏里输入：

```
https://api.github.com/users/torvalds
```

返回的是一大段数据，开头长这样：

```
{"login":"torvalds","id":1024025,"avatar_url":"https://avatars.githubusercontent.com/u/1024025?v=4",...}
```

这段东西叫 **JSON**，是接口之间传数据的通用格式。它看起来乱，其实有规律：一堆「名字：值」用花括号包着、用逗号隔开。

这里面每一段都有含义：`login` 是用户名，`id` 是编号，`avatar_url` 是头像地址。

**接口返回的东西是数据，不是网页。** 网页是给人看的，接口返回的 JSON 是给程序看的，程序拿到之后自己决定怎么显示。

---

## 接口的地址里有门道

接口的地址不是随便起的，它本身就是一套「说明书」。

看这个地址：`https://api.github.com/users/torvalds`

- `api.github.com` 是「接口所在的服务器」
- `users` 是「我要的是用户」
- `torvalds` 是「具体哪个用户」

你想换一个人，就把最后的 `torvalds` 换成别的用户名，返回的就是那个人的数据。

再复杂一点的接口，地址后面会带 `?` 和参数，比如：

```
https://api.github.com/search/repositories?q=language:python
```

`?` 后面就是**参数**，`q=language:python` 的意思是「我要搜 Python 语言的项目」。你把 `python` 换成别的词，结果就跟着变。

**地址就是接口的「遥控器」**：路径选「哪个功能」，参数选「什么条件」。你学会了看地址，就学会了一半的接口。

## 为什么调接口要申请密钥

你刚试的那个 GitHub 接口是公开免费的，随便谁都能用。

但很多接口不是。比如发短信的接口、支付的接口、查天气的接口、地图的接口。这些接口背后是要花钱的，而且能查到敏感信息。

所以这些接口的提供方会要求你**申请一把密钥**，也叫 key 或者 token。它长得像一串乱码：

```
sk-1a2b3c4d5e6f7g8h9i0j
```

你调用接口的时候，得把这把密钥一起带上。服务器看到密钥，才知道「是你在调用，你有资格」。

**密钥就是一把钥匙，证明是你本人。** 泄露了会怎样？捡到你密钥的人，能冒充你去调接口。如果他调的是要花钱的接口，账单记在你头上；如果调的是能改数据的接口，他能用你的身份改东西。

所以你在任何地方看到有人把密钥明文写在代码里、或者截图发出来，那都是事故。**密钥要当成银行卡密码一样保管。**

## 一个真实的场景

一个前端工程师，要做一个「显示天气」的功能。

他不会自己去架气象站。他去找一个提供天气接口的服务商，申请一把密钥，然后照着接口文档写代码：访问 `某个地址`，带上城市参数和密钥，服务商返回那天的天气数据，他把数据画成页面上的图标和数字。

这个场景里，接口解决了一个根本问题：**你不用自己会做天气，你只需要会用「别人开好的接口」。**

这也是现在做开发的主流方式。一个产品里，登录用的可能是别人的登录接口，地图用的是别人的地图接口，短信用的是别人的短信接口。开发者把一堆现成的接口拼起来，就做出了自己的产品。

---

## 它的边界

**接口不是万能的。** 别人开了什么接口，你才能用什么。别人没开的，你拿不到。比如 GitHub 的接口能让你查用户，但不能让你改别人的代码。

**接口会变。** 接口提供方可能改地址、改格式、涨价、甚至关掉。所以依赖别人接口的产品，要随时准备着接口哪天变了。

**接口返回的数据不一定对。** 它返回什么，取决于对方的服务器。你拿到数据之后，得自己检查一遍，不能拿到就用。

## 让 AI 帮你做
让 AI 帮你写「调用某个接口」的代码，要给它这几样东西：

第一，接口的文档。如果那个接口有官方文档，把文档地址或者关键内容发给 AI。

第二，你的密钥。没有密钥，AI 写出来的代码调不通。

第三，你要拿什么数据。别只说「查天气」，说清「我要拿北京今天的气温，用文字显示出来」。

拿到 AI 写的代码，先检查三件事：

**一看密钥有没有写对地方。** 密钥应该在请求里，而不是打印在屏幕上。如果代码里把密钥用 `console.log` 打出来了，让 AI 改掉。

**二看返回的数据长什么样。** 先让程序把接口返回的原始 JSON 打出来，你亲眼看一下里面有没有你要的字段，字段名对不对。

**三看它有没有处理「接口挂了」的情况。** 接口会返回错误、会超时。代码得能处理「拿不到数据怎么办」，而不是一失败就崩。

## 自己试一下

### 第一，访问一个接口

浏览器地址栏输入：

```
https://api.github.com/users/torvalds
```

你会看到一大段 JSON。这就是「一个用户的信息」，接口返回给你的数据。

### 第二，换个人试试

把地址最后的 `torvalds` 换成你自己的 GitHub 用户名，或者换成一个你喜欢的明星、开源作者的账号。返回的 JSON 就变成那个人的资料。

**你刚才做的是「改路径，换结果」。** 地址的最后一段是参数，换它，接口返回不同的东西。

### 第三，试试带参数的搜索接口

地址栏输入：

```
https://api.github.com/search/repositories?q=language:python
```

你会看到一段更长的 JSON，里面是一堆 Python 项目的列表。

注意地址里的 `?q=language:python`。把 `python` 换成 `javascript`，再访问一次，返回的就是 JavaScript 项目了。

**这就是接口的参数。** 你换一个词，它给你另一批结果。你平时在网站搜索框里输入、点搜索，背后就是程序把你输入的词拼进接口的地址里，然后访问。

---

接口是前后端之间唯一的通道，它是一个约定好的地址，返回约定格式的数据，有时候要带参数、带密钥。

## 几个常见的误解

**「接口就是网址。」** 网址是给人看的网页地址，接口是给程序取数据的地址。两者长得像，但接口返回的是 JSON 数据，不是网页。

**「调接口很难，要懂很多。」** 会看地址、会看 JSON，就能上手。真正难的是「出了问题知道去哪查」，「调」本身不难。

**「密钥可以随便放在代码里。」** 密钥泄露等于把钥匙交出去。放在代码里、提交到公开仓库里，都等于公开。要当成银行卡密码保管。

**「接口返回的数据就是对的。」** 接口背后也是别人的程序，也会出错、会返回空、会超时。拿到数据先检查，这是习惯。
