# 服务器 · 精通版

前后端初识 · 第 5 站

时间：2 小时到 2 个半小时。动手 90 分钟，留 40 分钟等服务器初始化、自己调试。

做完你会有一个：一个跑在公网上的服务，把地址发到手机上也能打开。

---

## 先把东西装上

下面要用两个工具，Mac 和 Windows 都已经有了，不用额外装。

一个是连服务器用的 `ssh`，一个是传文件用的 `scp`。

打开终端（Windows 用 Git Bash，Mac 用系统自带终端），敲：

```
ssh -V
```

看到类似 `OpenSSH_10.2p1` 这样一行字，就说明有了。版本号不一样没关系。

如果提示「不是内部或外部命令」，说明你打开的不是 Git Bash。Windows 上一定要用 Git Bash，只有它里面带这些 Linux 工具。

---

## 上一站那个服务，还差一步

上一站你写了一个 `server.js`，跑在自己电脑上，浏览器访问 `localhost:3000` 能看到你返回的数据。

但你把地址发给同学，同学打不开。

原因你已经知道：你的服务只跑在你自己的电脑上，你一合上笔记本它就不在了。而且你的电脑在局域网里，外面的人连不进来。

这一站做的事，就是把这个服务搬到一台一直开着、外面能连进来的电脑上。那台电脑就是服务器。

---

## 连上另一台电脑

服务器没有屏幕、没有键盘。你操作它的唯一办法，是从自己的电脑「连过去」。

这个动作叫**远程登录**，用的工具是 `ssh`。

它做的事一句话能说清：你在自己电脑上敲命令，命令通过网线发到服务器上执行，结果再传回来显示在你的屏幕上。你面前的窗口还是那个窗口，但敲的每一条命令，是在另一台电脑上跑的。

打开终端敲：

```
ssh 用户名@服务器地址
```

这一句现在先不用真的敲，你还没有服务器。先看它长什么样，下面会真的做。

连上之后，终端提示符会变，从你自己电脑的名字换成服务器的名字。从那一刻起，你敲的每一条命令都在服务器上执行。

---

## 先在自己电脑上练：让服务后台跑

在去买服务器之前，先解决一件更基础的事。

上一站你跑 `node server.js` 的时候，那个终端窗口被占住了，一按 Ctrl 加 C 服务就停。这在你自己的电脑上没问题，但服务器上不能这样，你不能开着一个窗口挂一晚上。

真实的做法是让服务**在后台跑**，不占着窗口。用的命令是 `nohup`。

先回到上一站那个文件夹：

```
cd ~/我的服务
```

如果你的文件夹在别的位置，换成你自己的路径。敲这一句：

```
nohup node server.js > app.log 2>&1 &
```

屏幕上会跳出一行，像这样：

```
[1] 60514
```

`60514` 是**进程号**，就是这个服务在系统里的编号。记住它，后面停掉它要用。

这行命令拆开看：`nohup` 的意思是「别挂断」，让你关掉窗口之后程序继续跑。最后那个 `&` 是「放到后台」。中间 `> app.log 2>&1` 是把程序的输出写进一个叫 `app.log` 的文件，而不是打在屏幕上。

现在你的终端空出来了，可以继续敲别的命令。打开浏览器访问 `localhost:3000`，服务还在。

### 看它是不是真的在跑

敲：

```
ps aux | grep server.js
```

你会看到类似这样的一行：

```
root     60514  0.0  0.4  60488  8000 pts/0  S  14:20  0:00 node server.js
```

开头那个 `60514` 就是进程号，和刚才屏幕上跳出来的一样。这行字的意思是：有一个叫 node 的程序在跑 server.js。

### 看它记了什么

服务跑起来之后，如果出了什么情况，它会写进 `app.log`。看这个文件：

```
tail app.log
```

你会看到：

```
服务起来了，端口 3000
```

`tail` 是「看一个文件的最后几行」。

### 停掉它

```
kill 60514
```

把 60514 换成你屏幕上看到的那个进程号。再访问 `localhost:3000`，就连不上了，说明服务停了。

**这一小段就是服务器上管理服务的基本功**：起服务、看进程、看日志、停服务。到了真的服务器上，做的事一模一样，只是命令在另一台电脑上执行。

---

## 租一台服务器

现在去弄一台真的服务器。

在浏览器里搜「云服务器 学生优惠」。几家大厂都有学生套餐，一年几十块，最低配就够这一站用了。

注册之后下单，注意三个地方：

**系统选 Ubuntu。** 版本选最新的长期支持版就行。不选 Windows，因为这一站的命令都是 Linux 的。

**配置选最低那档。** 1 核 2G 内存就够，跑一个网页服务绰绰有余。

**设置一个密码。** 下单或者初始化的时候会让你设 root 密码。root 是服务器的管理员账号，相当于这台电脑的最高权限。密码设一个你能记住的，后面连服务器要输。

下单之后等几分钟，系统初始化完成，你会拿到一个**公网 IP 地址**，长得像 `1.2.3.4` 这样。这就是你那台服务器在互联网上的门牌号，别人访问它就靠这个。

---

## 连上去

现在真的敲那句 ssh 了。打开终端：

```
ssh root@1.2.3.4
```

把 `1.2.3.4` 换成你自己的公网 IP。`root` 是用户名，@ 后面是地址。

第一次连接，屏幕上会出现：

```
The authenticity of host '1.2.3.4 (1.2.3.4)' can't be established.
ED25519 key fingerprint is SHA256:xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx.
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

敲 `yes` 再回车。

这行字是在问你「认不认识这台机器」。第一次连，当然不认识，所以它让你确认一下。敲 yes 之后它会记住这台机器，下次连就不再问了。

然后提示：

```
root@1.2.3.4's password:
```

敲你设的密码。**屏幕上不会显示任何字符**，光标也不动，这是正常的，输完直接回车。

成功之后，你会看到一串欢迎文字，最后停在一个命令提示符上。从这一刻起，你敲的每一条命令都在那台服务器上执行。

---

## 把文件传上去

现在要把上一站写的 `server.js` 传到服务器上。用的工具是 `scp`。

先在服务器上建个文件夹放代码。你现在应该已经在服务器里了（提示符是服务器的名字），敲：

```
mkdir /root/myapp
```

`mkdir` 是「建文件夹」，`/root/myapp` 是路径，放在 root 账号的主目录下面。

然后回到你自己的电脑。敲 `exit` 退出服务器：

```
exit
```

提示符变回你自己电脑的样子。现在敲这一句，把文件传过去：

```
cd ~/我的服务
scp server.js root@1.2.3.4:/root/myapp/
```

`scp` 的用法和 `ssh` 很像，中间多一个「把哪个文件传到哪」。它会再问一次密码，输完，文件就传上去了，屏幕上会显示一个传输进度。

---

## 在服务器上把它跑起来

再连回服务器：

```
ssh root@1.2.3.4
```

进去之后，先给服务器装 Node.js。这台新机器上什么都没有，得自己装。敲：

```
apt update
```

等它跑完（一两分钟），再敲：

```
apt install -y nodejs
```

这两句是在服务器的系统里装 Node。屏幕上会刷很多行下载的字符，最后回到提示符就是装好了。

验证一下：

```
node --version
```

看到版本号就行。然后进到放代码的文件夹：

```
cd /root/myapp
```

把服务后台跑起来，跟你在自己电脑上练的一模一样：

```
nohup node server.js > app.log 2>&1 &
```

---

## 让外面能访问

还差最后一步：服务器的防火墙。

云服务商默认会把大部分端口关掉，你得手动把自己要用的那个端口打开。

登录云服务商的控制台（就是浏览器里那个网页后台），找到「安全组」或者「防火墙」的设置，把 **3000 端口**放行。具体入口每家不太一样，搜「云服务器 打开端口」加上你买的那家名字，照着做。

放行之后，打开你电脑的浏览器，访问：

```
http://1.2.3.4:3000
```

看到你返回的数据，就成了。

现在把地址发到你手机上，注意手机要**用流量**，别连宿舍同一个 WiFi。手机浏览器打开，一样能看到。

**这一刻你已经把一个东西放到了公网上。** 全世界任何一台能上网的设备，访问那个地址，都能拿到你写的数据。

---

## 动手任务

一、在你自己的电脑上，用 `nohup` 把上一站的服务后台跑起来，再用 `ps`、`tail`、`kill` 分别做一遍看进程、看日志、停服务。

二、租一台学生服务器，拿到公网 IP 和密码。

三、用 `ssh` 连上去，用 `scp` 把 server.js 传上去。

四、在服务器上装好 Node，把服务后台跑起来。

五、打开防火墙端口，用手机流量访问，确认能打开。

六、把服务器上的服务停掉，再访问一次，确认它真的停了，你能解释为什么。

## 正式产出

**一个跑在公网上的服务，手机用流量能访问到。**

要求：

- 服务跑在服务器上，不是你自己电脑上
- 用 `nohup` 后台启动，关掉终端窗口服务还在
- 防火墙端口放行正确，外面能访问
- 用 `tail` 能看到服务的日志
- 用 `kill` 能把它停掉，停掉之后访问不到

---

## 卡住了看这里

**`ssh` 提示 `Permission denied`。** 密码敲错了。注意输密码时屏幕不显示，输完直接回车。连续错几次之后可能被临时锁定，等几分钟再试。

**`ssh` 提示 `Connection refused` 或者一直转圈连不上。** 三件事：公网 IP 有没有抄错；服务器有没有真的初始化完成（控制台里看状态）；你本地的网络有没有代理开着，代理可能把 ssh 的流量也拦了，先关掉代理再试。

**`scp` 提示 `No such file or directory`。** 你当前不在那个文件夹里，或者文件名打错了。先 `ls` 看一眼当前目录里有没有 server.js。

**服务器上 `node --version` 提示找不到命令。** Node 没装上。重新跑一遍 `apt install -y nodejs`，等它完整跑完。

**访问 `http://公网IP:3000` 打不开。** 按顺序查：服务在服务器上有没有跑（`ps aux | grep server.js`）；防火墙端口放行没有；代码里监听的是不是 `0.0.0.0` 而不是 `localhost`（上一站讲过，localhost 只接受本机访问）。

**改了代码，服务器上还是旧样子。** 服务器不会自动同步你电脑上的文件。改完要重新 `scp` 传一次，再 `kill` 掉旧进程重新启动。

**`kill` 之后访问还是打不开，但进程号变了。** 服务可能被系统重启了，或者你 `kill` 的是旧的进程号。再 `ps` 看一次，用最新的进程号。

---

## 走完之后

这一站你把前面几站串起来了：写的代码，第一次真正跑在了「别人能访问到」的地方。

服务器管理就是这些动作的重复：起服务、看进程、看日志、停服务、传文件。真实工作里工具会更多、更复杂，但核心就这五件事。

判断自己对不对路子，看一个瞬间：当你用手机流量打开那个地址、看到数据的那一刻，有没有觉得「原来是这样」。如果那一刻你觉得踏实、想继续搞明白为什么，运维和部署这条线适合你往下走。

## 想再往下看

每次都手动 `nohup`、`kill`，时间长了会烦。有个工具叫 `pm2`，专门管 Node 服务，能自动重启、能看状态、能开机自启。搜「pm2 快速上手」。

想了解「这台服务器为什么会一直开着、停电了怎么办」，去看云服务那一站（第 11 站），讲的是机房和虚拟化。
