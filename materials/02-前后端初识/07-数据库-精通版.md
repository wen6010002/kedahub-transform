# 数据库 · 精通版

前后端初识 · 第 7 站

时间：1 个半小时到 2 小时。动手 80 分钟，留 30 分钟自己改着玩。

做完你会有一个：一个自己的成绩管理小库，能增删改查、能按分数筛选、能备份。

---

## 先把东西装上

这一站用 SQLite。它是个完整的数据库，但不需要装服务器、不用联网，整个库就是一个文件，最适合新手。

**Mac** 系统自带。打开终端，敲 `sqlite3 --version`，看到版本号就是有了。

**Windows** 需要下载一个免安装的小工具：

1. 浏览器搜「sqlite download」，进官网 sqlite.org
2. 找「Precompiled Binaries for Windows」，下面有个叫 `sqlite-tools-win-x64` 的压缩包，下载
3. 解压，里面有个 `sqlite3.exe`
4. 把它放到一个你记得住位置的文件夹，比如 `C:\sqlite\`

装好之后打开终端：Mac 用系统自带终端，Windows 用 Git Bash。

**这一站所有 `sqlite3` 命令，Windows 用户都在前面加 `./`**（也就是敲 `./sqlite3`），因为 Windows 不会自动找到这个程序。Mac 用户直接敲 `sqlite3`。后面我就不每句重复了，你自己记得加。

## 你有一份成绩单想存起来

想象你有这么一份成绩单，想随时查：谁及格了、谁考了多少、谁进步了。

用记事本存，就是几行字：

```
张三 82
李四 91
王五 67
```

看着挺清楚。但你想问「谁没过 80 分」，就得自己一行行看。人一多，眼睛不够用。

这一站用数据库来做这件事：把成绩存进一张表，然后用命令去查，想怎么查就怎么查。

---

## 表、行、列、主键

数据库里存数据的基本单位是**表**。一张表像一张 Excel 表格。

- 竖着的一列叫**列**（也叫字段），比如「姓名」「分数」，每一列存同一种东西
- 横着的一行叫**行**（也叫记录），一行就是一个人的全部信息
- 每张表通常有一个**主键**，就是「唯一标识一行」的那一列，常用自动递增的数字。有了主键，你才能准确地说「改第 3 行的分数」，而不是「改那个叫王五的人」，因为可能有两个人叫王五

这些概念先混个脸熟，下面动手的时候你会一个个用到。

## 第一次动手：建表、存数据、查出来

先建一个文件夹放这一站的东西：

```
mkdir 成绩库
cd 成绩库
```

进入数据库。敲：

```
sqlite3 scores.db
```

`sqlite3` 是程序名，`scores.db` 是你给这个数据库文件起的名字。敲完回车，提示符变成 `sqlite>`，说明你进来了。现在你敲的每一条，都是给这个数据库下指令。

### 建表

敲：

```
CREATE TABLE students (id INTEGER PRIMARY KEY, name TEXT, score INTEGER);
```

回车，什么都没发生。**数据库是静默的，不报错就是成功。**

这句话的意思是：建一张叫 `students` 的表，有三个列。`id` 是整数、是主键；`name` 是文字；`score` 是整数。

### 存三条数据

敲这三句：

```
INSERT INTO students (name, score) VALUES ('张三', 82);
INSERT INTO students (name, score) VALUES ('李四', 91);
INSERT INTO students (name, score) VALUES ('王五', 67);
```

`INSERT INTO` 是「往表里插一条」。注意 `id` 没写，因为它是主键，数据库会自动给你填 1、2、3。

### 查出来

敲：

```
SELECT * FROM students;
```

屏幕上出现：

```
1|张三|82
2|李四|91
3|王五|67
```

`SELECT * FROM students` 是「把 students 表里的所有列都取出来」。（`*` 是「全部」的意思，`;` 是这一句的结尾，SQL 里每句都要带分号。）

**你已经完成了一个数据库最核心的循环**：建表、存数据、查数据。后面所有的本事，都是在这个循环上加花样。

---

## 一层一层加

### 只查某几列

不想看 id，只看名字和分数：

```
SELECT name, score FROM students;
```

```
张三|82
李四|91
王五|67
```

### 按条件查

只看没过 80 分的人：

```
SELECT name, score FROM students WHERE score < 80;
```

```
王五|67
```

`WHERE` 就是「只挑满足条件的行」。`score < 80` 是「分数小于 80」。

### 排序

按分数从高到低排：

```
SELECT name, score FROM students ORDER BY score DESC;
```

```
李四|91
张三|82
王五|67
```

`ORDER BY score` 是按 score 排，`DESC` 是从大到小（反过来是 `ASC`，从小到大，默认就是 ASC）。

### 改一条数据

王五补考过了，把分数改成 95：

```
UPDATE students SET score = 95 WHERE name = '王五';
```

再查一次：

```
SELECT * FROM students;
```

```
1|张三|82
2|李四|91
3|王五|95
```

`UPDATE ... SET ... WHERE` 是「把满足条件的行，改成新值」。**注意那个 `WHERE` 不能省**：不写 WHERE，它会把这表里所有人的分数都改成 95。

### 删一条数据

李四转学了，删掉他：

```
DELETE FROM students WHERE name = '李四';
```

再查：

```
SELECT * FROM students;
```

```
1|张三|82
3|王五|95
```

`DELETE FROM ... WHERE` 是「删掉满足条件的行」。和 UPDATE 一样，**不写 WHERE 会删光整张表**。

### 这些动作合起来，有个名字

建表、增、删、改、查，这五件事合起来，行话叫 **CRUD**（取 Create、Read、Update、Delete 四个词的首字母）。你刚才全做了一遍。

**这是所有程序跟数据库打交道的基本动作。** 一个电商网站、一个社交 App，背后的数据操作拆到底，都是这五件事的排列组合。

## 索引：为什么数据多了也不慢

现在这张表只有两三个人，查什么都是瞬间。但要是十万个学生，每次查询都从头翻到尾，就慢了。

解决办法是建**索引**。索引就像书后面的目录：你查「分数小于 80 的」，数据库不用翻全表，照着索引直接找到那几行。

先看看现在这张表有没有索引（其实主键 id 自动就有索引了，别的列没有）：

```
EXPLAIN QUERY PLAN SELECT * FROM students WHERE score < 80;
```

屏幕上会显示类似 `SCAN students` 这样的字。`SCAN` 的意思是「全表扫描」，也就是从头翻到尾。这就是没索引时的样子。

给 score 这一列建个索引：

```
CREATE INDEX idx_score ON students (score);
```

`idx_score` 是索引的名字，随便起，一般用 `idx_` 开头好认。再跑一次：

```
EXPLAIN QUERY PLAN SELECT * FROM students WHERE score < 80;
```

这次你会看到 `SEARCH students USING INDEX idx_score` 这样的字。`SEARCH ... USING INDEX` 的意思是「用索引找」，不再是全表扫描。

**数据少的时候，索引看不出差别；数据一多，差别是天壤之别。** 真实项目里，一张大表给哪个字段建索引、建几个，是直接影响速度的大事。你只要记住：常用来查的字段，就该考虑建索引。

## 事务：要么全做，要么全不做

还剩最后一件重要的事：**事务**。

场景是转账：从张三账户扣 100，给王五账户加 100。这两步必须一起成功。如果扣钱成功、加钱那步出错，钱就凭空没了。

事务把好几步操作「包在一起」，保证它们要么全部生效，要么全部撤销。

在 SQLite 里这样试。先敲：

```
BEGIN;
```

这是「开始一个事务」。然后随便插两条测试数据：

```
INSERT INTO students (name, score) VALUES ('测试', 100);
INSERT INTO students (name, score) VALUES ('测试2', 100);
```

现在查一下，你会看到这两个「测试」已经在表里了：

```
SELECT * FROM students;
```

```
1|张三|82
3|王五|95
4|测试|100
5|测试2|100
```

别急，敲这一句，把刚才的改动全部撤销：

```
ROLLBACK;
```

再查一次：

```
SELECT * FROM students;
```

```
1|张三|82
3|王五|95
```

那两个「测试」没了。**`ROLLBACK` 的意思是「撤销这个事务里做过的所有事」。** 刚才那两条插入就像没发生过。

如果你确认这一堆操作没问题，想真正保存，就敲 `COMMIT;`，意思是「提交，这些改动正式生效」。

**这就是事务**：BEGIN 开始，中间随便做，最后要么 COMMIT 全部生效，要么 ROLLBACK 全部撤销。银行转账、下单扣库存，靠的全是这个。

## 备份：把库复制走

SQLite 整个库就是一个文件，所以备份特别简单：把这个文件复制一份就行。

先退出数据库：

```
.quit
```

回到普通终端。看看当前文件夹里有什么：

```
ls
```

你会看到 `scores.db`，这就是你的整个数据库，所有数据都在这一个文件里。

备份就是复制它：

```
cp scores.db scores-backup.db
```

`cp` 是「复制」。现在你有两个文件，`scores.db` 是正式的，`scores-backup.db` 是备份。哪天正式的那个出问题，把备份改名换回来就行。

**其他数据库（MySQL、PostgreSQL 那些）没这么简单，它们有专门的备份命令。** 但「定期备份」这件事，对所有数据库都是铁律。

## 动手任务

一、照上面的步骤，把 students 表建出来，插入五个你自己起的名字和分数。

二、用 WHERE 查出所有及格（score >= 60）的人。

三、用 ORDER BY 按分数从低到高排一次。

四、用 UPDATE 把其中一个人的分数改掉，用 DELETE 删掉另一个人，再查一次确认改对了。

五、给 score 建索引，用 EXPLAIN 确认它从 SCAN 变成了 SEARCH。

六、用 BEGIN 插两条数据，再 ROLLBACK，确认数据没真的进去。

## 正式产出

**一个成绩管理小库，能完成增删改查、按分数筛选、按分数排序，并且有一个备份文件。**

要求：

- 表里至少有五个人的数据
- 你能用一条命令查出「分数大于 80 的人」

- 你有一个 `scores-backup.db` 备份文件

## 卡住了看这里

**提示 `Error: near "xxx": syntax error`。** SQL 语句写错了，最常见的是忘了结尾的分号，或者把英文引号打成了中文引号。检查 `;` 和 `'`。

**提示 `no such table: students`。** 表还没建，或者你换了一个数据库文件。确认你 `sqlite3 scores.db` 打开的是同一个文件。

**提示 `table students already exists`。** 你已经建过这张表了，重复建会报错。要么换张新表，要么先 `DROP TABLE students;` 删掉旧的再建。

**INSERT 的时候提示 `datatype mismatch`。** 你往整数列里塞了文字。比如 score 那列你写了 `'八十二'`，改成 `82`。

**SELECT 查出来是空的。** 可能你 ROLLBACK 之后数据回滚了，或者你在另一个数据库文件里。先 `SELECT * FROM students;` 看表里到底有没有数据。

**`.quit` 之后怎么再进去。** 重新敲 `sqlite3 scores.db` 就行，数据都还在文件里。

**忘了 Windows 要加 `./`。** 提示 `command not found` 或者「不是内部或外部命令」，就是忘了。Windows 用户在 sqlite3 前面加 `./`。

## 走完之后

你现在会了数据库最核心的五件事，和一个叫「事务」的保险，一个叫「索引」的加速器。

真实工作里，数据库的操作比这复杂得多，但骨架就是这些。判断自己对不对路子，看一个感觉：当你敲 `SELECT * FROM students WHERE score < 80`，屏幕上精确地跳出那一行的时候，你有没有觉得「数据被管得服服帖帖」。

如果你喜欢这种「把乱糟糟的东西，规整成一张表，然后随时精确取用」的感觉，数据库和后端这条线适合你。
