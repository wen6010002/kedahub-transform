# 后端都包括什么 · 精通版

前后端初识 · 第 4 站

时间：2 小时到 2 个半小时
做完你会有一个：一个跑在自己电脑上的服务，浏览器里敲地址就能取回你自己定义的数据

---

## 第一步：装 Node.js

后端可以用很多种语言写。这一站用 JavaScript，因为你在上一站已经见过它了，而且它跑起来不需要额外装一堆东西。

JavaScript 原本只能在浏览器里跑。有个叫 Node.js 的东西把它搬到了电脑上，让它能写后端。所以我们要装的是 Node.js。

**Windows**

1. 打开浏览器，搜「Node.js 下载」，第一个是官网
2. 官网上有两个版本，选左边那个写着「LTS」的（长期支持版）。右边那个是尝鲜版，不要用
3. 下载 Windows 版，双击安装
4. 一路点「Next」。有一处要注意：装到某一步会有一个选项问你要不要自动安装必要的工具，那个可以跳过，现在用不到
5. 装完，打开 Git Bash

**Mac**

同样搜「Node.js 下载」，下 LTS 版的 macOS 安装包，双击，一路继续。装完打开终端。

**验证装好了没有**

打开终端，敲：

```
node --version
```

看到类似 `v22.22.2` 这样的输出就成功了。看到「不是内部或外部命令」，说明没装好，或者 PATH 没配上，回去重装一遍，注意安装过程里的选项。

再敲一句确认 npm 也装上了（它是 Node 自带的包管理器，后面会用到）：

```
npm --version
```

## 第二步：第一个服务

建一个文件夹放这一站的代码：

```
cd ~
mkdir 我的服务
cd 我的服务
```

用 VS Code 打开：

```
code .
```

新建一个文件，叫 `server.js`，敲进这些内容：

```js
var http = require('http');

var server = http.createServer(function (req, res) {
  res.writeHead(200, { 'Content-Type': 'text/plain; charset=utf-8' });
  res.end('你好，这是我自己写的服务');
});

server.listen(3000, function () {
  console.log('服务起来了，打开 http://localhost:3000 看看');
});
```

存盘。回到终端，敲：

```
node server.js
```

屏幕上出现：

```
服务起来了，打开 http://localhost:3000 看看
```

**注意光标没有回到提示符。** 这说明程序还在跑，它在等着别人来访问。这是正常的，一个服务起来之后就会一直开着。

现在打开浏览器，地址栏里敲：

```
localhost:3000
```

页面上出现「你好，这是我自己写的服务」。

### 刚才发生了什么

`http.createServer` 建了一个服务。括号里那个函数，是「有人来访问的时候要执行的事」。

`res.writeHead(200, ...)` 是告诉浏览器「这次请求成功了，返回的是纯文本」。

`res.end(...)` 是把内容发回去。

`server.listen(3000)` 是让这个服务听 3000 端口。**端口**可以理解成一栋楼里的房间号：这台电脑的地址是固定的，但上面可以同时开很多个服务，各自占一个房间。

`localhost` 是一个特殊的地址，意思是「这台电脑自己」。你在浏览器里访问 `localhost:3000`，就是访问你自己电脑上的 3000 端口。

**要停掉服务**，回到终端按 Ctrl 加 C。

## 第三步：返回数据，而不是一段话

刚才返回的是一句人看的文字。真实的后端返回的是给程序看的数据。

把 `server.js` 改成这样：

```js
var http = require('http');

var items = [
  { id: 1, name: '二手台灯', price: 35 },
  { id: 2, name: '机械键盘', price: 180 }
];

var server = http.createServer(function (req, res) {
  res.writeHead(200, { 'Content-Type': 'application/json; charset=utf-8' });
  res.end(JSON.stringify(items));
});

server.listen(3000, function () {
  console.log('服务起来了，打开 http://localhost:3000 看看');
});
```

存盘，回到终端按 Ctrl 加 C 停掉旧的服务，再敲一次 `node server.js`。

刷新浏览器，你看到的是：

```json
[{"id":1,"name":"二手台灯","price":35},{"id":2,"name":"机械键盘","price":180}]
```

**这就是后端返回的数据。** 上一站你在 GitHub 的接口里看到的也是这个东西。

`JSON.stringify` 的作用是把 JavaScript 里的数组转成一段文本，因为网络上传的只能是文本。

那一行 `Content-Type: application/json` 是告诉浏览器「我发的是 JSON，你按数据来解析，别当网页显示」。

## 第四步：加上路由

现在不管访问什么地址，返回的都是同一份数据。这不叫服务，这叫复读机。

**路由**就是「根据不同的地址，做不同的事」。改 `server.js`：

```js
var http = require('http');

var items = [
  { id: 1, name: '二手台灯', price: 35 },
  { id: 2, name: '机械键盘', price: 180 }
];

var server = http.createServer(function (req, res) {

  if (req.url === '/api/items') {
    res.writeHead(200, { 'Content-Type': 'application/json; charset=utf-8' });
    res.end(JSON.stringify(items));
    return;
  }

  if (req.url === '/') {
    res.writeHead(200, { 'Content-Type': 'text/html; charset=utf-8' });
    res.end('<h1>欢迎</h1><p>试试访问 <a href="/api/items">/api/items</a></p>');
    return;
  }

  res.writeHead(404, { 'Content-Type': 'text/plain; charset=utf-8' });
  res.end('没有这个地址');
});

server.listen(3000, function () {
  console.log('服务起来了，打开 http://localhost:3000 看看');
});
```

`req.url` 就是用户访问的那个地址。

现在重启服务，试试这三个地址：

```
localhost:3000
localhost:3000/api/items
localhost:3000/abc
```

第一个显示欢迎页，第二个返回数据，第三个显示「没有这个地址」。

**这就是所有后端路由的基本形态**：看请求的地址是什么，决定返回什么。真实的框架（Express、Koa 这些）只是把这一堆 `if` 换成了更好写的写法，本质没变。

## 第五步：让它能接收数据

前面都是「你问我要，我给你」。真实的后端还要能「接收你发来的东西」。

加上这一段（放在两个 `if` 之间）：

```js
  if (req.url === '/api/items' && req.method === 'POST') {
    var body = '';
    req.on('data', function (chunk) { body = body + chunk; });
    req.on('end', function () {
      var newItem = JSON.parse(body);
      newItem.id = items.length + 1;
      items.push(newItem);
      res.writeHead(201, { 'Content-Type': 'application/json; charset=utf-8' });
      res.end(JSON.stringify(newItem));
    });
    return;
  }
```

这段代码做的事：如果收到的是一个 POST 请求，就把用户发来的内容攒起来（`req.on('data')` 可能被调用多次，所以要拼起来），等收完了（`req.on('end'`），解析成对象，加个 id，塞进数组，返回刚加进去的那条。

**注意上面那个 `if` 要放在原来那个 `/api/items` 的 `if` 前面**，否则 GET 的判断会先把请求接走。

浏览器地址栏只能发 GET 请求，要发 POST 得用别的办法。在终端里敲这一句（服务要开着）：

```
curl -X POST http://localhost:3000/api/items -H "Content-Type: application/json" -d '{"name":"二手书","price":12}'
```

它会返回刚加进去的那条：

```json
{"name":"二手书","price":12,"id":3}
```

再访问一次 `localhost:3000/api/items`，你会发现二手书在里面了。

（`curl` 是终端里的一个工具，专门用来发 HTTP 请求。Windows 的 Git Bash 里自带了。）

**数据存在内存里，所以服务一重启就没了。** 这正好说明为什么需要数据库，第 7 站会讲。

## 完整的文件

把前面几步合起来，`server.js` 最终长这样：

```js
var http = require('http');

var items = [
  { id: 1, name: '二手台灯', price: 35 },
  { id: 2, name: '机械键盘', price: 180 }
];

var server = http.createServer(function (req, res) {

  if (req.url === '/api/items' && req.method === 'POST') {
    var body = '';
    req.on('data', function (chunk) { body = body + chunk; });
    req.on('end', function () {
      var newItem = JSON.parse(body);
      newItem.id = items.length + 1;
      items.push(newItem);
      res.writeHead(201, { 'Content-Type': 'application/json; charset=utf-8' });
      res.end(JSON.stringify(newItem));
    });
    return;
  }

  if (req.url === '/api/items') {
    res.writeHead(200, { 'Content-Type': 'application/json; charset=utf-8' });
    res.end(JSON.stringify(items));
    return;
  }

  if (req.url === '/') {
    res.writeHead(200, { 'Content-Type': 'text/html; charset=utf-8' });
    res.end('<h1>欢迎</h1><p>试试访问 <a href="/api/items">/api/items</a></p>');
    return;
  }

  res.writeHead(404, { 'Content-Type': 'text/plain; charset=utf-8' });
  res.end('没有这个地址');
});

server.listen(3000, function () {
  console.log('服务起来了，打开 http://localhost:3000 看看');
});
```

## 动手任务

一、把上面的代码敲一遍，跑起来。不要复制粘贴，手敲能让你记住 `require`、`createServer`、`listen` 这几个东西长什么样。

二、改数据。把 `items` 里的东西换成你自己想放的，比如你的书单、你玩过的游戏。

三、加一条路由。加一个 `/api/about`，返回一个对象，里面有你的名字和学校。

四、加一个查询。加一条 `/api/items/search`，从地址里取参数，只返回名字里含那个词的数据。提示：`req.url` 会带上参数，比如 `/api/items/search?q=键盘`，用字符串切分把它取出来。

五、故意制造一个错误。把 `JSON.stringify(items)` 写成 `JSON.stringify(item)`（少个 s），看会发生什么。屏幕上的报错信息会告诉你哪一行出错。改回来。

## 正式产出

**一个跑在自己电脑上的服务，别人访问你定义的地址能拿到你自己定义的数据。**

要求：

- 至少三条路由：一个首页、一个返回列表的接口、一个接收数据的接口
- 返回 JSON 的时候设了正确的 `Content-Type`
- 访问不存在的地址返回 404，不是直接崩掉
- 用 `curl` 发一个 POST 请求，数据能存进去
- 重启服务之后数据没了，你能解释为什么

重点看最后一条。数据存在内存里，程序一关就没了。想让它留下来，就需要数据库，下一站开始讲。

## 卡住了看这里

**`node --version` 提示「不是内部或外部命令」。** Node.js 没装好，或者 PATH 没配上。重新运行安装包，选「Repair」，注意装的过程中勾选 PATH 相关的选项。装完重开一个终端窗口。

**`Error: listen EADDRINUSE`。** 3000 端口被占了，多半是你上一个服务还在跑。回到那个终端按 Ctrl 加 C 停掉，或者把代码里的 3000 改成 3001。

**改了代码，刷新浏览器没变化。** Node.js 不会自动重载。改完要回终端按 Ctrl 加 C，再 `node server.js` 重跑一遍。

**浏览器显示的是乱码。** `Content-Type` 里少了 `charset=utf-8`。中文必须加这一段。

**POST 请求返回 404。** 检查两件事：POST 的那个 `if` 有没有放在 GET 前面，以及 `curl` 命令里的 `-X POST` 有没有写。

**`JSON.parse` 报错。** 用户发来的内容不是合法的 JSON。`curl` 里 `-d` 后面那段要保证是标准 JSON 格式，双引号不能写成中文引号。

**端口是什么，为什么是 3000。** 端口是同一台电脑上区分不同服务的编号。3000 是开发时常用的，随便换一个别的数字也行，只要不跟别的服务撞上。

**服务跑起来之后终端动不了。** 这是正常的，服务占着这个终端。要执行别的命令就再开一个终端窗口。

## 走完之后

后端和前端的感觉完全不同。

前端是「改一下，刷新，立刻看到」。后端是「改一下，重启，用工具发个请求，看返回什么」。反馈慢，而且看不见界面，只有数据。

判断自己对不对路子，看两件事：刚才调那个 POST 请求的时候，你有没有耐心一遍遍改、一遍遍用 curl 试；看到返回的 JSON 里数据真的变了，你有没有觉得踏实。

后端的工作大部分时间在处理「什么情况下会出问题」。这一站你只写了正常情况，真实项目里，同样一段逻辑，处理异常的代码可能比正常的多一倍。

## 想再往下看

真实的项目不会用 `http` 模块直接写，会用框架。Node.js 生态里最常用的是 Express，它把上面那些 `if` 换成了更清楚的写法。

想试试的话，搜「Express 快速上手」，在现在这个文件夹里敲 `npm init` 和 `npm install express`，然后照着官网的第一个例子写一遍。你会发现代码短了很多，但做的事跟刚才一样。

再往后就是数据库了。数据存内存里，一重启就没，这是现在这个方案最大的限制。下一站开始解决这个问题。
