## 两个人同时改，后保存的覆盖先保存的

你和你室友做一个小组作业，两个人同时打开同一个 Word 文档，各自改各自的部分。

你改完保存，他也改完保存。结果后保存的那个人，把先保存的那个人的修改覆盖掉了，前面那个人白改。

你俩顶多互相瞪一眼。但一个网站的数据是几百、几千个人同时在操作，要是都用「一个文件、谁后存谁赢」的办法，天天出这种事故。

数据库就是来解决这件事的。

---

## 数据其实就存在硬盘上

先讲一件你可能没意识到的常识。

上一站你写的那个服务，数据存在内存里，服务一重启就没了。要让它重启之后还在，得把数据写进硬盘上的文件。

所以「数据存哪」这个问题的答案，最终都是硬盘。数据库也不例外，它也是把数据写进硬盘上的文件。

区别在于：**你自己存文件，是把数据随便丢进一个记事本；数据库存，是把数据整齐地摆进一张张表，而且有人专门管着怎么摆、怎么找、怎么不丢。**

这就像你的作业，可以直接一堆纸塞进抽屉，也可以按科目、按日期分类装进文件夹。都能放，但找起来速度差很多。

---

## 为什么不能直接存文件

数据库就是「存数据的程序」。它干的事，用一个具体例子最好懂。

假设你要存一个学校所有学生的信息，用记事本存，一行一个学生：

```
张三,男,18,计算机系
李四,女,19,数学系
```

看起来没问题。但真要用了，麻烦就来了。

**第一个麻烦：好几个人同时写会乱。** 两个老师同时往这个文件里加学生，可能一个把另一个写的东西覆盖掉。你那个 Word 文档的教训，在这里天天发生。

**第二个麻烦：找一条数据要翻遍整个文件。** 想找「计算机系所有 18 岁的学生」，程序只能从第一行翻到最后一行，一行行比对。一千个学生还好，一千万个学生，每次查询都翻一千万行，慢到你等不了。

**第三个麻烦：没有权限控制。** 谁都能打开这个文件，谁都能改。你没法说「这个文件只有教务处的账号能改，学生只能看自己的那行」。

**第四个麻烦：存到一半断电，文件就坏了。** 程序正在写文件，突然断电，文件可能写了一半，打开是一堆乱码。

数据库把这四个麻烦全解决了。它做的事，是把「存、找、改、删」这四件事交给一套专门的系统去管，不是把数据塞进更整齐的记事本。

---

## 数据库多做了四件事

**第一，索引。** 就是「目录」。你给「系」这一列建个索引，数据库就会偷偷维护一张「计算机系在哪几行」的表。以后查「计算机系的学生」，它不用翻全表，直接照着索引找。这就是为什么数据库里查一千万条数据也能瞬间出结果，跟翻记事本完全不是一个速度。

**第二，事务。** 就是「要么全做，要么全不做」。比如转账：从你的账户扣一百，往别人账户加一百。这两步必须一起成功。如果扣钱成功、加钱那步出错，你的钱就凭空没了。事务保证这两步绑在一起，任何一步失败，整个操作撤销，钱原样退回。

**第三，并发控制。** 就是「同时写，不互相覆盖」。回到开头那个场景：两个老师同时加学生，数据库会排队或者上锁，保证两个人的操作都完整记进去，谁都不被覆盖。

**第四，备份。** 数据存在硬盘上，但硬盘会坏。数据库能定期把数据复制一份到别的地方，硬盘真坏了，用备份恢复。

---

## 一个真实的场景

一个电商网站，用户点「下单」，背后发生的不止一件事。

要扣库存（这件商品少一件），要生成订单，可能还要扣用户的优惠券。这三件事必须一起成功。如果扣了库存、生成了订单，结果扣优惠券那步报错，整个下单就乱套了：东西少了，但用户没收到完整的订单信息。

数据库的**事务**在这里起作用：这三步包在一起，全成功才提交，任何一步失败就一起撤销。

做后端的人花很多时间在处理这类「数据不能乱」的问题。一个网站可以页面丑一点，但数据一旦错了、丢了、对不上了，用户会立刻不信任它。

**数据是网站最值钱的东西，比代码值钱。** 代码坏了可以重写，数据丢了就是真丢了。

## 它的边界

**数据库不是万能的。** 它负责「存得对、找得快、不丢」，但「这条数据是什么意思、该怎么用」是程序的事，数据库不管。你不能指望它替你想明白业务。

**不是所有数据都该进数据库。** 一张图片、一个视频，通常直接存硬盘上的文件系统，数据库里只存「文件在哪」这个地址。把大文件塞进数据库，反而又慢又贵。

**不是数据越多，越该用一个超大数据库。** 不同的数据有不同的存法，有的适合表格，有的不适合。下一站专门讲这个。

## 让 AI 帮你做
让 AI 帮你写数据库操作，把下面这几件事交代清楚：

第一，数据长什么样。别只说「存学生」，要说出有哪些字段：名字、年龄、系、分数，各是什么类型。

第二，你之后要按什么查。是常按名字查，还是常按系查。这决定要不要建索引、给哪个字段建。

第三，同时会有多少人用。几个人用的个人工具，和一个几千人用的网站，做法不一样。

拿到 AI 给的东西，先看三处：

**一看表结构。** 字段名是不是你要的，有没有漏。类型对不对（年龄是数字，别存成了文字）。

**二看它有没有建索引。** 没有的话，数据一多查询会慢。

**三自己跑一遍增删改查。** 先在一份测试数据上试，别直接在你真正要用的数据上试。出错了，把报错原文丢回给 AI。

## 先把东西装上

这一站用 SQLite。它是个数据库，但特别轻，不用装服务器、不用联网，就是一个文件，最适合新手练手。

**Mac** 系统自带，直接打开终端就能用。

**Windows** 需要下载一个免安装的小工具。步骤：

1. 浏览器搜「sqlite download」，进官网 sqlite.org
2. 找页面上的「Precompiled Binaries for Windows」，下面有一个叫 `sqlite-tools-win-x64` 的压缩包，下载它
3. 解压，里面有个 `sqlite3.exe`
4. 把这个 `sqlite3.exe` 放到一个你记得住位置的文件夹里，比如 `C:\sqlite\`

装好之后，Windows 打开 Git Bash，先 cd 进那个文件夹：

```
cd /c/sqlite
```

然后这一站所有 `sqlite3` 命令，在 Git Bash 里都敲 `./sqlite3`（前面多个 `./`）。Mac 用户直接敲 `sqlite3`。

## 自己试一下

先建一个练习用的文件夹，进去：

```
mkdir 数据库练习
cd 数据库练习
```

敲这一句，进入数据库：

```
sqlite3 school.db
```

（Windows 用户敲 `./sqlite3 school.db`。）

屏幕上出现 `sqlite>` 这样的提示符，说明你进来了。现在你敲的每一条，都是给这个数据库下指令，不再是给电脑下命令。

敲第一句，建一张表：

```
CREATE TABLE students (name TEXT, age INTEGER);
```

回车，什么都没有发生。这是正常的，数据库建表是静默的，不报错就是成功。

再敲三句，塞三个学生进去：

```
INSERT INTO students VALUES ('张三', 18);
INSERT INTO students VALUES ('李四', 19);
INSERT INTO students VALUES ('王五', 20);
```

现在敲这一句，把数据取出来看：

```
SELECT * FROM students;
```

屏幕上出现：

```
张三|18
李四|19
王五|20
```

**这就是数据库和记事本最根本的区别。** 你刚才用一条命令，就把数据整齐地摆进了表里，又用一条命令把它们取了出来。换成记事本，你得手动敲三行字，还得自己盯着别敲错。

再试试精准地找一个人：

```
SELECT * FROM students WHERE age = 19;
```

屏幕上只出现：

```
李四|19
```

**你刚才做的事叫「按条件查询」**，就是「把所有 19 岁的人捞出来」。数据一多，这就是数据库最值钱的本事：不用翻，直接定位。

最后退出。敲：

```
.quit
```

回到普通终端。

---

数据要整齐地存进表里，用命令去增、删、改、查，而且数据库帮你保证同时写不乱、找得快、断了能恢复。

## 几个常见的误解

**「数据库就是个高级点的 Excel。」** 表格的样子确实像，但差在三件事：Excel 你一个人打开改，数据库几百人同时写也不乱；Excel 数据一多就卡，数据库靠索引能瞬间定位；Excel 断电可能没保存，数据库有事务和备份。

**「数据存进硬盘就不会丢了。」** 硬盘本身会坏，机房着火、被雷劈都有。所以数据库才要定期备份，把数据复制到别的地方。

**「我以后用不到数据库。」** 只要写程序，几乎一定会碰到。哪怕你只做前端，调别人的接口，接口背后的数据也存在数据库里。迟早要懂一点。

**「一个数据库解决所有问题。」** 数据库分好几类，各有各擅长的。下一站专门讲这个。
