## 你看见的那一页，是三种文件拼出来的

打开任何一个网页，你看到的是一整页东西：有文字、有颜色、有按钮。

但在浏览器眼里，这一页是三种文件拼起来的。

一种管**有什么**。一种管**长什么样**。一种管**点了之后会发生什么**。

这三种文件各有各的写法，合起来叫前端技术栈。这一站把它们分开讲清楚。

## HTML：决定有什么

HTML 是网页的骨架。

它用一种尖括号的写法，把内容标出来。比如：

```html
<h1>我的第一个网页</h1>
<p>这是一段话。</p>
<button>点我</button>
```

`<h1>` 表示「这是一级标题」，`<p>` 表示「这是一段话」，`<button>` 表示「这是一个按钮」。

浏览器读到这些标记，就知道该怎么摆：标题要大字加粗，段落要单独占一块，按钮要长得能点。

**HTML 只描述内容是什么，不管它长什么样。** 同样一个 `<h1>`，可以是黑色大字，也可以是红色斜体，取决于下一层。

## CSS：决定长什么样

CSS 管样式：颜色、大小、间距、位置、圆角、阴影、动画。

它和 HTML 是分开的两份东西。HTML 说「这里有个标题」，CSS 说「所有标题用 32 号字、加粗、颜色是深灰」。

分开的好处是：**同一个内容可以换一整套样子，而不用动内容。**

网站改版就是这个意思。内容一个字没变，换一份 CSS，整个网站看起来就不一样了。公司的官网经常这么干。

CSS 里最花时间的是**排版**，颜色和字体反而是最简单的。两个东西怎么摆在一行、间距留多少、窗口变小了怎么自动换行、手机上怎么显示成竖排，这些没有标准答案，要靠经验调。

## JavaScript：决定点了之后发生什么

前两个都是「死」的。HTML 和 CSS 只能描述一个静止的画面。

JavaScript 是让页面动起来的那一层。

你点一个按钮，弹出一个窗口；你往下滚，顶部导航栏变成了半透明；你填表单，密码太短会立刻标红；你在搜索框打字，下面自动跳出候选词。这些都是 JavaScript 干的。

它和另外两种的区别在于：**HTML 和 CSS 是描述，JavaScript 是执行。** 它会根据情况做判断、做计算、改页面上的内容。

现在网页里跑的程序越来越复杂。有些网站的 JavaScript 代码有几百万行，跟一个桌面软件的规模差不多。

## 框架是什么，为什么要有

你写三个页面，用原生的写法没问题。

写三十个页面，问题就来了：同样的代码抄了三十遍，改一处要改三十个地方。页面之间跳来跳去，数据怎么传，谁该负责什么，很快就乱了。

**框架就是解决这个问题的。** 它给你一套组织代码的规矩，帮你把重复的部分抽出来，把数据的变化自动反映到页面上。

现在用得多的几个：React、Vue、Svelte。国内 Vue 用得特别多。

框架带来的好处很明显：代码好维护、开发快、团队协作有共同语言。

代价也有：要学一套新的概念、项目变复杂、打包和构建多了一层。**一个小网页用框架是杀鸡用牛刀。**

## 一个真实的场景

一个学生要给学院的社团做一个网站。他的想法是「先做首页，再做介绍页，再做活动页」。

他花了两周做完首页，样式调得很漂亮。做介绍页的时候，他把首页的代码复制了一份，改内容。做活动页的时候又复制了一份。

三个页面做完了，老师看了一眼说：「导航栏的间距有点大，能不能调小一点。」

他打开了三个文件，改了三个地方。

过了一周，老师又说：「主色换成学院的新颜色吧。」

他打开了三个文件，改了三个地方。改到第二个的时候发现，第一个文件里的颜色写成了 `#ff6b4a`，第二个写成了 `#FF6B4A`，第三个写成了 `rgb(255,107,74)`。三个地方写的是同一个颜色，但写法不一样，他得搜三次。

**这就是不用框架、也不整理代码的代价。** 页面一多，改一个东西要改很多地方，而且容易漏。

后来他把共用的部分（导航栏、页脚、颜色定义）抽出来放到一个地方，其他页面引用它。之后再改，只改一处。

框架做的就是这件事，只是它做得更系统。

## 它的边界

**前端能做的事有上限。** 它能做出漂亮的界面和流畅的交互，但做不了这些：把数据长期保存下来（刷新就没了）、让两台电脑之间传数据、验证用户的身份是真的。这些都要后端。

**前端代码是公开的。** 用户在浏览器里按 F12 就能看到你写的所有代码。所以**永远不要把密码、密钥、内部地址写在前端**。这一条是硬规定，不是提醒。

**前端不等于做设计。** 很多人以为前端就是调颜色、抠像素。实际上前端一半以上的时间在处理数据和状态：这个按钮该不该显示、用户没登录怎么办、网络断了怎么提示、数据还没回来的时候页面显示什么。

**框架会过时。** 十年前流行的一批框架现在基本没人用了。基础的三样（HTML、CSS、JavaScript）反而没怎么变。所以基础扎实比会某个框架重要。

## 让 AI 帮你写页面
**前端是最好上手的方向，因为反馈最快。** 你改一行，刷新一下，立刻看到结果，不用等编译、不用配置环境。

**让 AI 帮你写页面的时候，要说清三件事**：

要什么内容（这个页面是干什么的、放哪些东西）。

要什么风格（简洁还是活泼、主色是什么、参考哪个网站的样子）。

要什么尺寸（电脑上还是手机上，还是都要）。

**拿到代码之后，先在浏览器里打开看看。** 如果效果不对，把截图和你的要求一起给 AI，让它改。这样来回两三次就能调到满意。

**几个能照做的办法**：

想改一个网站的颜色，不用会写代码。按 F12，点 Elements，选中那个元素，在右边的 Styles 里改颜色，当场就能看到效果。改坏了刷新一下就恢复。

想让 AI 给你做一个页面，可以先找一个你喜欢的网站，把它的截图发给 AI，说「做一个类似的，内容是 XX」。

**一条原则**：前端代码里出现的任何密码、密钥、内部接口地址，都是给别人看的。要放这些东西，必须放后端。

## 自己试一下

这一站最爽的地方：**你可以当场改任何一个网页，包括别人的。**

### 改一段文字

随便打开一个网页，比如你学校的官网。

按 F12 打开开发者工具（Mac 上是 Command 加 Option 加 I）。

在面板左上角找到一个像小箭头点方块的图标，点它。然后去网页上点一段文字。

开发者工具会跳到那段文字对应的 HTML。

现在双击那段文字，把它改成你想要的内容，比如改成「这是我改的」。

回车。

**网页上的文字变了。**

### 改一个颜色

还是刚才选中的那个元素，看右边有一个 Styles 面板（中文版叫「样式」）。

里面有一行写着 `color:` 或者 `background-color:`，后面跟着一个颜色小方块。

点那个小方块，选一个别的颜色。

**网页上的颜色当场变了。**

### 想想刚才发生了什么

你没有下载任何东西，没有装任何软件，也没有登录那个网站的管理后台。

你只是改了自己浏览器里正在显示的那份内容。

**刷新一下页面，一切恢复原样。** 因为你改的只是你本机内存里的东西，没有改到服务器上。

（这一条也顺便说明了一件事：你在浏览器里看到的一切，都在你自己电脑上。所以网页上的「隐藏内容」都藏不住。）

---

网页由「有什么」「长什么样」「点了之后干什么」三层拼起来，三层是分开的，所以你改其中一层，另外两层不受影响。

## 几个常见的误解

**「前端就是做设计。」** 一半以上的时间在处理数据和状态：这个按钮该不该显示、用户没登录怎么办、网络断了提示什么、数据还没回来的时候页面显示什么。调颜色只是其中一小部分。

**「框架越新越好。」** 十年前流行的一批框架现在基本没人用了，而 HTML、CSS、JavaScript 这三样没怎么变。先把基础用熟，框架半个月就能上手，反过来就难了。

**「页面上的东西藏得住。」** 前端代码在用户浏览器里跑，按 F12 全看得见。任何密码、密钥、内部地址写在前端，等于公开。这一条没有例外。

**「手机上看着正常，电脑上就一定正常。」** 反过来也成立不了。屏幕宽度不一样，排版会散。开发者工具左上角有个手机图标，点它能切成手机尺寸预览，这个习惯要早养成。
