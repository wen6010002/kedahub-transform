## 从「你问一句它答一句」，到「它自己干完一件活」

你平时用聊天机器人，是这样：你问一句，它答一句。你再问，它再答。它不会自己动手做什么，它就是个「答题的」。

现在有一种新的用法：你给它一个目标，它自己想办法完成。

你说「帮我查一下这周末杭州的天气，顺便推荐适合的景点」。它不只是「答」你，它会**自己去查天气、自己去查景点、自己把结果整理好**给你。

这种「自己动手干活」的 AI，叫 **Agent**，中文常叫「智能体」或者「代理」。

---

## Agent 的循环：想、做、看、再想

普通用法和 Agent，最根本的区别是：**Agent 能用工具，而且能根据工具返回的结果，决定下一步。**

拆开看，一个 Agent 干一件活，是这样一个循环：

**第一步，想。** 它看着目标，想「下一步该做什么」。比如目标是「判断今天带不带伞」，它想：先得知道天气。

**第二步，做。** 它去调用一个工具。比如调用「查天气」这个工具，拿到结果「下雨」。

**第三步，看。** 它看工具返回的结果：哦，下雨。

**第四步，再想。** 根据结果决定下一步：下雨了，那要带伞。目标完成，输出结论。

这个「想、做、看、再想」的循环，是 Agent 的核心。它跟普通问答的区别就在这：

**普通问答**，模型只做「想」这一步（其实是「算」），它不能查、不能动手，只能凭自己记住的东西答。

**Agent**，模型能「做」，能调工具、能上网查、能运行代码、能读写文件，然后根据做的结果，再决定下一步。

所以 Agent 能干普通问答干不了的事：查实时信息、算准确结果、一步步执行一个长任务。

---

## 一个具体的例子

你让一个 Agent「帮我查一下，明天杭州下雨吗，下雨的话提醒我」。

普通聊天机器人会怎么答？它可能凭记忆瞎说一个，或者老实说「我查不了天气」。

Agent 会怎么做？

第一，它想：要查明天的杭州天气。它调用「天气预报」这个工具。

第二，工具返回：明天杭州有雨。

第三，它看结果：有雨。

第四，它输出：明天杭州有雨，记得带伞。

**整个过程，它自己做了「查」这个动作，而且是根据查到的结果，得出「带伞」这个结论。** 这是真查出来的，不是凭记忆猜的。

这就是 Agent 的意义：**让 AI 从「只会说」，变成「会做」。**

---

## 它现在还不太靠谱的地方

Agent 很强大，但现在是它「刚起步」的阶段，毛病不少。三个最明显的：

**容易跑偏。** 你让它干一件事，它干着干着就偏了，去查了不相关的东西，或者忘了最初的目标。长任务尤其容易这样。

**容易死循环。** 它调工具、看结果、再调工具，有时候会卡住，反复做同一件事出不来。就像人钻牛角尖。

**做错了不容易发现。** 它自己觉得「完成了」，但其实是错的，它还特别自信。你不管它，它就把错的当对的交给你。

所以现在用 Agent，有个共识：**重要的事，别全交给它撒手干，要盯着关键几步。** 它适合当「帮手」，不适合当「全权负责人」。

## 一个真实的场景

一个程序员要写一个「每天自动汇总新闻发给我的」小程序。

他用 Agent 来做。

他给 Agent 一个目标：每天早上八点，抓取几个科技网站的头条，总结成十条，发到我邮箱。

Agent 的循环是这样跑的：

想：要抓新闻，得先访问那几个网站 → 调「访问网页」工具 → 看：拿到一堆网页内容 → 想：内容太杂，要提取头条 → 调「提取文本」工具 → 看：拿到头条列表 → 想：总结成十条 → 调模型总结 → 想：发邮箱 → 调「发邮件」工具 → 完成。

**这一长串「想、做、看」，以前要程序员自己写代码串起来，现在 Agent 自己就串了。** 程序员要做的，只是定目标、把工具给全、然后盯着别出错。

这也是为什么 Agent 这么被看重：它把「写代码串联一堆步骤」的活，变成了「说一句话给个目标」。

## 它的边界

**Agent 不是「更聪明的模型」。** 它是个「会用工具的模型」。聪明程度还是那个模型，多出来的能力是「能动手」。所以模型本身笨，Agent 也聪明不到哪去。

**Agent 的能力，取决于它有哪些工具。** 你给它「查天气」工具，它只能查天气；给它「发邮件」工具，它才能发邮件。工具是它的手脚，没工具它就是普通的模型。

**Agent 会消耗更多。** 它一步一调工具，一次任务可能调几十次，比普通问答慢、贵。所以不是所有事都值得上 Agent，简单问答用普通方式就行。

---

## 用 Agent，注意三件事
**把 Agent 当成「一个能自己动手干活的助手」，用的时候注意三件事。**

**第一，目标要说死。** 别只说「帮我弄一下」，要说清「查什么、做成什么样、什么算完成」。目标越具体，它越不容易跑偏。

**第二，一次只给一件事。** 别一口气让它干十件事，它容易顾不过来。一件一件来，干完一件验收一件。

**第三，关键步骤自己核。** 它查的数字、它发的邮件、它写的结论，重要的地方你自己过一遍。它做完不等于做对。

这三条，是现在用 Agent 的基本姿势。

## 自己试一下

### 第一，你自己当一次 Agent

不碰电脑，用脑子走一遍。你的目标：**判断今天出门要不要带伞。**

你有一个工具：手机天气 App。

现在一步步来：

想：要带伞吗？先看天气 → 做：打开天气 App → 看：显示「今天有雨」→ 想：有雨，那要带伞 → 输出：今天要带伞。

**你刚才走的就是 Agent 的循环：想、做、看、再想。** Agent 干的事跟你一样，只是「想」是模型在做，「做」是它在调工具。

### 第二，看看你的 AI 工具是不是 Agent

打开聊天机器人，问一个「需要查实时信息」的问题：

```
现在北京天气怎么样？
```

看它怎么答。

**如果它真的查了天气、报出一个具体的实时结果，那它就是个 Agent**（它调了「查天气」工具）。如果它说「我查不了」，或者报了个明显瞎编的，那它还没这个能力，或者你工具里的联网开关没开。

（如果开了联网还是查不了，别纠结，你已经在脑子里走完 Agent 的循环了，概念已经懂了。）

### 第三，试一个多步任务

发这一句（工具支持联网的话）：

```
帮我查一下明天杭州的天气，如果下雨就提醒我带伞，如果晴天就推荐一个适合逛的地方
```

看它是不是自己一步步查、一步步判断。

**你会看到它先「查」，再「判断」，再「输出」**。这就是 Agent 和普通「问一句答一句」的差别：它自己把中间的活干了。

---

Agent 是「会用工具、能根据结果决定下一步」的 AI，靠的是「想、做、看、再想」的循环。它强大，但现在还容易跑偏、死循环、做错不自知。

## 几个常见的误解

**「Agent 是一种更高级的模型。」** Agent 不换模型，就是「模型 + 工具 + 循环」的组合。同一个模型，配上工具就是 Agent，不配工具就是普通问答。

**「Agent 什么都能自己干。」** 它的能力由工具决定。没有「发邮件」工具，它就发不了邮件。而且它现在还会跑偏、死循环，重要的事得盯着。

**「Agent 做完就一定是做对了。」** 它会做错，而且错了还自信。它做的东西，关键地方要自己核。

**「以后什么事都交给 Agent 就行。」** 简单问答，用普通方式更快更省。Agent 适合「要多步、要动手」的活，不是所有活的默认答案。
